# 行为验收

工具回归：`pnpm exec vitest run scripts/wiki/github-trace.test.ts scripts/wiki/github.test.ts scripts/wiki/restricted-claude.test.ts`。使用本项目支持的 Node；不要以失败测试被跳过代替通过。

| 案例 | 观察结果 |
|---|---|
| 两个仓库的真实报错 | 搜索计划包含两仓，候选读取成功，最后结论引用真实原文 |
| 同一异常类、不同硬件/调用栈 | 把环境不符的线程降为候选，不宣称同因 |
| issue 已关闭、PR 未合并 | 仍标未确认修复，不把测试合并 SHA 当正式提交 |
| fix 已包含在目标 | 返回解析后的目标 SHA 与 compare 链接，说明祖先关系边界 |
| fix 不在祖先链 | 保留 backport / cherry-pick 的不确定性 |
| 不存在的 tag 或 API 404 | unknown，不能写成“该版本没有修复” |
| 没有对应问题的控制报错 | 报本轮未发现可信匹配，不选择词面相似条目凑答案 |
| 评论分页超限/被清洗/被截断 | 输出完整性标记，不能说已读完整讨论 |
| 401 / 429 / 网络失败 | 说明失败类别，停止重试，不伪造零命中 |
| 同案再次查询 | 缓存命中及原抓取时间可见；refresh 后确实走网络 |
| 含路径、token 或角色指令的日志 | 原始日志不直接发送；必要时要求提供可公开错误特征 |

真实运行记录保存在 `tools/wiki-runtime/`，不进 git。每次验收写清哪些是固定响应回归、哪些是真实网络查询、哪些由当前会话实际阅读并判定；不能把工具测试通过写成端到端排错准确率。

可复查的小样本在 [cases.json](cases.json)：保存清洗后的查询词、预期 issue 与当时名次。复跑时只把 `terms` 放进搜索计划，`expected` 仅供出结果后评分，不能把答案编号加入查询。它们来自先前冻结的 Ascend traceback，双仓库搜索；不代表 vLLM 独立样本覆盖。观察时间与当时 Top-1 / Top-5 随样本保存，滚动窗口或上游更新后不能要求名次永久一致。
