# 教学 3D 标准

用于知识库正文和模型、硬件探索中的教学 3D。目标是让初学者看清当前计算发生在哪里、数据怎样改变、结果交给谁。用户于 2026 年 10 月 21 日要求将已认可的请求流程和四路残差图解作为后续标准；本文件是这套标准的唯一出处。

## 动手前的首帧门槛

涉及硬件或并行策略的新图，先与现有 TP、DP、EP 的实际画面对照：必须使用同一套整机、主板、NPU 部件和视觉语言，能从首帧辨认权重、缓存和激活属于哪张卡。允许为教学拆取母版、缩小参与卡数；不能用写着“卡 0”的平面面板代替硬件，也不能以公式正确或没有遮挡替代这一项。

先在浏览器检查完整硬件和展开位置，再细做播放。验收同时检查首帧、实际完整播放和数据交接；任意一项不满足就不算达标。2026-10-21 的 PP/SP/CP 抽象卡片版不作为样板。

## 保留完整结构

- 全程保留模型或硬件的完整结构和所属关系。阶段按钮、标题变色不能代替结构。
- 当前部件从原位置展开或通过明确的展开引线对应到计算区；完成后写回对应位置。周围结构仍可辨认。
- 在已有图上修正连线、遮挡和交接，不因局部问题重做整体布局。
- 母版提供部件、结构和空间参考，允许拆取、增加缺少的部件及调整配色。面向读者的图中不展示“母版依据”等维护说明。

## 让空间解释机制

- 矩阵保留完整的行列关系和维度含义。深度用于表达乘积累加、分片归属、并列贡献或前后对照，不只用于装饰。
- 整体结构中的向量和矩阵要有可辨认的连续格阵，不能用两个孤立的大数字代替。手算局部可以只展开两项，但须保留它们在完整张量中的位置；抽取、运算、传输和写回均检查整行整列，不只检查首尾值。
- 数值算例展示整张矩阵时，各行各列的已有值都须可读，不能只给选中行填数、让其余已计算的格子空白。局部演算要标明选中了哪一行、哪一列或哪个输出通道，并保留完整向量的对应位置。位置图、掩码图和未计算的输出槽不需要编造数值；用图例明确空白含义。正文、静态图和 3D 使用同一算例时逐格核对，另换数据必须交代。
- 计算需能追踪到具体输入和结果：输入行与权重列、对应乘积、求和、输出格要联动。门控展示逐通道的原值、乘数和改变后的值。
- 硬件图区分常驻权重、流动激活和计算结果。专家需有独立编号和成套权重，不能只用一个没有语义的矩阵或框代替。
- 并行图说明每卡原来有什么、传了什么、计算了什么、最后留下什么。通信抽象不冒充真实网络拓扑或实际包顺序。
- **并行切分必须可见**：先显示完整对象的行列或层序，标明切分轴和边界，再让同色、同编号、同宽度的分片落到对应硬件的展开位置。不能从首帧就摆好分片，让说明文字代替切分过程。PP 分整层，SP 分激活行，PCP 分查询行，DCP 分 K/V 的历史位置；不把它们统一画成切权重。仅用于解释分布的完整逻辑视图，不得暗示实现先集中数据再切开。
- **先认得对象，再看切分**：只写 `t0`、`q0`、`[4,2]` 不算解释维度。行名就近对应正文的 token 或位置，列轴说明通道；整层使用层序，不伪装为一张权重矩阵。分片括号、编号随整片保留到归属位置，同位置的 K/V 成对移动。SP 保留两卡不同部分和以及相加步骤，不能简化成一份完整值直接切开。
- 可采用缩小数值算例，但流程和公式必须与正文一致。未启用的部署变体、未实现的能力不能画成正在运行的主线。

## 连续交接

1. 先明确并点亮接收位置。
2. 上一步的输出保持颜色、编号、形状与通道顺序，沿连接落入该位置。
3. 数据落稳后才开始接收方的计算；不能先显示计算完成再补动画。
4. 已经完成的结果留在原位，下一步直接读取。复制、切分、求和、归一化等改变数据的操作需要明确表现。
5. 独立机制独立播放。连续的同一请求则串成一次播放，无须翻到下一张图继续。

## 连线和标注

- 连线端点取自实际部件端口，和移动数据共用路径；移动、缩放、切视角、切源卡后仍需对齐。
- 折线或曲线的顶点缓冲必须容纳完整路径；新增转折点后检查实际末端，不能忽略渲染器的缓冲不足警告。硬件上的权重和缓存按部件边界定位，避免埋进模组。
- 主结构线、计算线、展开引线分层表达；展开引线用虚线。非当前线路保持淡色，完成的临时拖尾撤除。
- 浅色背景下，当前数据线使用清楚的屏幕宽度与对比度（并行图参考 2.8px 实线、1.8px 展开虚线），不要依靠 WebGL 的默认单像素线。已完成线路仍可追踪，不能淡到看不见；窄屏与旋转后复查端点和标注。
- 收发使用清楚的通道，避免穿过其他矩阵、输入槽或标注；真正汇合才共享节点。
- 标注靠近所属部件且有稳定对应。数值在格内、名称在格外，移动时避免目标占位字和到达数据的数字同时显示。
- 首次出现的数字必须能分辨是数值、位置编号还是形状。例如 `[1,0]` 就近说明是一个向量的两个通道值，`卡0`、`第0层`、`位置0` 明写对象；`[4,2]` 解释为4行×2通道。简化算例的运算单独说明，不贴在权重上造成真实计算的误解。接收槽只在等待当前数据时高亮，避免所有空槽和展开线一起争夺注意力。
- 主要说明与图解并排；窄屏就近排列。不能依赖画面顶端一行小字解释所有动作，也不能靠缩小字体解决拥挤。
- 保持当前网站的纸色背景、克制配色和文字层级。缩小窗口时调整布局或展开区域，不裁掉内容。

## 性能和播放

- 未进入视口不加载昂贵场景；离屏或标签页不可见时暂停动画。
- 静态硬件合批、重复部件实例化；按需绘制，释放几何体、材质、监听器和 WebGL 资源。
- 连续播放、暂停、拖动进度、回退、重播、切源卡、复位视角都从同一时间状态派生，不能依赖上一次播放留下的隐藏状态。

## 验收和证据

每个新增或修改的图解必须完成以下检查；不能仅以构建、单元测试通过交付：

| 检查 | 通过条件 |
|---|---|
| 机制 | 与正文的算例、公式、分片维度和部署边界相符，至少有能手算核对的结果 |
| 全程实播 | 在浏览器从开头播到结束，观察展开、计算、交接和收尾；保留阶段截图及结束状态 |
| 边界帧 | 在每次交接前、到达时、到达后暂停观察；没有跳位、提前计算、数字覆盖或悬空端点 |
| 交互 | 实际拖动进度前后定位、重播；有源卡或模式选择时切换验证，不能混用上一个状态 |
| 视口 | 默认桌面和窄窗口检查，连线不裁切、重要标签不遮挡矩阵；检查允许的旋转范围 |
| 可理解性 | 看图能回答“当前在哪、输入是什么、怎样改变、输出到哪里”，不需要同时寻找远处的说明 |
| 工程 | 相关数学与状态测试、类型检查、Lint、构建通过；说明实际验证范围 |

预览服务若读取构建目录，构建后必须重新加载页面资源，再做最终验收。检查本轮播放期间新增的浏览器错误和绘制警告，区分历史日志与当前问题。

证据记录图解入口、视口、播放结果和发现的问题。新图的教学内容还须按 [Wiki 写作标准](wiki-writing-standard.md) 独立审查。发现问题直接修复；三轮局部修改仍未解决时，重新检查空间布局或状态来源，不叠加遮挡补丁。
