## 3. 六大真机实测“性能劣化 / 反直觉负收益”根因总结

1. **KV 整池非连续物化（Eager 实测坐实 `[M]`，线上 `FULL` 为待验证条件外推 `[I]`）与稠密 `TP=1→8` 观测负扩展**：
   - `vllm-ascend@c09d3e20` 为普通 GQA 层分配共享 backing `[2, num_blocks, block_size, kv_heads, head_dim]`，按页交错排布（`stride=(H, 2H)`，`k_contiguous=False, v_contiguous=False`）。在两份 Eager Trace 中，Decode 阶段 `aclnnInnerFusedInferAttentionScore → aclnnContiguous → aclnnContiguous_SliceAiCore_Slice` 对每层整个物理 KV 池做连续化复制：`Qwen3-8B` 两个 Decode 步各触发 **72 次大 `Slice`**（共 `144/144` 次，合计 `92.3106 ms`，占全部设备算子时间 **`62.220%`**；全部 290 次 `Slice` 占 `62.463%`），每步耗时 **`46.155 ms`**（读写流量 **`58.99 GiB/步`**，有效带宽 `1.372 TB/s`），而真正的 `FIA` 注意力核函数 108 次合计仅 `2.356 ms`；2 层裁剪 MoE 因整块空闲显存划入 2 层（`66,139` 块），8 次整池大 `Slice` 单次高达 **`13.45~13.67 ms`**（占设备时间 **`95.990%`**；全部 18 次 `Slice` 占 `96.012%`）。
   - 线上 `u=0.85` 时单请求运行 `FULL` 图；加 TP 使权重减小、每卡自动分配的本地 K+V 池字节从 `36.28 → 43.52 → 47.35 → 49.27 GiB` 递增。**若** `FULL` 图内重放同等整池复制且保持 Eager 有效带宽（条件外推耗时 `56.77 → 68.09 → 74.09 → 77.09 ms` `[I]`，包内尚无线上 `FULL` 设备时间线实测），并与源码中多卡 TP 的 **72 个行并行 `AllReduce` 位置**（独立 `16 MiB` 微基准测得 `0.0 µs` 重叠，线上真实重叠与分项占比待测）共同作用，可解释观测到的 `TP=1→8` TPOT 单调变慢（`78.54 → 94.42 ms`）、`c=16` 吞吐单调下降（`195.28 → 160.38 tok/s`），以及 `TP=1` 从 `c=1→16` TPOT 仅增 `+2.23 ms (+2.84%)` 而吞吐跃升 `15.3×` 的批内摊销现象。
2. **`4P4D / 2P2D` 叠加 `--enforce-eager` 等配置下 MoE Decode 持续步延迟劣化 `3.952×`（`77.90 → 307.83 ms`）**：一次 P→D KV 移交仅影响首 token（`30B c=1` 最慢 rank ADXL 读取段 `16.64 ms`），而后续 127 个 Decode 步每步净慢 `+229.93 ms`（稠密 `8B TP=2` 混部 Graph 对 `2P2D` Eager 为 `+63.47 ms`，`1.729×`）。这组实验同时改变了 PD 拆池、`--enforce-eager`、`prefix_caching=False`、`max_model_len=16384`（30B 还由 `u=0.88` 改为 `0.85`），48 层 MoE 在 D 端开启 Eager 后暴露的逐层路由/分发/合并提交与跨卡同步是持续 127 步高延迟的主要候选机制，纯 Eager 与纯 PD 各自独立份额尚待同拓扑单变量对照实验拆分。
3. **均匀 `262-token` 输入下 `2P2D`（8B）与 `4P4D`（30B）组合配置首 token 放大 `6.07×` / `2.20×` 且吞吐下降 `47.1%~69.5%`**（注：`0.6B` `1P1D` 仅为 `18+40` tokens 功能冒烟，无性能对照）：缺乏长短混合 Prefill 干扰源，P 池在 7/7（30B）与 8/8（8B）运行统计点均为 `Running: 0`；同时存在两跳 HTTP 代理、`do_remote_decode` 建链、`8B` 每请求 `216` 段（`27 MiB/rank`）离散块搬运、`Dest buffer device_id >= endpoint count ... falling back` 告警（8B `4,991` 行、30B `19,941` 行）以及双端 Eager 等组合因素（各项独立贡献待单变量对照拆分）。
4. **`Qwen3-30B-A3B` 扩至 `DP=2+TP=4+EP=8` 在 `c≤16` 出现负扩展（`179.70 → 149.45 tok/s`，单卡效率 `44.93 → 18.68 tok/s`）**：请求确已均分至双 DP（`c=1` `1/0`、`c=4` `2/2`、`c=16` `8/8`），路由专家权重精确减半（`54.000 GiB ÷ 8 = 6.750 GiB`，叠加非专家 `0.7652 GiB` 后单卡总权重由 `14.2652` 降至 `7.5152 GiB`，降幅 `47.32%`）；A2 无 LoRA 下 `ep_world_size=4/8 < 16` 均选 `ALLGATHER`，其中 `dp_size > 1` 的八卡组还须执行跨 DP gather / reduce-scatter 且空闲 DP 需跑 dummy batch 同步推进，`c=16` 每 DP 仅 8 请求、双池隔离前缀命中从 `25.49%` 降至 `16.99%`、绑核回退 `global-slice`（各项时延子份额尚无逐步通信 trace 拆分）。
5. **`VLLM_LOGGING_LEVEL=DEBUG` 热路径开销**：`worker.py:762-778` 每步读取 PyTorch 缓存分配器计数并打印日志（`TP=8` 达 `3,312` 行）外加 `acl_graph.py:275-281` `data_ptr()` 校验，使 `TP=8 c=1` 单样本 TTFT 从 `139.07 ms` 增至 `193.98 ms (+39.48%)`。
6. **图显存随 TP 逆向增长、Sleep/冷启动与静态量化陷阱**：`u=0.90`（`0.6B`）完成 `profile_run()` 与 35 档 `PIECEWISE` 后在 `FULL` `1/35` 的 `FIA` 内因申请 `1.98 GiB`（仅剩 `1.71 GiB`）OOM；`8B` 随 `TP=1→8` 每层本地 KV 视图增大（`1.008 → 1.368 GiB`），图捕获显存差值反从 `2.59 GiB` 涨至 `3.21 GiB`。Sleep Mode 在 `worker.py:279-286` 只要 `weight_nz_mode != 0` 即拒绝 `wake_up()`（即便 BF16 在默认 `mode=1` 下并未转 NZ），设 `weight_nz_mode=0` 后 `2.482s` 唤醒成功（较 `95.83s` 冷启动快 `38.61×`，板级占用 `55,740 → 6,211 MB`，较初始化前 `3,453 MB` 净留 `2.693 GiB`），且开启 Sleep 会使 RFork 自动回退默认加载。冷启动 `.pyc` 8 进程并发导入省 `11.713s`（`24.311 → 12.598s`）；首次 `npu_format_cast(NZ)` 懒加载耗时 `7.1618s`（二次 `0.0007s`）。未量化 GQA 模型传 `--kv-cache-dtype int8` 在 `attention_v1.py:583` 直接抛静态量化权重缺失 `ValueError`。
