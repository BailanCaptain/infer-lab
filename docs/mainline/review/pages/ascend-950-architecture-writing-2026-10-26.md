事实核对保留以下边界：

- 36 个 AI 子系统是完整设计描述，PR/DT 产品表实际有不同核数档；不同规格行的斜线不能任意配成一个 SKU。
- PR 内存 128/112 GB、1.6/1.4 TB/s；DT 144/96 GB、4 TB/s；L2 PR 128/112 MB、DT 128 MB。
- 两个 Vector 各有 256 KB UB；表 4-2 合计口径为每个 AI Core 组合 512 KB。GB 级封装内存与 KB 级核内 SRAM 分开。
- L0C→UB 和 L1↔UB 是不同通路；新路径不改变算式的预期结果，也不取消数据就绪和容量依赖。
- NDDMA 讲的是有配置约束的多维地址与重排，不是任意随机访问都能自动提速。四个教学元素不是四次实际事务。
- Buffer ID 的取得/释放组织同步，不承诺无等待或自动流水重叠。
- UMA 保留统一地址的含义，不扩展成任何路径等延迟；L2 命中与逻辑 GM 访问分别讨论。
- 互联是 72 路最高 112 Gbps HiLink 分成 18 端口，标称 2016 GB/s 双向；UBoE/PCIe 与 UB 端口共用，不能简单把各行峰值相加。
- 峰值类型和范围分开，Cube+Vector 总值不替换仅 Cube 的利用率分母；未给出本站服务性能测量。
- v0.23/v0.26/main 的具体硬件通路仍缺目标镜像、算子和执行记录，页头 `verified` 为空；main 特定格式加载事实链接原格式页，不扩展成所有硬件能力已接入。

官方 OBS 地址尚未被原有自动来源识别器收录。实际复跑确认：本页所有来源均未识别时，改页级证据为 I 仍报 `source-domain`；这不能靠调整证据字母解决。根任务据此接手仅这份官方 PDF 精确路径的来源接入与正反例测试，不放开整个 OBS 域名。最终页级证据由根任务按仓库分级规则统一，页末原始文档 S1、物理页码和教学推导标签始终保留；这里的人工核查不冒充识别器结果。

## 数值与教学自查

- 首图之前没有 calc、产品规格或峰值表；出现的数字只是已解释并回链的微型矩阵算例。
- 新演算一：1024 个 FP32 元素为 4096 B，经 GM 写读的逻辑量为 8192 B；明确原路径若命中 L2，实际外部内存事务不按此直接计。
- 新演算二：源二维偏移 0/1/4/5，取到 10/11/20/21；目标紧凑偏移 0/1/2/3。第二行首元素具体算 `4×1+0=4` 与 `2×1+0=2`，符号公式放正文，不塞进数值 calc。
- 错步长反例可复算：源行步长误用 2，第二行读偏移 2/3，得到 12/13，而非 20/21。
- 12→9 μs 明确是教学观测，仍需通过 trace 判断该设备片段是否位于请求关键路径。
- 当前标准统计：正文 4508 字（汉字 + 拉丁单词，不含源码区和围栏）；行内代码 0，正文证据角标 0；calc 2 个，0.444/千字；免责词命中 1/122 句，即 0.82%。`checkStandard` 无问题。统计不代替教学与事实审查。
