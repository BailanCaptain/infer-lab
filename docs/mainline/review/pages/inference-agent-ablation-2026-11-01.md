# 六道新案例：知识库具体增加了什么帮助

2026-11-01。agent 恢复后，本批已完成独立审题、24 份原答、隐去标签的独立评分、解封对照、两页原位修订和两道新条件复测。**知识库提供了可追溯的实现细节与验收边界，但本批没有证明它让通用排障能力大幅提高。**

六题各做两轮，每轮比较有库、无库答案；有库合计 **144/144**，无库 **142/144**。12 组配对中 **2 胜、10 平、0 负**，差值中位数为 0。两次胜出都来自同一道 N3 的“验收与代价”维度，不能说成两种不同问题都获改善。所有原答至少 11/12，独立首评未发现严重错误；量表已明显接近上限，分数之外仍须看具体动作。

本批是[验收方案](../../../superpowers/plans/2026-10-31-inference-user-field-acceptance.md)中的探索性预试，不替代正式十二题、真人试读或设备验证。六题是新的条件组合，复用已有机制，不是六起新公开事故。没有调用产品完整问答链。

## 发现什么就改什么，解释仍放在原页

N1 题干关闭 prefix caching，所以原答没有因这一条件出错。沿着引用继续检查时，发现原页把特定无复用条件下的重算说得过于通用，也容易把“150 个已知编号作为恢复输入”误读成一次全部重算、重新采样或重发。修订基于这个内容问题，不是为了制造原题得分增长。

| 原页 | 原问题与本轮处理 | 复用方式 |
| --- | --- | --- |
| [请求收尾](../../../../wiki/concepts/request-teardown.md) | 抢占进度归零后先查可复用状态，再算缺失部分；100＋50 示例明确无可复用 KV、可以分步、最新输出可能尚无自身 KV；重建状态不等于重新采样或再次交付。另把 GLM 异步调度由“已开启”改为默认配置推断，要求核对现场配置 | 重复交付引用现有流式输出；缓存命中引用 prefix caching；实际开关引用调度器配置说明 |
| [Scheduler](../../../../wiki/concepts/vllm-scheduler.md) | 修正“所有已算位置作废、之后从头重算”的笼统说法；固定 GLM 示例说明已知编号重新作输入、重建包括 KDA 在内的状态 | 只保留调度职责与短解释，链接请求收尾，不复制完整恢复样例 |

主持人核对本地固定源码 vLLM `0fc695fc` 的调度器抢占、恢复缓存匹配及请求历史追加路径；来源行号同步补齐。[改前快照及两页差异](../../../../tools/wiki-runtime/inference-agent-ablation-2026-11-01/before-edit/request-teardown.diff)、[Scheduler 差异](../../../../tools/wiki-runtime/inference-agent-ablation-2026-11-01/before-edit/vllm-scheduler.diff)只记录相对本轮开始时的变化，不归领共享工作区的旧改动。

## 还缺什么，分别放在哪里处理

- **学习者是否能独立跟上，仍没有真人证据。** N1 的状态区分有具体例子；N2 的有库答案仍集中出现多个状态名和实现入口。更细不自动等于更易懂。真人试读应检查能否先说清“共享长历史、每请求自己的状态、其他运行内存”三笔账，再按需找实现名；不要求背缩写。
- **现场事实不能靠增加教程补出来。** 精确版本、实际加载产物、通信成员、队列接纳/退出、池分配策略和逐步设备记录仍需现场提供。原页中的在途结果、固定地址元数据等明确待核项继续保留，不能改成已确认。
- **回答组织还有改进空间。** 有库回答更容易铺开字段清单。应先列第一项能区分候选的证据，再按结果追加采集；N5 的 90/s 应就近说成尝试产生率，不能省略实际接纳边界。这是答案表达的改进，不据此向知识库重复塞同一规则或追改原分。
- **本批没有发现必须新增页面才能填的机制缺口，也没有证明检索失败。** 实际给到的是完整相关页；引用支持关键动作。检索材料长、模型是否充分利用每一段以及产品最终回答表现，是不同问题，本批不能凭同分判定检索最佳或无用。
- **下一阶段应测动作与执行，而不只继续堆题数。** 复用已有试跑包，让读者先找依据、选最小日志、根据补给的观测换分支；记录到第一个有效动作的时间、无效采集量和讲不清的位置。真实读者试读与设备/脱敏现场日志验收仍是原计划的未完成项，正式批次另行冻结，不把本批题再次称为未见题。

## 方法、偏差与原始证据

本轮先完成[独立审题](../../../../tools/wiki-runtime/inference-agent-ablation-2026-11-01/private/preflight-retry.md)，六题保留原版。N4/N5 与更早案例有机制交集，新的是决策条件，不夸称从未涉及的领域。此前出题 agent 额度中断保存在[原阻断记录](../../../../tools/wiki-runtime/inference-agent-ablation-2026-11-01/run-status.json)；原 manifest 的零完成数是准备时快照，当前状态以[续跑状态](../../../../tools/wiki-runtime/inference-agent-ablation-2026-11-01/resume-status.json)为准。

有库输入来自现有 `loadAgentWiki(root).search(question, 3)` 的三篇直接命中与三篇关系扩展，共 26 篇去重全文；没有人工换页或截短。两组同题、同一中性要求、同一中文正文长度上限，每次新上下文、禁止额外检索，不继承父会话或私有评分。24 次分配与输入在作答前固定，全部原答保留。两名未作答的 agent 分别评分三题，原分落盘后才揭示组别；没有互相读对方评分。

需要一起保留的限制：

1. 原答引文可能暴露有库身份，所以是隐去标签的评分，**不是严格盲测**。两位评分者读取六维标准时实际回传了整份验收方案，已分别记录偏差；解封前没有读取组别映射。
2. 共享文件系统依靠读取约束，并非安全隔离。回执自报只读指定输入、写自己两份文件；主持人校验哈希、范围和记录一致性，不能把回执当独立工具审计。R03、R24 初读输出截断后补读了全输入，保留该记录，没有默认为读全。
3. 输入逐次保持原 SHA；作答、私有要点和原评分没有因修订被覆盖。无库材料为空，有库按全文分段读取。精确模型 ID、种子和单次 token 用量未由接口提供，不推断；本批也没有可比耗时或成本结论。
4. 六题每组两次不是十二位用户或十二起独立事故。中文正文汉字数核对为 538–625，原始英文、数字、标点与引文均保留；这不是事前定义的完整分词计数。分数接近上限，不能用 144 对 142 推总体提升率或统计显著性。
