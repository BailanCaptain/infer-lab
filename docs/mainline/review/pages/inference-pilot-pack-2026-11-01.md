# 推理知识库试跑包与 Agent 材料预检

[首轮试跑包](../../../superpowers/plans/inference-pilot-2026-10-31/README.md)已备齐：学习者读前两站并做两道变式，从业者查阅一个已有公开案例，主持人按阶段发题，评分依据单独保存。它用于开始小规模试跑，不增加 Wiki 教学页。准备工作始于 10 月 31 日，冻结快照和模拟作答在 11 月 1 日进行，因此保留原包目录日期。

## 本轮实际跑了什么

使用新上下文分别派发学习者、从业者、独立评分任务；作答者不接收评分依据或父会话。从业者先交首答，再开放四篇现有正文。修订后另用一个新 agent 检查材料边界并回答三道新条件题。允许材料、文件摘要和原答见[执行范围](../../../../tools/wiki-runtime/inference-user-field-acceptance/pilot-2026-11-01/run-context.md)。读取范围靠任务指令约束，不是文件系统安全隔离。

| 任务 | 独立核对结果 | 能说明什么 |
| --- | --- | --- |
| 学习者两站复述与变式 | 第一站 8/8，第二站 8/8 | 本次 agent 能从指定文字正确分段等待、区分片段与 token，并计算不同交付口径和成功率上下界 |
| 从业者完整方案 | 11/12；无严重错误 | 能据正文组织对象、窗口、对照、分流和交付验收；仍漏掉采集开销单列与正常采集设置下复验 |
| 修订后新条件题 | 三题均给出有依据的判断与下一步；同时指出两处相邻摘要的歧义 | 能正确处理“空闲量相等也触发”“goodput 为零但阈值未知”“有效输入相同而执行尺寸不同” |

[独立评分](../../../../tools/wiki-runtime/inference-user-field-acceptance/pilot-2026-11-01/answers/scoring-review-v2.md)逐维列出原答位置及分歧。主作者复核后采用从业者 11/12：两组采集设置一样，不等于单列采集开销或回到正常设置复验。没有替 agent 补出未写内容，也没有放宽评分把它变成满分。

这次最具体的方案变化是：从业者首答提出让 GPU 独占来对照，查库后改成**初始占用相同，只改变另一进程是否在量测窗口释放**，把独占组留作辅助。这一变化有显存量测页的具体段落支持。不过，首答本来就抓住了整卡与进程的区别；查阅正文还直接提供了同一公开案例的历史结果。因此这里只记录“已有知识被正确用于细化方案”，不报告分数增益或独立发现根因。

## 发现的问题与处理

| 问题 | 处理 |
| --- | --- |
| 包里说后续结论暂不提供，但允许阅读的旧正文已收录该案例结果 | 任务单、主持稿和评分统一改为：初答只看材料，查阅阶段可使用库内结果，必须说明出处；不称全程隐藏结论。初稿与实际资料暴露保留。 |
| 首答只有三问，却与完整方案同按 12 分评分 | 首答只作事实、候选和首个动作的记录；后答才评分，不计算分差。 |
| NPUWorker 页把报错提示写成同一容器其他进程释放的确定原因 | 改成待验证候选，保留同物理卡范围，并明确固定 NPU 断言的严格不等号。 |
| 样例页的有效输入数与执行尺寸缺少近处解释 | 在原表前解释真实位置与补齐空位，细节链接已有多请求示例。 |
| 测量页“该实现”指代不明；短输出的零值可能被误认为 goodput 本身为零 | 正文说明是否启用统计，具体实现移到固定源码；版本表明确填零的是达标判定用的 TPOT。 |
| 显存量测页的“严格大于”未写比较两端，可能把通过条件读成报错条件 | 写明初始与试跑后的比较，分别列固定 NPU 和 GPU 的相等边界；原因仍按原机制页取证，不新建排障页。 |
| 原有 GPU 来源范围只覆盖图内存估计，没有覆盖这次明确写出的断言 | 将同一来源从 L416–L443 扩为 L416–L460，保留原依据并覆盖 L452 的比较；独立复核关闭。 |

两项包设计问题经独立复核关闭。正文修订涉及四篇既有页，没有新增代码、参数、教学图或另一套推导；工作区中原有的其他修改没有归入本次成果。复验题、原始回答和评分都保留，不覆盖初次问题。

## 仍需真人与现场回答的问题

Agent 不具备真实初学者的阅读速度、陌生感或延后记忆；本轮没有前测、合页记忆或 24–72 小时复测。两站指定范围较长，45 分钟是否合适仍要让真人尝试，读不完保留停点。模型作答的 16/16 不折算成真人通过率。

本轮是已收录案例的资料使用预检，不是新的有库/无库因果对照；也没有实机采日志、注入故障或验证恢复。原方案的真人试跑、正式对照和现场验收继续保持待执行。

下一步直接按包中的主持稿，安排一名学习者和一名从业者分别试跑，保留原话、卡点和独立评分，再冻结正式题与时限。当前试跑包没有待用户决定的内容设计问题；实际试跑参与者、现场负责人和可用日志尚待落实。
