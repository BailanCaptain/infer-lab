## 沿学习顺序检查理解与衔接

以下是审查者仅依据正文能够复述的机制、代价和下一步用途。它说明页面提供了哪些推理依据，不替代真实读者反馈。

| 页面 | 前部建立的理解与代价 | 后文能支持的分析，以及本轮判断 |
| --- | --- | --- |
| 学习指南 | 先沿一个请求理解输入、调度、模型计算、采样与持续生成，再进入性能和故障分析。W8A8 只说明采用该量化方式的计算，不能推成所有数据都为 8 位。 | Token 和 Prefill/Decode 的表述更准确。基础路径与分析路径分开，读者可以按当前问题选择分支，不必先读完所有深入页。 |
| 性能贯穿样例 | D 已在持续生成，N 的长输入加入同一个设备步，D 会等这个混合步完成。减少 N 每步处理的输入可以缩短 D 的停顿，但 N 的首字可能更晚，还可能增加重复开销。 | 同一组 D/N 从客户端记录推进到调度和设备记录，包含改变证据后转查其他环节的分支。删除该处未解释的“关键路径”标签后，句子直接说明 D 在等什么，没有丢掉依赖关系。 |
| 推理测量 | 用户关心每次等待，服务还关心单位时间交付多少达标请求。总吞吐、达标吞吐和成功率回答不同问题。 | 新增成功率上界，使读者可以明确否决“B 吞吐改善，所以本批验收通过”。P95 的算法、样本范围及失败项单独记录也已解释。 |
| 设备性能分析 | 某个计算更快，不一定能让依赖它的下一步更早开始；另一个未就绪的分支仍可能决定等待。读权重、计算和通信也要沿实际依赖区分。 | 开篇将“一个步骤变短”与“整体改动有效”分开，后文 P2 修订消除了反例。新增到生产实践的桥接说明：跨实例后仍追踪相同的依赖和耗时，只是多了数据交接。 |
| DeepSeek 生产实践 | E/P/D 各自完成输入编码、长输入处理和持续生成。资源分开可以减少相互干扰，也会引入状态交接与就绪等待。 | 30 ms 与 120 ms 交接的对比能支持判断何时分离部署反而更慢。下一步先到容量与恢复，模型、SWA、DSpark、低精度作为机制分支，顺序比直接跳入模型细节更连贯。 |
| SWA 有界回放 | 已有历史状态不代表每一层近期窗口状态都还在。回放一小段历史可补窗口，但多层依赖使其是有条件的近似，而非任意状态都能无损恢复。 | 完整计算得 4、有界回放得 6 的小例子保留近似来源；新增位置范围明确区分“已命中却需要回放”和“原先未命中的新后缀”，便于解释缓存命中后仍有计算。 |
| DSpark | 草稿先提出候选，再由主模型验证。多验可能留下更多输出，也可能增加更多耗时；只能接受连续通过的前缀。 | 100 轮的解释让 4.22 这个期望值有具体含义。新增持平阈值，读者可以用自己的整轮耗时比较策略，而非只复述“少验可能更快”。停止和长度截断条件仍保留。 |
| 低精度格式 | 更少的存储位只能表示更少的数；缩放和舍入决定哪些信息损失。格式范围、分辨率及实现是否匹配是不同问题。 | FP16/BF16 的小区间演算解释了“范围大却不一定更精细”，并保留接近零、溢出、舍入和累加边界。可以据此区分普通量化误差和格式/缩放不匹配，完整故障路径继续复用正确性排查页。 |

这些修改没有新建概念页，也没有把缓存、关键路径、量化或容量公式复制到多个新出处。学习路径以问题衔接，已有页仍承担各自机制的完整解释。对当前 8 页逐项比较，未发现本轮为求顺口而删除原有算例、来源、模型适用条件或实际排查记录的情况。

## 新数字与反事实的读后检查

以下四项是审查者依据当前页面作的人工推演，并用 Python 有理数计算复核。没有调用产品问答引擎，不是真实学员答题结果；也未将题目重复写入正文。

| 改变的条件 | 推演和结论 | 页面是否提供足够依据 |
| --- | --- | --- |
| 仍发出 24 条请求，改为 22 条成功、0 条失败、2 条未完成 | 最终成功比例可能在 `22/24≈91.67%` 至 `24/24=100%` 之间。不能沿用原例“已有两条失败”的结论直接断言本批失败，也不能用已完成项中的 100% 宣布通过。若门槛仍是 99%，这批 24 条最终须全部成功；未完成项的结果决定结论。 | 足够。测量页区分已成功、已失败与未完成，并明确按全部已发请求作分母；因此能够识别反事实改变了上界，而不是照搬 91.67%。 |
| DSpark 全验期望仍为每轮 4.868 个输出，整轮耗时分别改为 11 ms、12 ms | `4.868/0.011≈442.55 token/s`，高于少验原来的 `422 token/s`；`4.868/0.012≈405.67 token/s`，低于 422。概率与停止条件必须保持原设定。 | 足够。正文给出期望输出/整轮耗时的比较方法和约 11.54 ms 的持平点，两个变式分别落在阈值两侧。 |
| SWA 输入长度改为 1100，仍先按 `L−134` 限制、再按 128 向下对齐，且相应窗口缺失 | 上限 `1100−134=966`；对齐命中长度 `floor(966/128)×128=896`。原先命中位置是 0–895；缺窗口后退至 768，回放 **768–895，共 128 个位置**；原先未命中后缀为 **896–1099，共 204 个位置**。两段合计需要计算 332 个位置，但不能全部记作原始未命中。 | 足够。正文明确长度与位置的区别，提供相同顺序的限制、对齐、回退步骤，并解释两段计算的不同含义。 |
| 在 `[1,2)` 区间将 1.003 分别舍入到最近的 BF16/FP16 值 | BF16 格点偏移为 `0.003×128=0.384`，最近为第 0 格，即 **1**，带符号误差 `−0.003`。FP16 偏移为 `0.003×1024=3.072`，最近为第 3 格，即 **1+3/1024=1.0029296875**，误差 `−0.0000703125`。两者均非正中间，不涉及平局规则；这是数学舍入，不是硬件实测。 | 足够。缩放示例已解释近似保存与还原，格式段又给出本区间的步长，可以推出本题 FP16 更接近原值；不能进一步推出 FP16 在所有任务中都比 BF16 合适。 |
