## 原始依据与条件变式

DeepInfer 相关资料读取本地固定快照 `774ce244b87cc0eb8d4b94ab9f5de2ab22049f01` 的 README、`examples/README.md`、`doc/inference_deployment_qa.md`，以及生产文章已缓存的正文。950 新增内容核对 PDF 物理页 24、28、29、34、36、37、38、39 的文字与原图；这些页的截图位于本轮 `sources/950-p*.png`。接收内容个案核对 `tools/wiki-runtime/github-trace/reference-audit-64048.json` 中的原 issue 正文与评论。以下为审查者手工换条件推演，不是设备测试或模型问答通过率。

| 要检验的新增推理 | 原始依据 / 变式 | 审查结果 |
| --- | --- | --- |
| 全接受口径不等于实际输出 | 示例明写吞吐用 `avg_SPS × decode_num_requests × (1 + nextn) / cp`，不考虑真实接受率。教学中保持 100 轮/s、2 请求，只把实际平均交付改为 1，则实际为 200 token/s，示例全接受口径仍为 800。 | 推理成立。正文分开了步数、验证数、接受与交付，没有把 800 写为设备实测或线上能力。不能再用未定义的“接受率乘候选数”代替实际交付计数。 |
| 分段 trace 不能量线上交接时间 | 原例 P/D 分别采样，导出时首尾拼接；中间预热与测量不在 trace。即使真实两个采样段之间相隔一秒，拼接后仍可紧邻。 | 推理成立。图内事件可解释采样段的算子组成与依赖；没有连续请求时钟，不能得出 TTFT 或零交接开销。 |
| 统计汇集剔除只适合对应离线口径 | 原例删除与 LB stats flush 重合的计时间隔。若线上每隔一段时间有同样工作，删除后会隐藏周期性开销。 | 正文要求线上容量保留真实周期工作、排队、失败与长尾，没有把离线稳定区间套成 SLO 能力。 |
| P 分流须看新增与已有历史 | QA 和生产文章均列四层分流与拟合代价。将模型换成固定窗口/稀疏选择后，100000 历史不必按全历史长度线性增加代价。 | 正文保留窗口、压缩、稀疏选择条件，没有编造 50 倍耗时。时间预算与显存预算也已区分。 |
| D 请求少的卡不一定更轻 | 两条长历史可比四条短历史拥有更多 KV；若当前瓶颈改成专家工作或请求固定开销，不能单靠 KV 长度判赢家。 | 正文同时保留请求数、KV 总长度与完成时刻，并另查专家负载；没有把示例直接变成通用路由指令。 |
| DVPP 与 Vision Encoder 不是同一处理 | PDF 的 JPEGD/VPC/JPEGE 是解码、像素处理和编码；Vision Encoder 把图像经模型变成特征。若实际软件用主机做预处理，950 存在 DVPP 并不证明它已工作。 | 当前解释和主机路径条件成立；没有宣称本项目实际启用了 DVPP。 |
| 远端池不自动增加当轮设备驻留 KV | PDF 说明资源可达，未给框架的缓存目录与算子策略。若必须全部取回本地再算，本地容量仍限制驻留；若支持按需远端读取，就需要另记实际可用边界。 | 正文明确限定“当前实现仍要求……”，也允许另一条取数路径，没有把所有服务都限定为存储→主机→设备。 |
| 本地计算空闲不排除端口争用 | PDF 34 页说明单 IO Die 内 9 个 x4 端口转发不进入计算 Die、不占 DRAM 带宽；36–39 页区分拓扑、池与两种以太连接。 | 新段据此要求看转发流量，推理成立；没有把端口峰值、全拓扑和框架支持混成一个保证。 |
| 接收成功不证明内容正确 | issue 报告 GH200/vLLM 0.31.0/NIXL 1.5.0 的成功传输、逐块逐层校验与独立复现。换成有布局转换的传输时，原始字节不同本来就合法。 | 正文先对齐请求/层/逻辑位置，仅同布局原样传输直接比字节；有转换先还原同一逻辑表示，避免误判。替换路径正常仅作为线索，不据此断言驱动根因。 |
| 支持 CP 与线上没用 CP 不矛盾 | README Supported features 写 balanced CP；同快照 QA 的生产部署回答 TP/CP 暂未使用。 | 入口页保留能力范围与部署选择的区别，没有把其中一份资料当作另一份错误。 |
