## 前两屏复述与后续连贯性

| 页面 | 审查者用初学者语言复述 | 如何接到后续分析 |
| --- | --- | --- |
| 模型结构 | 普通模型每层的输入已经被前一层加工，不能直接把某层历史当成所有层的历史。CED 在训练采用的结构中，让前半输出准备后半共享的长历史；旧位置可以少走后半，但近邻窗口还要补，新位置仍走完整模型。 | `(2,1)` 乘 `(3,−1)` 得到一个 K 分量，说明“投影”做什么；随后用 400→208 解释省了哪部分工作，再落到实际行数、原位置与共享 KV 的取证。 |
| SWA 回放 | 长历史命中与各层窗口存在是两件事。只算末尾能补一个近似窗口；较早位置少看的信息会逐层传到末尾，所以最后一层读到相同位置也不保证值相同。 | 两层均值例从原值到第一层 `2,4,6` / `6,6,6`，再到末尾 `4` / `6`，补齐了原文缺少的因果步骤。后面才区分两种恢复路径、槽位口径、布局等价和任务质量。 |
| DSpark | 草稿先猜，主模型按连续前缀验证。两请求各带一个已知末尾，选择验证 A 两个、B 一个，所以输入五行；接受与替代后本轮只新增三个编号，不能把已知末尾重复计入输出。 | 同一组 A/B 继续用于概率累乘、三个名额分配、整轮成本与现场记录；再讲草稿内部和异步时序，术语不再抢在完整一轮之前。 |
| 低精度 | 少位数只能保存有限的数；把 2.8 除以 0.5、舍入成 6，再乘回得到 3，空间减少伴随误差。字节、系数、分组和解读规则必须一起匹配。 | 同组数继续算点积和异常大值；再用同一字节读成 1.5 或 1.0 区分格式错误，用 scale=4 的错配区分缓存错误和正常量化误差。 |

这里的“前两屏”是基于实际开篇内容长度与图序的教学测试，不代表已在桌面页面上确认屏幕边界。四页都能复述“是什么、为何需要、代价在哪”；没有借用后部配置表替开篇过关。

## 逐项保留核对

### 模型结构

- [x] CED 的全局 KV 与各层 SWA 分开；语言 encoder/decoder 与 Vision Encoder 分开；prefill 与 decode 的省算范围分开。
- [x] 四层、100 个位置、后半保留 4 个位置的 `400→208` 示例保留，仍明确忽略投影、选取与搬运，不把工作份数当成时延实测。
- [x] 压缩、稀疏选择与跨层共享分别解释；索引模块、索引 K、主 KV 的共享范围没有合并。
- [x] 配置表保留：40 层和 20/20、5120、64 个 query 头/1 个 KV 头、512/64；前两层 SWA、压缩率 2/1；主 KV 来源 2/8/14/20；索引模块来源 2/8/14/20/24/28/32/36；32×128、最终 512；来源 20 的 2048×8 候选池；SWA 128；384 选 6 加共享专家；草稿 3 层/5 候选；视觉 32/1024/14。
- [x] Engram、mHC 不等于请求 KV；参数、活跃计算与请求状态仍是不同账。
- [x] 288/68/528 B、192+128=320 条、113920 B 分页载荷及其未包含项完整保留。
- [x] 主机持久保存与运行时显存分配分开；GLM 不能直接套 CED；版本、默认值、源码入口与待核边界保留。
- [x] 新增示意投影只是前半向量生成 K 的教学例，不声称等于普通 decoder 跑完后层的结果，也不声称各层输出相同。

## 图与原始证据

实际查看了旧样板 `kv-cache.png`、`quantization-dot.png`、`tensor-parallel-two-splits.png`，以及本次九图。当前图使用整块加格线、语义颜色、有限箭头和相同背景；不再仅以文字流程框充当机制解释。

| 图 | 实际看到的机制与判断 |
| --- | --- |
| deepseek-model-intuition | 普通四层各自准备历史，与前半投影后半共享明确对照；绿色计算位置、蓝色历史与末尾窗口可分辨。没有把共享 KV 画成后层完整输出。 |
| deepseek-model-flow | 模型配置、共享映射与实际 100→4 行相连；原位置错误与行数未减是不同证据。 |
| swa-replay-state | 已存全局历史与缺失的两层窗口分开；回放输入经过计算成为近似窗口。最后修订明确格内 7/8/9 是位置。 |
| swa-replay-intuition | 两条路径第一层值和第二层末尾值逐格可算；颜色标出边界变化，不仅画相同末尾位置。 |
| swa-replay-flow | off/mask/compact 的输入行与可见窗口分开画；mask 保留行而 compact 删除行，语义相同的部分有视觉对照。 |
| dspark-intuition | 已确定末尾、被选候选、未选候选、接受、拒绝替代与最终输出均有可追踪编号；输入 5、输出 3 对得上。 |
| dspark-flow | CPU 总预算与设备更新置信信息从两路汇合，随后才形成下一轮五行；不暗示 CPU 预先读到尚未产生的新信息。 |
| low-precision-intuition | 原值→除 scale→可表示值→读回值全部可算，scale 单独保存；最后连线调整待最终页面布局复核。 |
| low-precision-flow | 字节格式、正常舍入、计算差异、缓存系数错配有不同证据，图中 4.7/5.25 和 2/8/24 与正文一致。 |

原论文像素证据：`sources/deepseek-v41-p7.png` 的总体结构和 `deepseek-v41-p9.png` 的 CED/SWA 公式，来源为 [V4.1 报告](https://arxiv.org/html/2609.19969v1)；配合固定配置与 `yoco_swa_share_hidden=False` 核对全局 KV 来源和逐层 SWA，避免仅按名称猜结构。缓存文件均位于本轮 `tools/wiki-runtime/inference-teaching-2026-10-26/` 或前轮 `inference-diagrams-strategies-2026-10-24/sources/`。

同字节例的依据是 [OCP MX v1.0](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf) 物理第 11 页的规格化公式与偏置：`00111100` 分别为 E4M3 的 1.5、E5M2 的 1.0。NVFP4 的 16 元素局部 E4M3 系数加张量级 FP32 系数核对 [NVIDIA 原说明](https://developer.nvidia.com/blog/introducing-nvfp4-for-efficient-and-accurate-low-precision-inference/)。DSpark 信息轮次对照原论文 §5.2 和钉住实现 `mtp_varlen.hpp`，没有把教学概率例当成采样分布证明。
