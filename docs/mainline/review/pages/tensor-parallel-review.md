## 二、问题清单

### P1（事实或数字错误）

**P1-1　`wiki/concepts/tensor-parallel.md:349`　复制部分漏掉 54 MiB 索引器 FP32 常驻副本，导致 TP4 / TP16 估算偏移**

- 证据：页面写
  ```
  复制部分 = 193.5 + 135 + 267 + 68 + 64 = 727.5 MiB
  > 依次为 router、mHC、MLA 低秩与索引器、KDA 低秩门、MTP 输入投影；沿用部署权重账，忽略 KiB 级小项
  ```
  我把这五项逐一反推，**全部精确对上**底稿的分项（router 42×4.5+4.5=193.5；mHC 135；MLA 低秩与索引器 12 层×22.25=267；KDA `f_a`/`g_a` 34 层×2=68；`eh_proj` 8192×4096×2=64 MiB），说明推导过程是真做的。
- 但 `docs/mainline/02-forward.md:134` 另有一项 **54 MiB**：索引器首次前向时把 `wk_weights_proj` 和 `index_kpool_compress_gate` 各转一份 FP32 常驻缓存，每层 4.5 MiB × 12 层 = 54 MiB/卡。它是**复制**的（页面自己第 199–201 行的表就把索引器列为 replicated），却被留在了「可切部分」里。
- 独立复核：按底稿分项自底向上重建可切部分 = 302.5(embedding+lm_head) + 1,108.9(KDA) + 165(MLA 主干) + 126(共享专家) + 18(MTP) = **1,720.4 MiB**，而页面写 1,774.5 MiB。
- 影响：TP4 由 22.32 → **22.26 GiB**，TP16 由 19.72 → **19.74 GiB**，TP8 锚定值 20.58 GiB 不变。0.06 GiB 量级，**不改变本节任何结论**（TP16 省权重有限、TP4 不能靠权重账排除都照样成立）。
- 建议：把 `复制部分` 改成 `193.5 + 135 + 267 + 68 + 64 + 54 = 781.5 MiB`，注脚补「索引器 FP32 常驻副本，见部署页」，后面三行的 1,774.5 改 1,720.5、22,852.5 改 22,798.5、20,190.75 改 20,217.75、两个 GiB 值同步。

## 三、以初学者视角，最卡住的 3 个地方

**1）KDA 状态：刚算出 18.2 MiB，下一句变成 85 MiB（`:172-183`）**

calc 块一步步把每层每请求算到 `561,152 B`，读者顺手乘 34 得 18.2 MiB；紧接着正文说「34 层实际合计 **85 MiB**/请求/卡」。中间 4.67 倍的差只用「物理页还有补齐及投机状态副本」一句带过，并甩到部署页。读者第一反应是自己算错了。
底稿其实有完整桥梁（`docs/mainline/02-forward.md:304-310`：每层 4 页 × 655,360 B = 2,621,440 B，34 层 = 89,128,960 B = 85.0 MiB）。建议在正文补一行 `有效 561,152 B → 物理 4 页 × 655,360 B`，把倍数落地，再链出去。

**2）MC2 与 ALLGATHER 两条路径，以及「不能重复计数」（`:239, :249-255, :304`）**

读者要同时记住：两条互斥路径；共享专家的 All-Reduce 在两条路径里位置不同；MoE 外层那个 `maybe_all_reduce_tensor_model_parallel` 在 MC2 分支**直接返回**所以不算一次。第三点是整篇通信账能不能对上的关键，却压缩在一句话里。
（我核过源码，这个判断**完全正确**：`register_custom_ops.py#L159-L167` 在 MC2/ALLTOALL/FUSED_MC2 下 `return final_hidden_states`；`fused_moe_0_23_0.py#L663-L670` 反过来在同样条件下才做 All-Reduce，源码注释原话就是「exactly the opposite of」。）
建议给这一句单独一个小节或一个高亮块，把「一加一减」的互补关系画成两行对照，别让它淹在段落里。

**3）row parallel 之后「形状完整、数值是部分和」——全页最核心的一句，图没托住（`:106, :364`，图 1）**

这是 TP 的题眼，正文说得很准。但图 1 把 P₀…P₇ 画成一行 8 个等宽小格，视觉上读起来是「一个东西被切成 8 片」，而实际每个 Pᵣ 都是**完整的 `[4,4096]`**、只是数不全。图和文在这里打架，初学者大概率按图理解错。
建议把 P₀…P₇ 画成 8 个同样大小的 `[4,4096]` 方块（叠放或并排都行），每块内部用浅色纹理表示「数不全」，而不是一行窄条。这一处改对了，整页的理解成本会明显下降。
