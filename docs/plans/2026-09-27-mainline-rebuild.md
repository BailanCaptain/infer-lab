## 5. 页面标准 v2

§5–§5.2 已整理进 docs/wiki-writing-standard.md，以后以该文件为准

每个读者页都要有下面这些内容：

1. 一句话说清它是什么。
2. 挂在主线哪一站：请求走到哪一步时会遇到它，这一站为什么需要它。
3. 在我们的部署下长什么样：每张卡上的形状、次数、字节数、显存，写出可以复核的算式。
4. 图：至少 1 张「站点位置图」，再按需加机制图。图用手写 spec 生成 SVG。
5. 逐步推演：沿着示例请求一步步走，照样章的写法。
6. 对照源码：源码位置；怎么开、怎么关；默认值，按 v0.23 / v0.26 / main 分别写清；会报什么错；开销。
7. 常见误解。
8. 下一步和相关的站。

还必须遵守仓库的硬约束，以 `2026-09-27-page-inventory.md` §1 为准，这里不重复。主要有这几类：
- frontmatter 字段；
- `## 对照源码` 的固定结构；
- 每页在 toc.ts 里只能出现一次；
- 跨页重复检查：深入页引用主线页，不要复述主线页的内容；
- 图只用 wiki-diagram 格式，yaml 和 svg 必须一致。

术语规则（09-27 用户定）：有固定英文名的术语，一律用英文原名，不翻译成中文。「固定英文名」指源码里的标识符、官方文档里的名称、论文里的名称。术语第一次出现时，用中文解释它是做什么的；这是解释，不是给它另起一个中文译名。

禁止：
- 用否定式免责句代替答案。不知道就写「待核：缺什么」。
- 用玩具规模代替真实参数。可以先用小例子讲原理，但必须回到真实数字。
- 术语没解释就先用。
- 用脚本批量生成或改写正文和图。
- 删掉旧版已经核实过的条件而不给源码证据。

**09-27 新增的深入页标准**：图的画布宽度 ≤ 900px（在 1280 宽的屏幕上正文栏只有 968px，还要减掉图框内边距；全库 136 张图本来就是 900 宽）。放不下就重新设计布局（改成纵向排、拆成两张、精简节点），不靠横向滚动。

### 5.1 单一出处表与写手常见错误（09-27 起，每个写页的提示词都要附上）

同一段推导只允许在一页里写，其他页只写结论，再链接过去：

| 推导 | 唯一出处 |
|---|---|
| KV 预算、每块字节数、3,855 块（算例）/ 3,908 块（精确） | glm-5-3-flash-two-node「剩下的显存变成多少 KV cache」 |
| 16 卡分组、每卡放什么、为什么用两台 | glm-5-3-flash-two-node |
| MC2 容量门槛 128 | one-request（MoE 那一站） |
| R1 的 15 块、七站的形状、字节数、通信次数 | one-request |
| 图尺寸补齐、两组对齐、空闲组陪跑 | concurrent-requests |
| 进程、类、函数调用链，按日志认站 | request-call-chain |

写手反复犯的错：
1. 把「每台机器 / 每个 DP 组」说成「完整的模型副本」。实际是 EP16 把 288 个专家分到 16 张卡上，每台机器是一个 DP 执行组，两台合起来才是一份完整的模型。已经在 4 页里出现过。
2. 术语先用后解释。要求每个术语第一次出现时，就地用一两句中文解释清楚。
3. 两页各推导一遍同一个量，结果对不上。按上面的单一出处表链接过去。

### 5.2 深入页讲法：先直觉、后数字（09-27 用户审 P4 后定）

用户读完 TP/EP 试点页：「看完还是不知道 TP EP 是什么」。诊断（会话 scratchpad/p4-busy/report.md）：两页先算 GLM 双机账、后讲概念；TP 第一张图前已有 3 个 calc、44 个数、约 38 个术语；直觉图缺失或画成部署图；calc 每千字 2.3（样章 0.8）；行内代码每千字 24.4（样章 13–15）；正文带角标 28 行（样章 0）。§5「必须回到真实数字」被执行成「一上来就是真实数字」，本条纠正。

深入页（并行、特性、机制页）骨架：
1. 第一屏：H2 用读者的问题命名；一句话定义（只用已解释的词）；一张通用直觉图，只画原理、只标卡数，不标字节、不画 GLM 形状，图里要看得出东西怎么流动。
2. 第二屏：为什么需要（一个真实数就够）；代价在哪（哪一步后通信、每层几次）；和相邻概念的区别（一段或 ≤4 行小表）。
3. 然后落到 GLM 双机：按「一个 token 走一遍」排，不按层类型排目录；每节一句结论 + ≤1 个 calc；表和 calc 不相邻；场景 M 等整批账单独放后面的 H2。
4. 特殊层（KDA、MLA、词表、共享专家等）集中一节，只讲切法哪里不同，细节链到各自页。
5. 常见误解 → 对照源码。参数名、报错串、commit、版本表集中在对照源码；正文行内代码每千字 ≤13。
6. 对照源码之上零证据角标，全部放页末来源；「待核」也放页末。

验收加「初学者测试」：审查员只读前两屏，说不出这个概念是什么、代价在哪，记 P1。
