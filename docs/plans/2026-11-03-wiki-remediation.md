# Wiki 学习内容整改方案

本轮按用户 2026-11-03 的授权连续执行：先落实已确认问题，再分组审查全站，依据审查结果制定第二轮方案、整改并验收，最后统一汇报。无需在方案阶段再次等待批准。

## 目标与范围

学习者能解释真实部署中的资源、进程、模型状态和特性组合，知道结论对应的模型、硬件、软件快照，以及如何验证。保留固定 GLM 双机教学基线和已有有效推导，不把最新教程的参数直接套回旧算例。

第一轮依据为前轮已读的 29 篇官方文档、现有页面和发布实现。官方资料固定到 vllm-ascend `921ccc52c6d8c9864190b981792318a489aeadf4`；现有 v0.23、v0.26、v0.30.0rc2、main 教学钉点继续以 seeds 为准，不移动既有 main 含义。新增现行资料在正文明确标注日期和完整快照。

全站审查覆盖正式概念页、参数页、来源页以及导航、检索、发布入口。图只在受影响的事实或布局需要变更时修改；不重做已认可 3D，不将本轮静态审查冒称 NPU 实测。

## 保全与编辑方式

工作区已有大量未提交修改。执行前在 `.tmp/wiki-remediation-2026-11-03/before.zip` 保存受影响目录的当前文件和哈希，后续以该快照比较本轮变化，不用 Git HEAD 覆盖工作区。

仅机器历史尾注的清理和骨架迁移使用确定性迁移；教学正文逐页撰写。迁移前后的活动正文逐字比对，保持来源编号、算例和有效结论不变。已经提交的历史由 Git 保存，未提交旧稿由本次工作区快照保全；不另建面向学习者的历史页面。

实施前写作标准要求保留机器历史尾注，与用户明确要求移出学习内容冲突。本轮以用户授权为准，同步更新标准、生成器及校验，保留审阅决策中的证据责任。现有自动发布仍须遵守原审批机制；本次人工协作修改已获得用户明确授权。

## 全站分组审查与第二轮方案

第一轮整改完成后，按下列组读取当前完整正文，检查定义、条件、算例、页面间衔接及对应官方材料；每页进入覆盖记录。机械扫描只负责定位和盘点，不计为内容阅读。

1. 入门、模型结构、数学与逐层计算。
2. 请求生命周期、调度、并发、采样与服务接口。
3. 硬件、并行、通信与多机部署。
4. 缓存、状态、卸载、PD 与共享存储。
5. 性能、量化、图、投机、可靠性及排障。
6. RFork 专题、参数与来源页。

逐组记录页面、已核内容、问题级别、原始证据、修法和验收结果。新发现汇总为第二轮方案后直接实施；已有正确内容保留，不为了统一篇幅重写全页。重要问题修订后复审，不以自动检查替代语义审查。

## 验证与交付

- 代码修改先以失败测试证明问题，再修复。运行相关测试、类型检查、Lint 与构建。
- 运行 `check:content`、`wiki:lint`、`wiki:audit`；图有变更时运行 `wiki:diagrams --check`。
- 独立审查者阅读实际修改页、关联页及 diff；P1 修订后复审，P2 全部处理。
- 在桌面浏览器实际阅读修改页，操作目录、跨页链接、锚点与检索；关注前两屏、表格及算式。
- 最终交付两轮方案、逐组审查记录、修改清单和实际验证结果。无法做 NPU 实测的事项准确区分为文档或源码证据，不以实测口吻发布。
