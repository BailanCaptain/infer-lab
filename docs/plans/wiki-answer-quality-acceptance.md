# 独立回答质量评判：实施与验收（2026-10-06）

## 目标与范围

承接 [F004 AC3](../features/F004-knowledge-loop.md)：将回答模型的自报覆盖状态升级为独立调用的检查结果，接入现有缺口、审批与复测流程。不另建队列，不自动发布知识，不开启夜间任务。F004 其他 AC、F001–F003 的整体真实场景验收不因此完成。

独立指新会话、无工具、只读材料的模型调用；仍使用本轮开始时状态页选中的接入方式和模型，不擅自改用另一模型。判定输入绑定问题、上下文、完整回答和知识快照 revision，回执及模型用量走既有持久化工作流。

## 实施结果

1. 每个成功完成的网页回答增加一次独立检查。页面显示“正在独立核对”、分类及理由；调用失败、格式或证据校验失败显示“核对未完成”，保留原回答。
2. 区分有据可答、回答错误、所查材料缺知识、漏检、版本不适用和未判明。引用必须逐字存在于所给页/回答中；漏检必须引用原作答材料以外的页；版本差异至少有两个不同引文。引用匹配只是机器校验，理由和分类仍为模型判断。
3. 不满足或未判明的结果以 `independent-review` 信号记录判定回执 ID，沿用同问题累计三次排队机制。独立通过不再因回答自身的未覆盖标记新增信号；实际联网尝试仍按原约定保留观察。明确不满足的回答不提供“存进 Wiki”。
4. 发布前后四类复测复用同一检查器，各题回执新增独立评判。冻结判准不交给作答模型，人工逐题验收仍保留，独立评判不自动关闭缺口。旧复测记录不被重写为已通过新检查。

实现入口：`server/answer-quality.ts`、`server/chat-route.ts`、`scripts/wiki/retest.ts`；机器协议在 `src/content/wiki/answer-quality.ts`，不另复制配置或引入依赖。

## 真实模型检查

以已验收的固定版 vLLM v0.10.0 FP8 隔离知识库作为材料，使用 Codex / `gpt-6.1-sol`。五个预先指定的样本均符合预期分类：

| 样本 | 结果 |
|---|---|
| 1024 个 FP8 标量、不含元数据，回答 1024 B | covered |
| 刻意写错为每个 2 B／总计 2048 B，并自报已覆盖 | answer-error |
| 无依据地肯定 Ascend / Atlas A2 支持 | answer-error |
| 明确资料只能支持 CUDA/ROCm 条件，Ascend 未知 | covered |
| 作答未获页面、回答无法确认；独立检索找到容量换算 | retrieval-miss |

这些是人工构造的答案检查样本，不冒充五次真实用户问答。输入、期望、实际结果保存在 `tools/wiki-runtime/quality-real-20261006/results.json`，五次真实判定回执保留。

另外通过真实 `handleChat` HTTP 路径，在新的隔离库运行一次真实问答与独立判定：HTTP 200，回答为 1024 B，引用有效，独立结果 covered，返回可保存 answerId，没有 error 事件。SSE 和调用回执在 `tools/wiki-runtime/quality-http-20261006/`。准备阶段漏拷图目录导致快照拒绝，补齐隔离夹具后完成；没有改动快照校验。

## 取舍与剩余工作

- 每个新回答多一次模型调用；沿用共享预算/账户用量机制，失败不自动重试。模型上下文、超时或额度导致检查失败时，不展示通过。
- 只核对所提供的材料，最多 10 页、每页 8000 字符、正文合计 26000 字符；截断和省略范围进入回执。它不是全库不存在某项知识的证明，也不能发现所有源材料本身的错误。外部原文没有联网重核。
- 五例真实检查与一次 HTTP 链路不能替代全库质量评测；尤其版本差异分类的跨版本真实场景仍在后续整体验收中。
- 现有补写、审批、四类复测和人工关单闭环在本轮集成测试中重跑；没有宣称本轮重新做了所有真实资料补写和发布实验。正式用户知识库内容未因这些隔离测试改变。
- 下一项为课程术语/页面入口映射与已有缺口核对，之后做多版本导入、成组问答、参数分类和 GitHub 反例验收。无新增待用户拍板项；代码未提交或推送。
