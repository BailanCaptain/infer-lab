# F005 Drop 验收证据

日期：2026-10-06。Feature 的需求与最终状态只维护在 [F005](../features/F005-wiki-drop.md)；实施步骤见 [计划](wiki-drop-plan.md)。本记录分别列出最终工程回归、真实资料前后测和限制，全部约定样本已形成闭环。

## 实现范围

- `src/content/wiki/drop.ts`：网页与 CLI 共用契约，区分来源、修订、批次、系列和页面身份。
- `scripts/wiki/drop-batch.ts`、`drop-fetch.ts`：不可变原文/解析快照、幂等接收、静态 HTML、遗漏报告、预检和跨次指令隔离。
- `scripts/wiki/drop-run.ts`、`drop-integration.ts`：固定模型的持久阶段、缓存与恢复、完整候选目录、按需读取正文、外部补证、多页与资产生成、独立复核。
- `scripts/wiki/drop-assets.ts`、`review.ts`：图布局与 SVG 校验，正文/公式/图/目录整组发布，base 变化阻止覆盖，原发布事务恢复。
- `server/drop.ts`、`src/app/wiki/DropPane.tsx`：预检、明确开始、系列续传、取消、重试、换模型新尝试与整组审阅。
- `src/app/wiki/DropReviewPreview.tsx`、`server/review.ts`：目录和算式前后预览；图以宿主生成 SVG 显示。

## 验证环境和边界

使用既有 `feat/llm-wiki` 工作树。真实测试分别位于忽略目录 `tools/wiki-runtime/drop-real-20261006` 与 `drop-real-correction-20261006`，没有导入真实正式 Wiki。模型固定为全局选择 Codex / `gpt-6.1-sol`，每次调用为新会话、禁止工具；输入原文与正式页面由宿主明确提供。

正式 Drop 不使用旧测试预算的业务次数/费用限制。仍记录调用和供应商回传用量；没有回传的用量显示未知。单份资料 1 MiB、HTTP 请求 8 MiB、单次模型上下文 900 KB 和单次超时属于资源/故障边界，达到边界明确失败，不截断原文或声称完整读取。大批次可分次补资料；单次上下文超限需要拆分批次。

HTML 使用 parse5 结构解析；不执行网页脚本、不登录、不解析图片或附件，报告遗漏。只允许公网 HTTP(S)，校验重定向与解析地址，连接固定到已检查地址。沿用环境代理时使用 Node 原生代理 Agent，需要 Node 22.21+ 或 24.5+。

## 真实样本和固定判准

### APC 新知识与主动补证

原始资料：[vLLM v0.10.0 APC](https://raw.githubusercontent.com/vllm-project/vllm/v0.10.0/docs/features/automatic_prefix_caching.md)。批次 `63c076fb-5b1e-4a99-9f99-265fd915839f`。模型主动补取同版本设计文档和离线示例，原文均存内容 hash 快照。

前测在空隔离库进行，三个问题均回答没有页面依据：prefill/decode 差异、无共同前缀能否保证收益、能否证明 Ascend 某版本默认开启。后测已通过：只省共享前缀 prefill、不减少 decode；无共同前缀不能保证收益；Ascend 默认值仍回答未知，未以显式 `True` 代替默认值证据。答案均指向实际正式来源页并保留 v0.10.0 范围，记录为 `query-before.json` 和 `query-after.json`。

定位阶段的显式测试限额从 20 调整到 60、100 次，实际历史调用不清零；这不是产品限制。累计 90 次编译/修订调用包含开发期失败与取消，不能作为成熟功能单批耗时基准。发现并以失败测试修复了：末尾换行导致引用越界、单页修复重复发现/抓取、后续错误丢失早先协议修复、完整性问题反馈遗漏、精确行号子区间，以及宿主序列化移除规范要求的 evidence 引号。网络中断、格式和别名错误均停留在未发布状态。

审阅 `f50695b078ab2dac37e58be25d9a8fc8dd26102c1673829e3655d6909e9cb7e7` 已使用真实批准校验发布到隔离库：3 个来源页、3 张图、3 条有理由的依赖边。逐页核对文本与来源，设计中的扩展提议未升级为已实现功能，示例计时未冒充实测。1280/390 px 实际阅读全部三页并核对图数量，无页面横向溢出；三张图的桌面截图已查看，手机使用既有滑动看图交互。证据在该隔离目录 `browser-results.json` 与 `*-figure-*.png`。

### FP8 纠错与新教学页

原始资料：[vLLM v0.10.0 Quantized KV Cache](https://raw.githubusercontent.com/vllm-project/vllm/v0.10.0/docs/features/quantization/quantized_kvcache.md)。批次 `333c8c08-0f9a-4d47-8f02-473cd03a903c`，显式测试调用上限由 40 调整为 70，历史用量保留。

在隔离库刻意注入“FP8 每标量 2 B”、1024×2=2048 B 及错误配图。该初始页是合成错误夹具，不是官方事实。前测如实依赖旧页，给出 2048 B；时延保证和 Ascend 支持问题均表示未知。后测须为 1024 B，保留不含元数据的条件，不宣称吞吐翻倍或时延必然降低，也不能证明 Ascend 支持。

已通过真实批准校验并发布隔离审阅 `c51e6a4d126453e3961c16f0880e6d18125711402bacea74287e5f6028c8394e`：

- 旧 `fp8-capacity` 的摘要、正文、算式与原有图一起改为 1 B／1024 B；宿主保留原来 2 B／2048 B 的逐字历史、旧来源和新替代依据（官方原文第 7–12 行）。
- 新来源页记录固定版本，新概念 `kv-cache-quantization` 包含机制、容量与配置三图及目录落位。独立复核指出的缩放因子缺少写入依赖连线已由模型修订，未手改生成页规避验收。
- 后测正确回答 `1024 × (8 ÷ 8) = 1024 B`，保留不含元数据的条件；不承诺时延下降、不推断 Ascend 支持。额外未参与编译的改写题用“一千零二十四个 8 位值”“Atlas A2”提问，结论与未知边界仍正确，见 `query-after.json` 与 `query-paraphrase.json`。
- 1280/390 px 浏览器实际阅读三个页面，核对 4 张图均渲染，手机画布可键盘聚焦并滑到末端，页面无横向溢出。已查看四张桌面图截图：缩放输入/恢复连线一致，2048 B 对照条为 1024 B 条的两倍，旧图显示 1 B／1024 B。记录见 `browser-results.json` 与 `*-figure-*.png`。
- 在真实已发布审阅记录中重新打开前后预览，桌面和手机均断言旧公式为 `2048 B`、新公式为 `1024 B`，同时显示旧图与新图，见 `real-review-formula-1280.png`、`real-review-formula-390.png`。首次自动化误把第二次打开后保留的详情状态当成列表，补上“全部变更”的正常导航后通过；未修改应用状态保持行为。

该样本累计 52 次开发期编译/修订调用，含问题定位与取消。没有设备测试，不把样本教学页对 GLM 主线的概念定位写成该部署支持确认；隔离库本身没有正式 GLM 主线页，报告明确这一缺口，不造无效链接。

## 结论适用范围

本轮证明约定三类公开样本在固定模型选择下能够收录、整合、审阅、发布并复用，也覆盖了没有知识增益的结束路径。它不是对所有资料的正确性保证。开发期共 161 次批次调用（90＋52＋16＋3），另有前后测与改写问答；保留全部实际记录，不清零失败或取消，不把 ChatGPT 订阅调用的未知美元费用记作免费。

真实测试所有写入均在隔离库。实际用户库仍由用户整组批准；当前模型选择和夜间任务配置保持原值。未提交或推送本次代码，未覆盖其他未提交的参数、日志及运行记录。

## 使用入口

网页：知识库助手 → Drop → 粘贴正文、上传 MD/TXT 或填写 URL → 接收并预检 → 开始处理 → 查看整组变更 → 批准或附意见退回。收录目的、来源标识、版本和系列均选填；已开始批次不能修改输入，续传产生关联新批次。

CLI：`pnpm wiki:drop <文件或目录> [--why 目的] [--collect-only]`，或 `pnpm wiki:drop --url <公开网页>`。单份资料可用 `--identity` 与 `--version`；通过 `--batch <批次id> --retry-failed` 恢复，`--new-attempt` 使用当前全局模型重新整合。旧 `.rst/.json/.csv` 文本入口保留。运行资料中的代码不会被执行。

待审期间正式内容或依赖资产变化：重新整合产生新审阅包；不能强制覆盖或自动批准新提案。发布中断：审阅页恢复本次完整发布。
