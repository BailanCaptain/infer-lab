## 2026-11-01：发现、上下文与证据完整性

### 本轮实现

- `drop-discovery.ts` 复用现有全文检索器，在固定 Wiki 快照内查询正文、标题和别名，分页继续查找，不设候选总数上限。影响范围包括正反向关系、相对 Markdown 链接、共享图的全部使用方，以及模型在复核中发现的语义依赖。
- `drop-context.ts` 保存带 hash 的材料身份与来源信息。同次请求合并同材料的重叠范围；摘要和历史已读记录不能替代当前请求的原文。新来源逐段读取；后续任务保留当前完整段及逐字引文所在的跨段原文段落，避免一次宽泛补读永久变成后续每次必带全文。引文所在段落的未引用限定条件、不同版本中相同引文的全部命中均保留，其他范围仍可补读；最终逐页复核仍覆盖来源的全部段。旧页完整阅读；长旧页使用精确范围修改，未改文字逐字保留，重叠修改、过期 hash 和切开 Unicode 字符均拒绝。
- `drop-integration.ts` 的发现、生成、逐页和跨页复核均支持继续查询、翻目录、补读原文与旧页。生成一个目标时不累计传入此前所有生成正文；其他目标的完整分工和正文可按需读取。新长页可按稳定章节生成后合成，最终仍核完整候选。
- 同一任务中指向同一旧页、同一原文范围的比较理由合并复核，全部理由保留；固定预算放不下时继续拆成较小检查，不删除理由或事实。小窗口回归验证四条理由可拆开完成。
- 通用规则保持注入；完整手册、术语、图 schema 与公式规则以可读材料保留，按用途取回。教学页仍收到正式写作标准，来源页遵守自己的格式范围。超量补读明确标记未提供的范围，要求重新请求较小范围，不能直接跳到结论；必需证据本身仍无法容纳时失败并保留检查点。
- 新提案使用协议 3，固定本次模型、Codex 路径、上下文窗口与输出预留。缓存键包含规则、材料、模型与预算。审阅包绑定实际输入、阅读范围、比较引文、原文处理决定、逐页及跨页检查；发布时重算必要任务、候选和依赖身份。删除复核记录、遗漏源段、候选变化、出现新页或降级协议都不能绕过门禁。旧协议记录不补默认字段，保留既有内容 hash。
- 审阅与归档页面显示整合理由、比较旧页、原文链接、阅读覆盖、跨页/共享资产检查与材料输入字节；字节不冒充 token 或费用。覆盖表示实际提供，不声称程序能证明模型理解无遗漏。

没有新增依赖；正式 Wiki 仍整组人工审批，未将实验页写入用户知识库。

正式 Drop 不使用旧测试预算的业务次数/费用限制。仍记录调用和供应商回传用量；没有回传的用量显示未知。单份资料 1 MiB、HTTP 请求 8 MiB、单次模型上下文 900 KB 和单次超时属于资源/故障边界，达到边界明确失败，不截断原文或声称完整读取。大批次可分次补资料；单次上下文超限需要拆分批次。

HTML 使用 parse5 结构解析；不执行网页脚本、不登录、不解析图片或附件，报告遗漏。只允许公网 HTTP(S)，校验重定向与解析地址，连接固定到已检查地址。沿用环境代理时使用 Node 原生代理 Agent，需要 Node 22.21+ 或 24.5+。

## 使用入口

网页：知识库助手 → Drop → 粘贴正文、上传 MD/TXT 或填写 URL → 接收并预检 → 开始处理 → 查看整组变更 → 批准或附意见退回。收录目的、来源标识、版本和系列均选填；已开始批次不能修改输入，续传产生关联新批次。

CLI：`pnpm wiki:drop <文件或目录> [--why 目的] [--collect-only]`，或 `pnpm wiki:drop --url <公开网页>`。单份资料可用 `--identity` 与 `--version`；通过 `--batch <批次id> --retry-failed` 恢复，`--new-attempt` 使用当前全局模型重新整合。旧 `.rst/.json/.csv` 文本入口保留。运行资料中的代码不会被执行。

待审期间正式内容或依赖资产变化：重新整合产生新审阅包；不能强制覆盖或自动批准新提案。发布中断：审阅页恢复本次完整发布。
