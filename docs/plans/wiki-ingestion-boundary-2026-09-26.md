# 教学改版：现有入库路径的能力边界

2026-09-26 静态核读；没有触发自动代理、付费调用或任何发布操作。

| 检查点 | 实际实现 | 能证明什么 / 不能证明什么 |
|---|---|---|
| 写作规则传入代理 | `scripts/wiki/ingest.ts` 的 extract / integrate 请求把 HANDBOOK 的页面格式与对应角色切片一起注入；`handbook.ts` 把 TERMS 拼入写页切片 | 新基础规则与术语能进入写作上下文；不保证代理遵守或解释正确 |
| 同 id 修订 | `revisions.ts` 区分 supplement / editorial / supersede，核对旧原文、替代结论和来源，并维护历史 | 防止无记录覆盖特定事实；分类与来源语义仍需审阅 |
| 正式写入边界 | `review.ts` 只接受允许目录与内容，检查 base 哈希，派生 registry/index 在发布时生成 | 避免过期提案覆盖已变化页面；不识别遗漏的知识依赖 |
| 手写草稿入库 | `stage.ts` 走同一副本验证与待审包路径 | 不因“手写”跳过格式和来源检查；不是自动批准 |
| 结构检查 | `integration-check.ts` 执行 lint 与源码路径/行号审计 | 能检查可定位性；URL 返回的 url 判定不等于联网验证，行号有效不等于结论成立 |
| 主题目录 | `src/content/wiki/toc.ts` 按稳定 id 编排，未收录的新教学页进入“待编排” | 新页不会消失，但程序不会自动选择正确学习主题 |
| 图与目录写入 | 正式页发布 allowlist 不包含图规格/目录代码 | 图与目录需维护者另行更新并验收，不能声称现有自动流程会一并生成正确配图与分类 |

本轮只完善 HANDBOOK 的内容责任、TERMS 和使用说明，不扩张自动编译/同步系统。新增架构默认以独立案例和差异页接入；如证据推翻旧事实，审阅者须追踪正文、图、公式、摘要与依赖页。已有工作流提供审阅与可追溯基础，未实现全面的语义影响分析。
