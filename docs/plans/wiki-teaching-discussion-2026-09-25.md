## 后续新架构加入时的内容演进原则（本轮建议，待落实）

知识库可以持续扩展，GLM-5.3-Flash 教学主线保持稳定。新架构通常新增专题及差异说明，链接已有概念，避免整套复制；读者不必因新模型加入而重学另一套贯穿案例。

| 新材料的性质 | 对现有内容的预期影响 |
|---|---|
| 新模型/新架构（如 DeepSeek 的另一条注意力路线） | 新增模型结构与差异专题，放入明确目录，关联注意力、MoE、缓存和并行等已有主题；不自动替换主模型 |
| 同一通用概念的新解法 | 在概念页补适用范围/变体入口，需要时另开详解页；通用定义单处维护 |
| 新框架版本改变支持、参数、默认值或执行路径 | 在对应版本边界内修订实现说明，保留旧版仍然正确的结论；不把 main 新行为套入已固定发布版案例 |
| 新证据证明旧结论错误或过度泛化 | 修正相关正文、图和推导，并检查依赖页面；教学主线稳定不是保留错误的理由 |
| 希望升级全篇贯穿模型或部署版本 | 独立规划迁移范围，重新核验数字、图、调用链和参数，不能由普通材料入库顺带触发 |

已有 HANDBOOK“整合”规定同 id 可修订、不同 id 同主题可合并，需写修订理由并保留版本边界；已有 relations 可以表达依赖和变体。上述依据是本轮读取的规则，不代表已实测所有自动流程。本轮未审计/修改运行时，不能承诺新增材料绝不会改旧页。仍需把主模型/部署事实与通用概念的边界、目录落位、影响检查纳入后续写入与审阅规范并验证；已发现无标题自动追加问题也需修正。

## 根据最新反馈调整的导读方案（待讨论）

调整上一轮“先全面讲架构再追请求”的建议：先给够用的模型和系统总览，走单请求、并发请求，再归纳正式架构、深入源码。主目录按知识对象组织，导读按学习顺序串联。

1. **认识模型**：名称、Dense/MoE、注意力类型、参数规模和必要配置。2D 总图展示 Token IDs → Embedding → Decoder Blocks → Final Norm → LM Head → logits；采样画在模型前向之外，再画 token 反馈到下一轮。展开单层 Attention/MLP、Norm、残差，标张量形状和 KV 分支。
2. **服务就绪**：权重已加载、缓存资源已准备。启动与每次请求不同，启动细节后文再展开。
3. **单请求闭环**：HTTP/聊天模板/分词 → 引擎接入 → 调度和缓存分配 → Executor/Worker/ModelRunner → 模型前向 → logits/采样 → 引擎状态更新 → 输出处理/流式响应。同一模型图、系统图持续定位；标注交接数据与状态归属。
4. **第一个与后续 token**：普通自回归、无投机等教学前提下，完整 prompt 的 Prefill 结果选出第一个 token；该 token 作为下一轮 Decode 输入，复用过去 KV，生成第二个 token。分块 Prefill 未完成时不一定有输出。token 不等于汉字，也不与网络包一一对应。
5. **多请求**：A/B 同时到达、输入长度不同，C 稍后加入；用时间线展示等待、运行、退出和每步选取的 token。共享模型权重，维护各请求的位置、KV 和序列边界；批量计算不会使不同请求互相注意。前缀共享需要另行声明条件。混合 Prefill/Decode 的具体排法受版本、策略、预算影响，示意不作为调度保证。
6. **归纳架构**：由观察解释 Scheduler、KV Cache Manager、Executor、Worker、ModelRunner 为什么存在，以及 Ascend 平台、后端、算子与通信适配。及时介绍正式名称，不再用“前半 vLLM、后半 Ascend”替代真实职责。
7. **双机扩展**：在相同请求/批次流上增加 rank、TP/PP/EP、HCCL、机器边界。并发请求、模型并行、多个服务副本是不同维度。

当前状态：贯穿模型方向已收敛到 GLM-5.3-Flash，不需要用户重新选型。固定双机配置与版本、图形结构和源码映射属于实施前事实核查，由执行者提出有依据的方案；目录与图组件详细方案尚未完成。

待用户决定的实施节奏：建议先完成“模型介绍与现有 2D 母版接入、单请求完整闭环、多个请求并发、框架架构总览”四个代表性部分，连同目录草案一起审阅，确认讲解深度和画风后推广到全库。此为建议，尚未获实施指令；用户此前“先不改”的要求仍有效。其余已识别的事实修正与验证工作无需拆成逐项用户选择。
