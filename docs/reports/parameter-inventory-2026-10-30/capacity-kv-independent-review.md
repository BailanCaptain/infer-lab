## 九单元事实核对

- **总长度：** None 从模型推导，和 -1/auto 的后续容量搜索不同；CLI 单位、Python 整数、越界保护及无长度信息时 -1 的失败分支写清。133120 是教程显式值。auto-fit 不是模型压测，也未被推荐为本部署实测配方。
- **三种容量入口：** 三版比例定义默认均为 0.92，范围 (0, 1]；字节数和块数覆盖均默认 None。GLM 教程 0.85、字节预算每卡口径、启动空闲检查仍按比例、覆盖优先级、0 和 None 的建议日志差异均有实际消费者依据。完整 CLI 为 `--kv-cache-memory-bytes`。
- **块长：** CacheConfig 初始缺省补 16，GLM 根据状态推导为 640；641 向上取整为 768。Mamba 块长由 GLM 补丁最终覆盖，不能把显式输入当作有效值；前缀 align 取逻辑块，否则取配置阶段的模型长度。
- **缓存类型：** 字段枚举和硬件支持分开。GLM 主缓存硬编码 BF16，不代表该输入完全没有影响：更早的配置补丁仍用缓存精度计算逻辑块。权重量化 W8A8 没有被混同为 KV 量化。
- **Mamba 模式：** none 仍保留当前请求状态；all 与 align 的保存边界有同一组示意位置说明。基线/0.26 开前缀时按模型能力选 all/align；main 缺省改为 align。仅 AscendStoreConnector、无前缀缓存时可为 align + 133120，正文没有误写成固定 640。
- **混合管理：** 默认是 None/自动决定；disable=True 和 no-disable=False 的双重否定写清。GLM 布局要求启用，自动关闭不是可用回退。通用等页模型与 GLM 两档布局没有合并。
- **版本边界：** main 的容量准入和 auto-fit 先扣一个保留 null block；前两版没有该处扣减。参数定义一致没有被等同为分配结果一致。

## 教学与保留核对

前两屏可以复述：入口把文字与参数整理成引擎请求、CPU 有成本；显存预算先留运行开销，再把剩余空间切块；缓存规格定义各层每页的成本，同组共用编号，而物理共享槽位要求匹配页大小。缓存规格的补齐与短请求尾部空白是实际代价。

三个主体页都沿用已有机制、例子和图，参数参考在源码区补充。API 的两组输出预算算式、HTTP 拒绝时机、GLM R1 前提保留；预算页的四项记账、双次试跑、遗漏的运行占用、650 M、3855/3908 口径、实机日志待核保留；规格页两档页、五组、五种 block_size、4 的回写、15 个块号、逻辑/kernel 换算和待核保留。没有复制部署页预算推导。移除的旧参数条目全部在新参考表及后文找到去向；唯一核心改写是上述有源码反证的分组定义。
