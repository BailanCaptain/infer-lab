## 五单元事实核对

- **容器与入口：** CLI JSON 对象、-cc 和点号简写，与 Python LLM 的整数 0–3 兼容入口分开。EngineArgs 字典构造单独说明。同一尺寸字段同时来自独立选项与配置对象，即使同值也互斥。未把编译 mode 的数字当作图模式。
- **模式与默认：** 五种模式及 decode/mixed 的映射正确；字段 None 与 O0/O1/O2/O3 填默认的阶段分开；显式配置仍受平台与后端兼容检查。主 eager 先置编译与图为 NONE，不能被显式 FULL_DECODE_ONLY 再打开。
- **尺寸与上限：** 自动初始上限、逐档生成、预算封顶、显式表去重/过滤/排序、最终最大档回写及两字段一致性条件正确。512 是自动路径的截断，不是显式尺寸硬上限。只给上限不保证存在等于上限的自动档；interactivity 小尺寸逐档保留。显式表按 token 预算过滤，不按初算上限过滤。
- **对齐与平台：** MTP 的向上取整保留上限检查，不自动求最小公倍数。Ascend 两尺寸字段都缺省时先注入不含上游 ×2 的最大值。main 上游 Blackwell 1024、统一 decode 补档与动态宽度分层，不可直接套到已经提前注入最大值的 Ascend 路径。rc/main 非 V2 Runner 才做该 MTP 后处理，main Ascend 的 TP 对齐扩展条件均已区分。
- **主模型与草稿：** 主 eager 默认 False，True 关闭两层并清空尺寸；草稿 speculative_config.enforce_eager 与 GLM 系列保护仅针对草稿。四版保护存在不等于四版均支持本站模型。没有把关闭 npugraph_ex 说成关闭全部融合，也没有把配置允许图当作每轮必回放。

独立运行 `python tools/wiki-runtime/main-graph-20261031/independent-checks.py`，**95 条断言通过**，结果见同目录 `independent-checks.json`。脚本提取固定源码的真实函数体与枚举，移除注解和装饰器，以轻量配置上下文执行，没有改写控制流。覆盖五模式解析、默认和显式尺寸、预算过滤、两个尺寸冲突、空表/零上限、二次重算拒绝、主 eager、交互细档、MTP 与 SP 的组合、main 平台上限和补档、四版 Ascend 注入。SP 筛选上下文使用可整除 fixture；CLI Pydantic 入口为源码核对，环境没有 pydantic，未声称执行完整 TypeAdapter 或 vLLM 启动。以上都不是 NPU 推理证据。

## 教学、保留与密度
