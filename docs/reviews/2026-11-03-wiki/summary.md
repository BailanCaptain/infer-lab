## 为什么需要两轮

PP 启动参数、Engram 与机器修订历史只是入口问题。全站阅读进一步发现：核心概念和图标签不一致、单个模型的条件被写成通则、静态容量被当作实际流量、旧版本断言覆盖新版行为，以及生成工具按同名字符串推断参数身份。只补用户指出的段落，会保留这些根因。

第一轮方案见 [2026-11-03-wiki-remediation.md](../../plans/2026-11-03-wiki-remediation.md)，第二轮方案见 [2026-11-03-wiki-group-remediation.md](../../plans/2026-11-03-wiki-group-remediation.md)。原始清单是 [inventory.json](inventory.json)，最终逐页阅读与哈希记录是 [coverage.json](coverage.json)。

## 已实施的改变

1. **学习页面只保留当前解释与必要版本条件。** 62 页机器历史尾注已移出正式正文；发布仍校验旧原文、分类和新来源，历史证据保留在维护决策中。新的候选正文不能重新带回该尾注。
2. **扫描结果与正式教学分开。** 5 个只有静态定义的参数骨架移回草稿。后续扫描新字段也进入草稿，补齐用途、配置入口、运行行为和支持边界后才发布；既有人工解释在确定性刷新中保留。
3. **补齐部署链条。** PP 与多节点启动、节点 rank、headless、执行后端分别解释；卡数、DP 执行组与完整专家副本分开。DeepSeek 专页说明 Engram 主机驻留、本地 DP 共享、容器 IPC 和 P/D 资源口径。CPU 绑核、CP、编码器缓存、Runtime Guard 等关联入口同步补充版本与组合条件。
4. **修正跨页概念与预算。** TP 不保证所有模块都分片；prefill 可以分块；源 token 补位不等于专家卡没有工作；mHC 双随机约束不保留所有信息方向，有限迭代与稳定项得到近似归一。KDA 页容量、投机状态、实际传输及每步访存分别记账；HCCL 配置之和不当作显存实占。
5. **补全操作与新版边界。** Xlite、Super Kernel、LoRA、profiling、MSProbe、RL 权重更新与 Trace Replay 增加前提、入口与验证方法。KV Pool 格式迁移与命名空间、RFork 租约/续期/端口/释放、rc2 STAIR 与 PCP owner 单列，不覆盖旧 GLM 算例。
6. **修复会再次生成错误的工具。** 扫描器识别旧构造路径中的嵌套 weight_prefetch_config；prefetch_ratio 的身份和自动表一致。类字段谱系按文件、类、字段核对，size 不再混入全库同名历史。无自动定义的人工参数页显式跳过；定义损坏仍阻止整批发布。对应回归经历失败复现、修复及独立代码复核。
