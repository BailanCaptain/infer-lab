## 问题

### M1 · P2 · 图表把激活峰值增量简写成了分配总量最高点

- 位置：`wiki/concepts/kv-cache-memory-profiling.md:215` 的“两次合起来的最高点”、`:233` 表格的“两次试跑中 PyTorch 分配的最高点”，以及 `wiki/diagrams/kv-cache-memory-profiling.yaml:58` 的“激活峰值：试跑最大批量时的最高点”。
- 影响：分配总量最高点包含试跑前已经常驻的权重等分配。读者若按图或表直接从预算减这个值，再减权重，就会重复扣减。正文第150行已经正确说明需要减去试跑前占用，图表摘要没有同步，形成同页冲突。
- 证据：独立读取 `vllm-ascend@db701c1f:vllm_ascend/worker/worker.py#L563-L574`，实际为 `profile_torch_peak - before_profile.torch_peak`，再与权重、非torch增量相加。`vllm@0fc695fc:vllm/utils/mem_utils.py#L191-L268` 在区间入口重置峰值、拍试跑前快照；它的2GiB权重、4GiB分配峰值示例只计2GiB激活。Ascend v0.26 `2ed6cbba` L548–559、main `baa023ad` L589–600、rc2 `7d825229` L597–608也保持此减法。
- 修法：表格改为“两次试跑的分配最高点减去试跑前占用”；首图标签可缩为“激活峰值：试跑最高点 − 试跑前占用”。第215行改成“两次合起来取最高点，再减去试跑前占用”，保持同一口径。无需修改预算图比例或新增算例。
