## 对本站结论的影响

本轮没有发现要求修改本站的新增 P1/P2。查看了与新发现相关的本站局部表述：`low-precision-formats.md` 的字段位宽、[1,2) 分辨率和非规格化数边界，以及 `attention-backend-family.md` 对精确注意力、舍入差异和 Hopper/Ascend 的区分。此处是定向核查，不声称重新独审这几页全部引文或共享 3D。

补读中需要保留的事实边界：

- BF16、FP8、HiF8 表中的训练/PTQ 结果依赖具体模型、数据与量化方法。HiF8 的 OPT-66B 直接 cast 困惑度恶化明显，PTS/SmoothQuant 结果不同，不支持“直接转低精度普遍无损”。
- V4.1 的 reasoning effort 标量不是 vLLM 的固定思考 token 预算。多张双轴图显示输出长度随 effort 更稳定增长，但准确率会波动，不能说越长必然越准。
- FA 的 dense、稀疏、近似算法，以及前向、反向、合计和不同 masking/dropout 条件不能混成单一速度结论。精确 dense FA 仍有二次计算量；减少的是中间存储与 HBM 传输。
- FA3 的 H100 图有短序列落后于 Triton/cuDNN 的例子，FP8 也不是每种 shape 都领先；它们不能当成 Ascend 内核或在线服务吞吐实测。

发现三处**固定 HTML 来源自身的内部标注疑点**，未据此改本站：

1. HiF8 Table 5 的 ViT-Base-Patch16 行为 79.95、79.18、差值 +0.13，三者不相符。本站 Markdown 搜索 `79.95|79.18` 无命中。本轮只确认固定 HTML 的不一致，未裁定 PDF 或作者最终应改哪个值。
2. FA Table 2 图注称对 Hugging Face 最多 3 倍，而 small 行列出 3.5 倍。应引用具体行及条件，不能机械抄为统一上限。
3. FA3 Algorithm 3 第一行将 `rowsum(dO⊙O)` 标作 `R^d`，与 N 行输入及后续按行分块不一致；按操作维度推导应有 N 项。这是源内维度标注疑点，不作为某个实现消费者的证明。
