## 学习者复述与事实判断

首两屏可复述为：前向为每个候选编号给分；贪心选择最高分，随机路径经过温度、概率和截断后抽取；抽到的编号成为下一轮输入。随机选择保留多样性，同时增加分数处理和随机状态的代价。第一屏没有被维护记录和新接口细节替换。

新增教学可复述为：自定义处理器在采样前改一批请求的分数，每条请求是否启用及具体规则可以不同。六词例子只保留编号 1，将贪心结果从“猫”改为“你”，所以不能声明该规则保持最高分。批次退出、填空和重排会改变行号，处理器须同步自己的请求状态；`[A,B,C,D] → [B,E,D]` 的替换、单向移动、交换过程与官方设计一致。没有成员变化不等于没有新增历史。

两组调用位置已分别核实：可能改变最高分的组在允许编号/禁词之后、罚分及贪心之前；保持最高分的组在温度之后、top-k/top-p 之前。全贪心批次跳过后一组；混合批次贪心行使用此前保存的选择，不能用一条请求贪心就跳过整批操作。

四版表的主要结论均有实际消费者支撑：

- V1 非空显式自定义列表与 speculative 同开时在构造阶段拒绝，包含 GLM 原配方的 MTP；适配器不会解除此限制。
- 只有 entry point 插件、显式列表为空时，speculative worker 构造提前返回，仅装最少长度处理器；请求参数校验仍有独立加载/回调路径，回调出现不能证明采样执行了插件。
- A2/A3 选择 V2 时保留显式列表或已装插件的拒绝；rc2/main 的其他硬件跳过校验分支不被外推为支持。
- HTTP `vllm_xargs`、SDK `extra_body` 包装、离线 `extra_args` 分开说明；实际规则由已安装处理器约定，业务语义需自行校验。旧 Completion 参数值类型与后续版本不同，当前表只陈述一致的传递路径，未承诺旧版也接收列表。
