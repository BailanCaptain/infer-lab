## Scheduler 必须保留的解释

- Scheduler 位于 CPU 上的 EngineCore；每步决定请求、位置数和块号，实际算子与图模式由 worker 决定。位置进度统一 prefill/decode，但执行层仍可能分路。
- 普通示意预算 20：A/B 各 1，C 取得 18、余 9，D 等待；KV 格子表达借用关系，不等于一 token 一块。
- 先 running、后 waiting；running 也包括部分 prefill。数量由缺口、单条阈值、预算与长度限制共同决定；异步占位和候选影响缺口。
- waiting 准入还受暂停、抢占、running 容量及完整输入容量约束；完整输入容量检查与实际分配、未知输出预留分开。
- 默认 fcfs 缺块抢占队尾，priority 按优先级/到达时间挑选；可能撤销本轮已经安排的请求，恢复预算。抢到自身停止 running；本轮抢占后不再接 waiting。
- GLM 每 DP 8192/32，R1 首步 4，lookahead 3，总 7 位置与 15 块的出处；decode 通常每条 4，固定部署 prefix caching 关闭。
- 纯 decode 32×4=128，约 1.6% 预算；新请求准入时最多 31 条已有请求、门槛 8068，场景 M 的 8144/6048 与 20,000 prompt 三步分块回链。
- 8192 与逻辑块 640 不整除；KDA none 模式不走 align 补丁。真实 kernel 对齐与 async 日志缺口继续保留，不能因改写消失。
- GLM BalanceScheduler 关闭时回落上游；异步导入顺序是源码推断，实际类/启动日志仍待验证。三种镜像变体及不适用 PD 的限制保留并明确版本。
- 参数的输入默认、配置兜底、硬件/入口默认、throughput 翻倍、模型长度封顶、显式值不覆盖；普通 NPU serve 2048/256 的前提与 LLM 类差异。
- partial-prefill 两个字段不能在标准入口设非 1；阈值负值/上界的三版差异；关闭分块与正阈值仍可能截段；显式自定义类不会自动变异步。
- 所有启动错误/警告、抢占计数、成本与反例；现有三版结论与 rc2 connector 延迟释放、watermark 条件应扩全，不删成概括句。

## 并发页必须保留的解释

- continuous batching 的逐步加入、退出、复用；共享权重但请求历史与结果独立。七站对照表及 R1 回链。
- 场景 M：DP0 十二条 decode + 新 6000 prompt，DP1 七条 decode，已有历史约 20,000；M′ 的 DP1 空闲。两台合成完整专家集合，不称每台完整模型。
- 原部署 waiting×4+running 路由、单 API 本地计数 +1、协调统计滞后、显式头指定、派定后不迁移；rc2 新分数须单独讲。
- 三步 48/6048/52 对 28/28/28；新 N 在第一步调度后到达；32 条与 8192 位置是不同限制；running 数不等于本步调度数。
- 分块门槛 8144/8068、满 32 时不能准入；20,000 提示词为 8144+8144+3712，未完成 chunk 的采样丢弃，第四步 52。
- 拼接 input_ids/positions/query_start_loc 的 13 请求示例，14 个边界数、6048 行；每请求历史范围、KDA 槽位与 MLA 块表不串。
- 6048×4×4096 BF16=189 MiB 残差、47.25 MiB embedding 载荷、32 KiB R1 及 1512 倍；这是张量量，不当成物理链路流量。
- 3855 块的预算假设，5 缓存组、full 640、KDA 12 块、尾状态3–4块与 prefill 临时 n/4；6000 prompt 的1523块、decode25块；335–367剩块、约67000位置、120–121释放块、9步重算与2167准入检查。
- 七档图尺寸4/8/16/32/64/96/128；28→32、36→64等填充比例；本地补图和跨DP对齐分别解释，prefill进度不满足时即使形状相同也不回放decode图。
- 场景M的64/6048/64主干宽度；草拟48/6048/52且三遍；allow_dp_padding分支和M′空批次不同，不泛化成全部 eager 路径都同宽。
- A2 MC2/AllGather 的128门槛，80 prompt仍MC2、81则越界；A3另有路径。AllGather配对组与执行DP组区分。
- AllGather逐操作载荷148.4MiB/层、6.09GiB/卡/步、4.15GiB跨DP操作口径；MC2逻辑上界1.31MiB/层、55.1MiB主干、31.5MiB EP范围；不当实测、不直接除出耗时倍数。
- 12,096×8专家配对、每专家336/每卡6048理想均分；真实路由与填充行、最慢卡等待和EPLB默认关的边界。
- 空闲DP仍为对端计算真实专家，主干dummy与草拟dummy；每32步全局检查、最后请求结束后最多31步陪跑。层内实际简化和性能仍待核。
- 49行logits的48+1来源、各请求独立验证与停止、块复用；prefill MC2开关4096边界与DP元数据CPU/NPU组开关；异常与待核保留。
