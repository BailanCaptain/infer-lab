## 当前来源判断的关键边界

下列为逐项账的摘要，不替代 72 条人工判断。

| 页面 | 本轮核实的主张 | 不能推广的范围 |
| --- | --- | --- |
| CPU offload | CPU-only 的私有可锁页张量与 Tiering 的共享 mmap 分开；容量按执行组、页字节、段倍数与副本数计算；只有共享区域门和纯 MLA 的精确类型、并行、单节点条件同时成立，才采用单份布局 | 不能把 DP 服务总数再机械乘进执行组预算；不能因新版兼容多组字节视图，就声称 GLM 已完成设备恢复验证 |
| CPU offload | 保存计划、前向计算写好、所有参与者报告传输完成是不同阶段；复用待保存的源页会 flush；阈值、已有键、容量和可达窗口会过滤保存 | “到边界”不保证实际落入主机池；单 worker 完成不保证整个执行组就绪；事件字节/耗时仅表示传输段，不能代替端到端等待 |
| CPU offload | rc2/main 部分尾状态有单物理块、统一逻辑长度、细哈希、align 递推组、无 EAGLE、DCP=1 等门，加载需各组在同边界 ready，保存需实际边界状态交接 | 普通完整段算例不代表任意半块都能恢复；GLM 释放的约 7.5 GiB 是池容量量级，不能当真实搬运 payload |
| Prefix caching | 输入身份包含前缀链和额外键；一个 hash 可对应多个物理块；四版本默认 sha256、四算法入口、cache salt 作用有据 | hash 不是数学上的无碰撞证明，salt 不是认证/显存配额；CBOR 规范序列化不让不同模型兼容；共享图不代表系统随时合并所有重复块 |
| Prefix caching | 旧版/v26 的 none 依据能力属性转 all/align，main 的 none 转 align；匹配单元与实际状态检查点不同；rc2/main 排除私有 tail 并回上游解析 | GLM 的 640 推导须保留固定配置、未放大块长、无 CP 等条件；细 hash 不保证每个细边界都存有可恢复状态 |
| Prefix caching | 启用且不延迟时，分配阶段就会登记本步确定位置，随后才前向写状态；重复物理块、分组共同恢复边界及末 token 规则均保留 | 登记不等于计算就绪，普通共享图不能取代混合模型各组状态条件 |
| 块分配 | Ascend 需求检查的额外计数与实际借块分开；running 请求默认空 new_computed 列表会满足某些额外计数条件，但外部实际分配仍检查 external>0 | 变量名或需求检查多报 1，不能直接推成实际每组借 1；已有 4 块的非 align 分支不需要每步再借 4 |
| 块分配 | 调度先增加 computed，投机拒绝再回退，异步 placeholder 另记；rc2 zeroing 门、v26/rc2/main 的 full/Mamba 部分尾状态条件实际核对 | 静态完整步数字不代表所有截短、封顶、异步步形状；rc2 retention=0 的临时检查点限制保留，不能推广为所有中间边界公开共享 |
