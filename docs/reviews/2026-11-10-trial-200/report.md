# 收尾后的 200 项引文核验与额度记录

本批已完成。账户周额度显示值从 **4% 到 5%**，增加 **1 个百分点**；开始与结束属于同一个 10,080 分钟窗口，没有刷新。这个读数属于整个账户、按整数显示，也可能有统计延迟，所以只能说本批期间观察到约 1 个百分点的增加，不能把它当成精确、独占的任务计费。

其中 194 项为固定 Git 提交的源码或官方设计片段，2 项为 URL 来源，4 项为历史 raw 摘录归档。源码按主张、分支和版本逐项比对；相同摘录复用已读内容，但保留各页面不同的主张判断。URL 来源的 GLM rc2 教程片段与固定源码重复；v0.23 架构总览的正文已读，未据此声称审过官方插图，也未用其中较旧的概述替代精确 V1 调用路径。

4 个 raw 共含 136 段固定源码摘录，逐段与对应 Git 内容比较一致（仅忽略外侧空行），归类为重复归档。它们不算新读的 4 篇官方资料，也没有声称本轮重新全文语义阅读。完整性结果见 [archive-integrity.json](archive-integrity.json)。

| 判定 | 项数 | 含义 |
|---|---:|---|
| supported | 168 | 在所写版本与适用范围内支持对应主张 |

## 修订结果

修改了 6 个页面、5 张图的 YAML 和派生 SVG，共 16 个产品文件。保留原有示意请求、GLM 部署数值、版本比较和设备实测缺口。主要修正：

- 草稿模型也处于加载显存统计区间；结果整理、草拟、接受数更新的顺序按固定 Ascend 实现说明。
- 零 token 的出口保留 DP/KV 协作条件；输入内容每步更新与输入缓冲跨步复用明确区分。
- 缓存配置按 Worker 分发，不能把同构 TP 示例推广为任意 PP 各卡配置恒同；补编译端点与剔除图尺寸的门槛分别说明。
- 异步候选占位与实际候选编号分开；V2 异步并发批数 PP+1 与执行器默认分支统一到现有专页。
- 同步路径准备结构化输出表可与当前前向重叠；下一圈调度等待本轮结果是另一件事。各次 RPC 均有响应，最终 token 结果只收一份。
- 补齐 rc2 清零条件、main attention 后处理筛选的实际依据；修复版本表断行，并同步图注的 PCP/PP/KV connector 条件。

每页完整本批 diff 保存在本目录 `<page-id>.diff`；[changes.json](changes.json) 是首轮 50 处替换的记录，后续独审修订以最终 diff 为准。[file-checkpoint.json](file-checkpoint.json) 保存 16 个文件的最终哈希；六页另有开工前哈希。

新独立审查发现 2 项 P1、2 项 P2、1 项 P3，均经修订后实际复读关闭。该独审核对修改、页面与图，没有冒充另一个审查者重新逐条全读 200 项。完整依据、信息保留对照及关闭记录见 [independent-review.md](independent-review.md)。

## 怎样使用这次额度数字

这是一组连续调用链的样本，存在重复源码和共享上下文。约 1 个百分点可以作为这批“核查并修到验收”的观察值，不能直接乘剩余项数得到全站精确预算。其他分组的资料跨度、问题密度和设备验证需求不同，账户并发使用也会影响读数。

父会话 token 事件增量另有记录：输入 11,151,139，其中缓存输入 10,818,944；输出 43,463（包含 8,144 reasoning output）。重复上下文会被反复计入输入；这不是 1,119 万个新读文字，也不是可直接换算成订阅额度的计费单。该父会话计数不含独审子任务独立 token，账户额度快照则是共享读数。

本批不等于全站官方资料和全部引文核验完成，也没有 NPU 实机验收。待用户决定事项：无；剩余全站工作未自动扩大执行。
