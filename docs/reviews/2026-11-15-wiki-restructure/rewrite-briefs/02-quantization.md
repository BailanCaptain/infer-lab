## 三、循序渐进的推荐讲解主线（围绕读者理解难点重构，禁止套僵化模板）

本节给出按认知阶梯理顺后的叙事逻辑，目的是解开第二节指出的五处正文纠缠，并自然保住全部 7 个跨页入链 `#anchor`，**不是**要求按机械段落字数填空：

1. **第一阶：为什么要压成整数，以及什么叫量化（合并精简开篇，直入痛点与直觉）**
   - **读者卡点**：为什么非要把好好的 BF16 改成有损整数？压完以后整条推理链路全变成 8 位了吗？
   - **顺畅讲法**：先用最痛的两笔工程账开场——1,000 亿参数在 BF16（2 B/数）下仅权重就要约 200 GB，直接挤占同池的 KV cache 并发预算；而小批量逐词解码每吐一词都要把参与计算的权重从显存搬进计算单元，瓶颈卡在搬运字节数而非算力（顺带用一句自然语言点明权重常驻部署与权重卸载的区别、MoE 每词只读被选中的少数专家，删去首屏“投机解码”等旁支干扰）。紧接直接亮出 `[0.26, 1.04, -0.18, 13]` 四数示意与 `quantization` 图：用 `s = 0.1` 把 2 B 浮点映成 1 B INT8（`[-128, 127]`），一眼看懂普通舍入误差（`0.26 → 3 → 0.3`）与越界截断误差（`13 → 127 → 12.7`），顺势划清 `W8A8` 边界——只代表参与矩阵乘的权重和激活压成 8 位整数，乘加累加器、还原系数和层间传递向量不必是 8 位；把相邻概念页路标集中收在节末。

2. **第二阶：`## 一个数怎样压下去、再还原回来`（先立主线对称公式，讲清动机再引非对称零点）**
   - **读者卡点**：比例尺 $s$ 怎么定？离群值为何致命？既然下文动态 W8A8 不用零点，为什么还要学 $z$？
   - **顺畅讲法**：先摆主线真正要用的**对称量化** KaTeX 公式 $q = \text{clamp}(\text{round}(x / s), -128, 127)$ 与 $\hat{x} = s \times q$，说明未越界时误差不超过半格 $s/2$，以及动态对称取法 $s = \max(|x|)/127$（全零向量单独处理避免除零）。立刻回扣上一节的离群值 `13`：为了装下它，$s$ 被迫撑大到 $13 / 127 \approx 0.102$，其余落在 `[-1, 1]` 的小数只分到约二十个格子——**直接为下一节“拆成按列/按行细粒度各自取 $s$”埋下因果伏笔**。随后**先亮明动机再进非对称公式**：“本部署动态 W8A8 矩阵乘全程走对称无零点路径（离线权重虽存 `weight_offset` 但矩阵乘不读取）；引入零点 $z$ 是为了解决激活全为非负数时半边负数格子闲置的问题，也是后文静态量化 `input_offset` 的数学基础”，再给出 $q = \text{clamp}(\text{round}(x / s) + z, -128, 127)$、$\hat{x} = s \times (q - z)$ 与 `[0, 12.7]`、`z = -128` 算例。

3. **第三阶：`## 放进一次矩阵乘：W8A8 的四步`（先解开“为何按列×按行能提公因式”，再落微观三件套验证）**
   - **读者卡点**：为什么偏偏是“权重每列（输出通道）一个 $s_w$、激活每行（token）一个 $s_x$”？为什么累加器绝对不能用 INT8？
   - **顺畅讲法**：先配 `quantization-intuition` 图讲清代数根因——矩阵乘 $Y_{i,j} = \sum_k X_{i,k} W_{k,j}$ 沿内维 $k$ 求和；只有当激活比例尺 $s_{x,i}$ 只跟行号 $i$（token）走、权重比例尺 $s_{w,j}$ 只跟列号 $j$（输出通道）走、两者都不随内维 $k$ 变化时，才能把 $s_{x,i} s_{w,j}$ 提到求和号外面，写成 $\hat{y} = s_x \times s_w \times \sum_i q_{x,i} q_{w,i}$！这就让硬件在内维循环里连续做纯粹的 INT8 乘加并用宽整数（如 INT32）累加，最后一步乘回 $s_x \times s_w$ 恢复 BF16（或交给融合算子处理）。讲透这层结构后，再用清晰的“宏观→微观单元素核验”过渡串起三件套，不再同义反复：① `quantization-dot` 静态对齐两路输入、逐项乘积与求和；② 三元素 `calc` 逐数验算 `10438` 为何远超 `127` 以及 `0.0012` 误差从哪来；③ 冻结 3D `inference-mechanism:5` 动态播放离线权重预压 vs 运行时激活现算的时机差与 `12 B → 6 B` 搬运减半。

4. **第四阶：`## 省下什么，付出什么` 与 `## 动态量化和静态量化，差在什么时候算系数`（算准收益代价，分清两类运行时契约）**
   - **顺畅讲法**：用 `[4096, 4096]` 线性层算明权重连同每输出通道各 2 B 的 `weight_scale`/`weight_offset`（共 `16 KiB`）占原 BF16（`32 MiB`）的 **`50.048828125% ≈ 50.05%`**（省下 `16,368 KiB ≈ 15.98 MiB`），删去与正文重复的 `L254-258` 两行小表，保留三笔真实代价（多层误差累积需重评、加载转置分块与运行时量化开销、省下显存须重跑启动期显存探测才可转成 KV 预算且不等同于吞吐翻倍）。紧接对比 `w8a8_dynamic.py`（每次前向按 token 现算对称 `scale`，普通未量化浮点输入如 BF16 下 `output_dtype=x.dtype` 保持原精度；但离线压权重做平滑/裁剪时仍可能用校准集）与 `w8a8_static.py`（加载期注册整张量 `input_scale`、`input_offset` 及 `quant_bias`、`deq_scale`，算子输出 `params_dtype`，当前固定版本仅注册 `linear` 未注册 `moe`）。

5. **第五阶：`## 放到 GLM 双机：两个 8 位分别从哪来`（彻底解开四线穿插：先两道门总表与新图，再走单卡 Linear 与 EP/MC2 专家）**
   - **顺畅讲法**：
     1. **先把 `### 哪些矩阵是 8 位，哪些保持 BF16` 提上来打头阵**：配重画后的两道门分流图 `quantization-flow` 与分层依据表，一次性讲透 GLM 决定层精度的**两道关卡**——**第一道门（模型代码建层）**：`glm5_next.py` 建 KDA 线性注意力 9 个投影、稀疏 MLA 的 indexer K 投影与打分投影、词嵌入时不传 `quant_config`（保持 BF16），MoE 路由门控 `GateLinear` 固定用 FP32 算路由分数，它们根本不会去查描述文件；**第二道门（`quant_model_description.json` 查表）**：收到 `quant_config` 的 Linear / MoE 层按层名前缀查表，标 `FLOAT` 走未量化方法，标 `W8A8_DYNAMIC` 交 `(quant_type, layer_type)` 注册表派发动态量化方法。当场揭晓两份实测模型清单的分歧：两者都把共享专家与路由专家标成 `W8A8_DYNAMIC`、把 `lm_head` 与 MTP 标成 `FLOAT`，唯一分歧在稀疏 MLA 四个主投影（`9e55cbc8` 为 `FLOAT`，`3121f187` 为 `W8A8_DYNAMIC`）；同时交代缺条目回退差异（`Embedding` 缺键回退 `FLOAT`，`Linear`/`MoE` 缺键或分片不一致直接报错）。

### 5.1 概念边界、数学算例与收益代价（须全数保留在正文）

1. **存储与带宽边界**：
   - 1,000 亿参数在 BF16（2 B/数）下仅权重约 `200 GB`，权重与 KV cache 共享同池显存；小批量 decode 每吐一词要搬运参与计算的权重，受限于访存带宽；MoE 每词只激活被选中的少数专家；权重常驻显存的在线服务场景区别于每次从内存/磁盘卸载加载权重的场景。
   - **本页职责与相邻页路标**：本页聚焦“压成整数怎么算、误差哪来、GLM 双机落哪”；低精度位宽家族（FP8/INT4/MXFP8 等）见 `low-precision-formats.md`，离线平滑/裁剪与校准方法（SmoothQuant/AWQ/GPTQ 等）见 `quantization-methods.md`，KV cache C8 见 `kv-cache-quantization.md`，精度评测见 `quantization-evaluation.md`，双机总账见 `glm-5-3-flash-baseline.md`。
2. **量化/反量化公式、误差与粒度伏笔**：
   - `W8A8` 定义：权重 8 位整数 + 激活 8 位整数参与矩阵乘；乘加累加器、还原系数及层间传递隐藏向量不必是 8 位。
   - 四数示意 `[0.26, 1.04, -0.18, 13]`（`s = 0.1` → `[3, 10, -2, 127]` → `[0.3, 1.0, -0.2, 12.7]`）：同时覆盖舍入误差（`0.04`）与越界截断误差（`0.3`）。
   - 对称公式 $q = \text{clamp}(\text{round}(x / s), -128, 127)$、$\hat{x} = s \times q$，未越界最大误差 $s/2$；动态对称取法 $s = \max(|x|)/127$，**全零向量须单独处理防除零**；离群值 `13` 把 $s$ 撑到 $\approx 0.102$ 压缩小数分辨率。
   - 非对称公式 $q = \text{clamp}(\text{round}(x / s) + z, -128, 127)$、$\hat{x} = s \times (q - z)$ 及 `[0, 12.7]`、`s = 0.1`、`z = -128` 算例；明确本部署动态 W8A8 矩阵乘走对称无零点路径（离线权重虽存 `weight_offset` 槽位但 `w8a8_dynamic.py` 矩阵乘不读取）。
3. **矩阵乘四步、冻结三元素点积与 `[4096, 4096]` 账目（注意源码精确适用条件！）**：
   - 权重离线按输出通道（列）存 `s_w`，激活前向按 token（行）现算 `s_x`；因两者均独立于求和内维，可提出求和号写成 $\hat{y} = s_x \times s_w \times \sum_i q_{x,i} q_{w,i}$，内循环纯 INT8 乘加并用宽整数（如 INT32）累加防溢出。
   - 冻结三元素点积数值与 `calc`、`inference-mechanism:5` 严格一致（见第一节 1.1）。
   - **`[4096, 4096]` 体积比精确表述**：BF16 为 `32 MiB`（`33,554,432 B`）；INT8 权重 `16 MiB` 加每输出通道各 2 B 的 `weight_scale` 与 `weight_offset`（`4096 × 4 B = 16 KiB`）共 `16,384 KiB + 16 KiB = 16,400 KiB`，**占原 BF16 体积的 `50.048828125% ≈ 50.05%`，省下 `16,368 KiB ≈ 15.98 MiB`（约 `49.95%`）**——严禁把 `50.05%` 倒写成“省下 50.05%”，也严禁把权重省半写成“端到端推理速度翻倍”！
   - 三笔代价不丢：① 多层量化误差累积，长上下文/代码/数学任务须实测重评；② 权重加载后需转置并整理成 NPU 亲和分块格式，动态量化每次前向多了激活现算开销；③ 省下的权重显存不会自动变 KV cache 预算，取决于启动期可用显存探测重算结果。
4. **动态量化 vs 静态量化精确代码契约（源自 `w8a8_dynamic.py:48-152` 与 `w8a8_static.py:33-141`）**：
   - `AscendW8A8DynamicLinearMethod`：权重加载期就位（含 `weight`、`weight_scale`、`weight_offset` 槽位）；前向若输入还不是 INT8，调用 `torch_npu.npu_dynamic_quant(x)` 现算每行激活 INT8 与动态 `scale`，再调 `torch_npu.npu_quant_matmul(..., output_dtype=x.dtype)`——**必须写明适用前提：在普通未量化浮点输入（如 BF16）下 `output_dtype=x.dtype` 输出保持原浮点类型**（不可脱离输入类型无条件写死“任何路径永远输出 BF16”）；同时点明“运行时动态算激活 `scale`”不代表离线压权重时没用过校准样本。
   - `AscendW8A8LinearMethod`（`W8A8` 静态量化）：加载期注册**整张量（标量形状 `1`）**的 `input_scale` 与 `input_offset`，并存 `quant_bias`（INT32）与 `deq_scale`（BF16 时为 FLOAT32，否则 INT64），前向调 `quant_per_tensor` 后走 `npu_quant_matmul(..., output_dtype=params_dtype)`；固定版本 `v0.18.0rc1` 中 `W8A8` 仅注册了 `linear`，未注册 `moe` 专家分支。

### 5.2 GLM 双机落地、MC2 跨卡链路与默认折叠 `## 对照源码` 清单

1. **GLM 两道门与两份模型清单事实（正文第五阶必留）**：
   - **第一道门（建层未传 `quant_config` / 固定高精度）**：`glm5_next.py` 中线性注意力 KDA 的 9 个投影层、稀疏 MLA 的 indexer K 投影与打分投影、词嵌入层 `VocabParallelEmbedding` 建层未传 `quant_config`（保持 BF16）；MoE 路由门控 `GateLinear` 固定把输入与权重转成 **FP32** 计算路由分数。
   - **第二道门（`quant_model_description.json` 查表与回退边界）**：收到 `quant_config` 的层按前缀查表，标 `FLOAT` 走未量化方法，标 `W8A8_DYNAMIC` 交 `(quant_type, layer_type)` 注册表；**缺条目回退差异不丢**：`Embedding` 缺键回退 `UnquantizedEmbeddingMethod`（`FLOAT`），而 `Linear` 或 `MoE` 缺键、或同一融合层各分片量化标签不一致会直接抛异常报错。
   - **两份实测模型清单唯一差异**：`9e55cbc8` 与 `3121f187` 均将共享专家与路由专家标为 `W8A8_DYNAMIC`，均将 `lm_head` 与 MTP 层标为 `FLOAT`；唯一分歧在**稀疏 MLA 的四个主投影**（`9e55cbc8` 标为 `FLOAT`，`3121f187` 标为 `W8A8_DYNAMIC`）。
   - **单卡专家体量与辅助系数账目**：双机 16 卡（`TP8 / DP2 / EP16`，288 个路由专家按 EP16 分摊）下每卡承载 `18` 个路由专家，单层三维权重张量共 `432 MiB`，42 层共 `17.72 GiB`（占 `3121f187` 单卡语言模型权重子账 `20.58 GiB` 大头）；单层路由专家两块权重的 4 组 2 B 系数与偏移（`576 KiB`）加加载后另存的 FP32 系数副本（`288 KiB`）共 `864 KiB`，合计约占权重体积的 `0.2%`。
2. **A2 双机 MoE / MC2 通信量化闭环（正文 `### 为什么 EP dispatch 搬的是 int8` 必留）**：
   - A2 选 `MC2` 的三项前提（`_select_a2_moe_comm_method`）：设备为 A2，且同时满足**每卡专家数 `<= 24`、`EP >= 16`、本轮 `num_tokens <= mc2_tokens_capacity`**（否则选 `AllGather`；`16` 是 `EP` 下限而非总卡数上限，也不限定仅 decode，双机 `18` 专家/卡与 `EP16` 满足前两项后仍须检查本轮 token 数）。
