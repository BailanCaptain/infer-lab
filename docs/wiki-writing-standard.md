# LLM-wiki 写作标准

本文件是 wiki 写作标准的唯一出处，适用于 `wiki/concepts/` 下的概念页、深入页和主线页。写作、改写、审查前必须先读；与计划、临时任务单、历史审查意见或其他文档冲突时，以本文件为准，用户另有指示除外。后续标准变更只更新此处，任务单链接本文件。

**三级版本基线契约：**
1. **全站默认主基线**：`vllm-ascend@c09d3e20`（`v0.30.0` 正式版）+ 配套 `vllm@ced6857a`；教学标准标尺采用 `Qwen3-8B`（Dense GQA）与 `Qwen3-30B-A3B`（MoE），不把未修复的 `v0.30.0rc2` 或停服模型混入主基线。
2. **显式例外 A（`RFork` 专题 10 篇）**：已完成主基线重锚，统一钉在社区上游 `vllm-project/vllm-ascend` `main`（`8d6180e2`，见 `wiki/seeds/vllm-ascend.yaml`）；历史独立工作版快照与原补丁留档于仓库根 `rfork/`（`rfork/archived-seed.yaml`），不混套 `v0.30.0` 正式版默认行为。

## 写给谁，先讲什么

读者是初学者。每页须回答：这是什么；请求走到主线哪一站会遇到它、为什么需要；在对应基线部署下怎样运行、付出什么代价；如何对照源码。挂靠站点要链接到对应主线页的小节，页末通过 relations 说明下一步和相关站点。

先建立直觉，再沿请求逐步推演每卡形状、通信次数、字节数和显存。标准主基线部署数字（`Qwen3-8B` / `Qwen3-30B-A3B`）或例外 B 绑定算例数字在原理讲清后出现；通用示意图可以简化卡数，数值例子必须明确标为「示意」，公式和机制仍须正确，不得把示意数当成实测。不要反复铺陈部署前提，也不要把维护者的编排理由写进教学正文。

`docs/mainline/` 下三份主线底稿（[部署、入口与调度](mainline/01-deploy-entry-schedule.md)、[逐层前向](mainline/02-forward.md)、[采样与 decode](mainline/03-sample-decode.md)）仅作为**例外 B（第 7 章 4 篇 GLM 案例与 14 篇含 `wiki-scene` 历史绑定算例）的专用事实底稿归档**（钉住 `vllm@0fc695fc + vllm-ascend@db701c1f`）；标准 `v0.30.0` 主基线页面直接以 `vllm-ascend@c09d3e20`、`vllm@ced6857a` 源码、官方文档及 `src/sim/modelspec/` 单真源为准，不从 `docs/mainline/01-03` 搬运 GLM 数字。读者页的 sources 直接指向钉住 commit 的源码、官方文档或论文，不以底稿代替原始证据。

## 基础讲法：反八股自适应与从理解到演算

读者只懂基本 Python、向量和矩阵乘法，未必学过 Transformer、vLLM 或昇腾。用户的反馈表达初学者的困惑，写手应判断怎样讲最顺，**不立任何单篇固定模板（不把旧实验稿变成新八股，也不用新模板替代旧模板）**，不锁死旧稿句式、段落顺序或旧 2D 图，也不把一句反馈机械放大成整页规格。改写时**先评估提炼、后按需重写：不是每页或每张图都盲目推倒重来，原稿中已经写得清楚的好段落、好算例与已经讲清机制的好 2D 图必须明确保留；仅对黑话突袭、交错混乱、主次颠倒或套框堆字讲不清因果的段落与 2D 图，重新组织正文或按场景选用最契合的图形态升级**；同时必须完整保留已核实事实、一手来源、成立条件、既有 3D 场景（`wiki-scene`）及与其绑定的核心算例数字。

写作与改写遵循**四条认知底线与两条硬核保真铁律**：

1. **底线一（主干先行，条件归仓）**：前半程用干净标准路径把核心机制讲透；多版本分叉、特殊模型分支、`assert` 早退统一收束至后半段「适用范围 / 边界与版本差异」或文末 `## 对照源码` 区，`summary` 与首屏免除全量免责括号轰炸。
2. **底线二（Edition-A 因景制宜视觉教学体系：立体拆解剖面引线直标 + 按场景选型的机制矢量图 + 1+3 公式与算账准则）**：以“绝不因精简而讲糊涂、什么场景配什么最契合的图、保留已讲清好图、严禁无脑套用单一方框卡片八股”为原则：
   - **层一 · 复合立体拆解剖面与趣味微缩场景破冰图（`PLATE`：`mode: "native-svg"` 内嵌紧裁透明底 `<image href="./wiki-illustrations/<slug>.webp"/>` + 开放式大字号矢量中文引线直标）**：支持两类高记忆点插画——**① 硬件/系统立体拆解剖面图**（核心全景页、芯片存储层级、跨节点拓扑的空间解剖）；**② 趣味微缩场景破冰图**（针对抽象易迷糊的核心痛点，如分页块表寻址、长短请求混编堵车、投机草稿批改、写时复制分家、离群值撑爆量化尺、热点专家排队、算力屋顶与带宽吸管、图捕获录播等，用温暖克制的编辑插画建立直觉，并用矢量引线将场景角色映射到真实系统组件名）。所有 `.webp` 存放于 `public/wiki-illustrations/`，必须**紧裁掉四周死白并做外缘透明去底**，使主体在 `width <= 900` 画布中占 `550–860px` 直接浮在 `.wiki-diagram` 纸面上；位图内仅保留极简英文短标或纯图形（严禁塞中文小字），在留白区用**高清矢量圆点引线（`●───`）与开放式中文编号直标（标题 `15px` 粗体、辅助短句 `13–14px`、序号 `12–12.5px`）**建立映射并绑定伴生 `.yaml` 的源码 `pins`；**铁律：立体剖面与趣味场景图做“空间/直觉破冰加法”，与精确数据流/矩阵/比例纯 2D SVG 互补配合，严禁覆盖存量好图，严禁画外层大底板框或仪表盘黑条**；
   - **层二 · 因景制宜的分节机制矢量图（`FIG`：`mode: "native-svg"` 或 `layout: "figure"`）**：根据机制本质选择最匹配的图形态——**① 时序、并发、进程生命周期与流水线气泡用多泳道时间轴或地址空间分叉树；② 矩阵乘法、张量切分、块表寻址与量化缩放用带真实行列格线的比例张量图；③ 显存账单、耗时退化、通信税与容量水位用严格按数值比例绘制的瀑布条/堆叠尺/Roofline 坐标曲线；④ 硬件互联与端口归属用芯片/板卡/链路拓扑图；⑤ 路由回退与故障分诊用开放式状态跃迁或漏斗分流图**。**先评估再动手：存量图若已把结构或流程讲明白则保留，绝不为改而改；重画或新增时严禁把时序、比例或矩阵偷懒画成“外层彩色大框套三张同尺寸白底文字卡”的新八股**。画布宽度推荐 `860–900px`（硬上限 `width <= 900`），严禁画整幅外层底框；**图内字号严格对齐 `DESIGN.md`：分栏标题 `16px`、主标签 `14–15px`、辅助说明/等宽标识 `≥12.5px`、角标/刻度等次要短标记允许 `12px`（严禁 `< 12px`，由 `pnpm wiki:svg-geometry` 守护）**；**配色严格复用全站 `src/design/tokens.css` 暖纸矿物语义色系**（墨色 `#17211f` / 次级灰 `#66716d` / 暖沉底 `#ece9df` / 暖分隔线 `#d8d8cf`、Token 青 `#087f73` / `#ddf4ef`、权重琥珀 `#c78300` / `#fff4cf`、KV 靛蓝 `#4c65b6` / `#e8edff`、通信梅紫 `#9a4b86` / `#f7e7f2`、错误陶红 `#b54237` / `#fff0e9`，严禁混用高饱和冷调 Tailwind 色）；
   - **流程、架构与系统导览页（写法 1 + 2D 图）**：不编造假小数向量做重复乘加刷屏（如连抄 6 遍或 12 遍点积）；直接用 **2D 数据流/分格图 + 真实张量形状流转 + 极简一行结果对照表**讲清机制，细粒度算术留给对应算子专页；
   - **算子数值与工程算账页（写法 3 + 2D 比例图）**：**全面停用灰底 ```` ```calc ```` 围栏框**（由 `wiki:lint` `stage2-no-calc` 硬门禁守护）；参数量、显存账、压缩比与数值算例统一采用 **「2D 构成/比例对比图 + 清爽 Markdown 表格 + 单行标准 KaTeX 公式（行内 `$...$` 或块级 `$$...$$`）」**，多字母算子/函数名使用 `\text{clamp}`、`\text{round}` 等正体，负号使用标准 ASCII `-`，同一类算式最多示范 1 次，严禁重复刷屏；
   - **严禁用 ASCII 字符树（`├─►` / `└──`）代替正式 2D 图**：凡决策树、模块分流、目录映射与多卡协同（TP/DP/EP/CP），一律画成正式 `wiki-diagram` 2D 矢量图；既有 14 篇 `wiki-scene` 保留已认可整体布局及与其绑定的算例数字，新建或修改教学 3D 遵守 [教学 3D 标准](3d-teaching-standard.md)；
   - **配置参数与排障诊断**：直接给判据表、现象→最小首取证据→区分实验与下一站机制页结构及取证命令。
3. **底线三（单页入口自洽 + 共用数字回链单一出处表）**：每页能独立进入，入门算例在页内 30 秒立住，可用 2–3 句白话交代背景数字；前置概念首次出现须就地用一句话解释，链接放在实际用到概念之处。**凡引用跨页共用推导值，仍须回链下方「单一出处表」，严禁各页私自重推漂移。**
4. **底线四 + 保真铁律（自然语言条件留主干，机器标记与四版本矩阵入文末折叠核验区）**：
   - **保真铁律一**：**教学主干必须在结论就地用自然语言说清示意设定、静态推导前提或未实测边界（严禁在归档机器标记时把适用条件一起抽走后移），对照源码之上零证据角标**——`[C#]/[S#]/[D]/[I]/[A]/[!]` 机器方括号标记统一归入页末 `## 对照源码` 核验区（参数页 `type: param` 可在 `## 事实表` 保留紧凑标记，但严禁在首句用 `**v0.30.0 对照：**` 或 `**v0.30.0rc2 对照：**` 劫持开篇）；
   - **保真铁律二**：**`v0.23.0 (2c59ff10)` / `v0.26.0rc (2ed6cbba)` / `v0.30.0 (c09d3e20)` / `main (8d6180e2)` 四版本核验矩阵**与核心源码锚点**必须保留在同一 `.md` 文末 `## 对照源码` 核验节内**（保证 `wiki:find`、`wiki:mcp`、`retrieve.ts` 完整可读，绝不允许删空 `sources` 或版本差异），由前端阅读器渲染为默认折叠区，并由右栏 `WikiPanel` 离线证据面板支持源码、`raw:` 快照与精确图 `pin` 离线对照。

### 可读性与去法务化五条手术规则（保真不降深）

在不削弱任何已核实事实、成立条件与源码严谨度的前提下，正文句法、算账与双层标尺排布统一执行以下五条手术规则：

1. **设定与结论分句**：去掉条件会算错或误配时，把设定独立写成前一句或表头，紧跟结论句；禁止把变量、多分支、源码类名和例外挤成 `>120` 字法务长句。
2. **首屏只完成一个干净判断**：前两屏只用标准场景（`Qwen3-8B` / `Qwen3-30B-A3B` 或玩具例）走完一次「输入 → 变换 → 输出」；固定镜像分支或罕见入口严禁插入前 5 个正文块。
3. **分支归入「边界与例外」**：改变执行路径的边界（如 `TP > n_kv` 复制、线性状态组、投机槽位预留）集中放进紧随主算例的「边界与例外」，写清「触发条件 → 变化结果 → 核验入口」。
4. **一段一推理，一格一账目**：粗体仅标本节新增结论；公式旁配一行数字代入；同一单元格只放同口径单一账目。
5. **同页双层标尺边界**：含冻结 `wiki-scene` 的基础/机制页允许上半场用 `Qwen3` 讲清 `v0.30.0` 主干，下半场以明确标题转入绑定该冻结 3D 的例外 B 算例；各自小节内不跨标尺混算，冻结围栏、锚点与绑定数字原样保留。

图按教学需要配置，**废除脱离题材的强制充数挂图**。张量用一个整体加格线；计算图要能看见数如何变化。静态通信图使用**静态分格**展示「发前各自有什么 → 谁把哪块发给谁 → 发后各自有什么」，样板是 [All-Reduce 分格图](../wiki/diagrams/collective-communication-all-reduce.yaml)。交互 3D 统一遵守 [教学 3D 标准](3d-teaching-standard.md)（保留既有认可布局与绑定算例，新建或修改必须完成实播视觉验收）。

讲不清时先看参考资料的实际图像，学习它如何组织概念与例子，再用本站图语言重画，不照抄。通信原语及 TP/DP/EP 的参考包括 [通信原语](http://www.xzclass.com/?p=3366)、[AMD MoE 指南](https://rocm.blogs.amd.com/software-tools-optimization/vllm-moe-guide/README.html) 与[并行参考](https://zhuanlan.zhihu.com/p/2003423046342554380)；只有文字抓取不算看过图，本地已存截图也可使用。图元不足时新增能力，先核对未提交改动，不改变既有图元行为；改后运行 `pnpm wiki:diagrams --check`。

逐节让初学者用自己的话复述：核心概念错误、前置概念先用后讲、需要演算却没有演示，都按 P1 处理。参考已达标的量化缩放、KDA 二维状态、RMSNorm/LayerNorm 对照、稀疏注意力重归一化与 DP 请求分配例子。深度和事实保留要求见下节「顺序不等于删减」。

## 深入页参考递进骨架：先直觉、后数字

> **顺序不等于删减。** 「先直觉、后数字」只规定讲的顺序。该讲清楚的机制、推导、数字和边界情况，一样都不能少：知识库也是问答的知识底子，页面讲得不全，问答就答不全。瘦身只删重复和水分，不降深度。（用户，09-28）

并行、特性、机制深入页推荐按以下递进脉络组织（具体小节标题、讲解顺序与表达工具随题材自适应，不作机械模板锁死，也不用一套新模板替代旧模板）：

1. **第一屏：解决什么问题、这是什么。** H2 用贴合该页核心矛盾的问题或命题命名；开篇直接从具体痛点或问题切入，定义本页概念并交代解决什么问题，必要的前置词先就地解释。需要建立空间/结构直觉的机制页配一张通用直觉图（只画原理、只标卡数，不标字节、不画具体部署形状；箭头必须让人看出东西如何流动；首图位置按理解需要安排，不搞硬凑前两节挂图）。
2. **第二屏：怎么运作、为什么能接上、代价与条件在哪。** 用属于该机制的具体小算例、提炼伪代码或重绘的 2D 图把机制运作步骤与因果讲透，让读者读完前两屏不仅能用白话复述机制，还能换一组数字自行推导；需要数值时用已标明的示意数，具体部署数字留给后文。讲明哪一步后通信、每层几次、在哪里等待；用一段话或紧凑小表区分相邻概念。
3. **落到标准部署或绑定算例（适用时）。** 标准 `v0.30.0` 主基线页面采用 `Qwen3-8B` / `Qwen3-30B-A3B` 与 `src/sim/modelspec/` 单真源算例；第 7 章 4 篇 GLM 专页按例外 B 维持原 GLM R1 / 场景 M 单标尺走读，含冻结 `wiki-scene` 的基础/机制页按上节「同页双层标尺边界」在各自独立小节内部保持单标尺不混算（冻结 3D 绑定小节内不混塞 Qwen3 数字）。小节 `calc` 数量与表/`calc` 间隔以推演清晰为准（建议每节先给结论、表与 `calc` 间用正文交代因果，不靠拆空洞小标题凑密度）。整批账单独放在后面的 H2，首次使用时交代设定并链接，不混进单 token 走读。
4. **适用范围、特殊层与变体边界。** KDA、稀疏 MLA、词表、共享专家或多版本分叉只讲与一般主干有什么不同及成立条件，细节链接各自页面。
5. **常见误解 → 对照源码。** 教学正文对参数名、变量名、函数名、类名、退出码/状态码按语义正常使用反引号代码样式，普通技术名词保持正体、避免无意义代码底色（**已废除旧版“正文行内代码每千字不超过 13 个”的机械配额**）。源码行号锚点、commit 对照与完整四版本差异矩阵集中在文末默认折叠的 `## 对照源码`。
6. **机器证据角标与待核放页末。** 对照源码之上零证据角标（教学主干用自然语言就地写清条件），所有 `[C#]/[S#]/[D]/[I]/[A]/[!]` 机器角标与「待核：缺什么」归入页末 `## 对照源码`；迁移标记以降低阅读干扰，绝不删除已核实的事实与限制条件。

**TP 直觉图示例：** 按数学上的「输入维 × 输出维」画成对矩阵：先 column parallel（沿输出维按列切），各卡从同一输入算出数值完整的几列，本地完成逐元素激活；再 row parallel（沿输入维按行切），接住本卡这几列，得到形状完整、数值尚未加齐的部分和；最后一次 All-Reduce（各卡按位置相加并取得结果）。图中竖条、横条、长边和维度标注必须一致。紧接图解释反例：非线性激活不能对部分和分别算完再相加，先行切就得在激活前先归约；两次都列切则需在中间 All-Gather 拼回输入。先列后行才省去中间通信，不能只画行切，也不能宣称反过来在数学上完全无法实现。存储转置的区别移到源码区。

**EP 直觉图示例：** 画出源卡与多张持有完整专家的卡，给专家编号，区分选中与未选中的专家；用箭头串起「一个 token → router 选 k 个专家 → dispatch 发到持有卡 → 各卡计算 → combine 回源卡按权重相加」。源卡自己也持有专家；均分示意中每卡格数一致。图只表达分工，k 的含义在图旁解释；实际卡数和选择数在后文部署段交代。routed experts 指整个可供 router 选择的专家集合，不是某个 token 本次选中的子集；shared expert 是所有 token 都经过的共享专家，切分方式按对应部署说明回链。

## 写手常见错误

1. **把每台机器／每个 DP 组说成完整模型副本。** 在 GLM-5.3-Flash 双机部署算例（或一般 MoE EP 部署）中，EP16 把 288 个专家分在 16 卡，每台是 DP 执行组，两台合起来才构成完整模型。
2. **术语先用后解释。** 首次出现就地解释；不要让首屏别名、参数和未解释的图标签压过概念。
3. **两页重推同一个量，结果对不上。** 按单一出处表只保留一份推导，其余给结论和链接。
4. **先算账后讲概念。** 第一张图之前堆 calc、部署数字和形状表，读者仍不知道概念是什么；直觉图也不能画成部署图。动机必须用属于该机制的数字，不能用 EP 专家容量证明 TP 的必要性。
5. **TP 只画按行切，或图文切分方向相反。** 必须讲列切、激活、行切如何成对配合，并解释反过来为何不能省掉激活前的通信；不能靠「非等比例」图注掩盖方向错误。
6. **把 routed experts 定义成「被挑选的专家」。** 它指可供选择的整个集合；本次选中的是子集，另须区分共享专家。核心概念或定义讲错一律 P1，不能因后文用法正确而降为 P2。
7. **为简洁删事实，或把猜测写成事实。** 重排需保留已核实数字、条件、反例、链接和误解条目；纠错要给原始证据。静态推导、源码证据和硬件实测分清，未核项不能因换写手消失。
8. **只有数字没有解释，或反复更换算例。** 形状标明每一维代表什么；场景切换交代设定；表与 calc 之间用正文解释因果，不用一句空泛引语隔开。

- **重写丢信息与旧事实三出口守恒**（09-28 P5 实测：GPT 写的前 7 页里有 4 页丢了旧版的关键结论，都记为 P1）。深改前必须先把旧版的结论、机制、数字、边界情况与已核实源码/排障线索逐条列成清单；写完逐条核对旧事实的三类合法去向（三出口守恒）：
  1. **保留或等价改写（`editorial`）：** 新版正文、表格或折叠核验区中仍保留该事实及版本/硬件限定条件，或以语义等价的自然语言/表格重写；
  2. **跨页迁移（`editorial` 同批承接）：** 挪到拆分子页或单一出处页时，必须满足四项条件：**① 同批候选 `Review.writes` 包含目标承接页写入；② 目标页具备真实承接锚点与实际承接事实正文；③ 目标页通过 `base` 校验；④ 原页留有指向该锚点的链接，并经独立语义复核**（绝不能只凭原页填一个链接就算旧事实已保留）；
  3. **带证据显式纠错（复用 `supersede.claims`）：** 旧版结论或默认行为与一手源码/实测冲突，必须走 `revisions.ts` 的 `supersede.claims`（`claims[].old` 唯一匹配旧正文、`claims[].replacement` 存在于新正文且不同于旧文、`claims[].sources[]` 列出符合 `isSourceRef` 的合法来源并列入新页 `sources`［其中源码证据须固定 `commit/路径/行号`；官方文档、归档实测材料等一手证据按现有合法 `source` 类型提供，不要求非源码来源伪造源码行号］）。
  **严禁三类伪判据：** ① 严禁拿 `sources` 来源数量不减、仅看数字集合或总字数未下降代替 `editorial` 事实保真判断（保留 `supersede` 中 `claims[].old` 唯一匹配旧文与 `claims[].replacement` 存在于新文的确定性校验）；② 严禁以“某句无独占来源”为由免检删句；③ 严禁要求“必须有新上游 commit 才准纠错”（同一固定 commit 下的准确源码行号与一手资料同样可作为纠正历史误读的合法 `claims[].sources[]` 依据）。必须在整合回执、审阅记录与独立语义复核中逐条闭环。

## 审查与修订流程

流程遵循 **前置评估提炼 → 按需改写与配图 → 双路独立审查（教学可读性审查 + 源码事实核验） → 闭环修订**：
1. **前置评估提炼：** 深改前先通读现有正文、既有 2D 图与一手参考材料，明确：① 读者核心问题与讲解主线；② **现有正文与 2D 图中已经讲得清楚、必须原样保留的好段落、好算例与好图（严禁一刀切盲目重绘重写）**；③ 存在黑话突袭、逻辑跳跃、漏讲因果或套框堆字讲不清机制的部分；④ 旧版事实与成立条件去向清单。
2. **按需改写与因景配图：** 依据一手源码/论文/官方文档组织正文，保留既有好段落、好 2D 图、既有 14 篇 `wiki-scene` 及绑定算例数字；对确有认知短板的图按场景选用泳道时间轴、比例张量格网、真实比例瀑布条、硬件端口拓扑、开放状态机或趣味微缩场景/立体剖面 `PLATE`，并编织好跨页互链与 `relations` 图谱关系。
3. **双路独立审查：** 改写完成后分别进行**教学可读性审阅（对照旧稿检查是否去除了黑话与跳跃、好段好图是否保留、初学者读完前两屏能否白话复述并换数推导）**与**独立事实性核验（对照固定 commit 源码、官方文档与论文逐条核实定义、切分维度、算式、默认行为与三出口守恒）**。存在 P1/P2 问题必须在当前轮闭环修复。

审查清单：

- **初学者可读性与去黑话检查：** 首次出现的专业黑话、缩写或源码类名是否就地用白话解释清楚；只读前两屏能否复述该机制解决什么问题、怎么运作、代价与条件在哪；凡比旧稿退步、误删好图好段或读完一头雾水，一律记 P1。
- **源码与参考文档事实性校验：** 独立对照钉住 commit 的实际源码（`vllm` / `vllm-ascend`）、官方文档与论文核实图文定义、切分维度、计算顺序、通信与数值算式；核心概念错误或无依据编造一律记 P1。
- **旧事实三出口守恒：** 对照改前版本逐条核对结论、数字、条件与排障线索的三出口去向（本页保留/等价改写、同批目标页带真实锚点与承接事实的跨页迁移、或走 `supersede.claims` 有证纠错），严禁用字数或来源条数统计代替语义核对。
- **因景制宜配图与几何门禁：** 图表是否契合场景本质（不搞无脑套框卡片八股，也不盲目重绘既有好图）、画布宽是否 `<=900px`、字号是否 `>=12px` 且零越界零重叠（`pnpm wiki:svg-geometry`）、正文是否零机器角标。
- **知识图谱连通性：** 本页及跨页链接、锚点可解析，邻近概念就地互链，`relations` 四类有向边与 `note` 准确完整。
