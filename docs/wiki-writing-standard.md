# LLM-wiki 写作标准

本文件是 wiki 写作标准的唯一出处，适用于 `wiki/concepts/` 下的概念页、深入页和主线页。写作、改写、审查前必须先读；与计划、临时任务单、历史审查意见或其他文档冲突时，以本文件为准，用户另有指示除外。后续标准变更只更新此处，任务单链接本文件。

**三级版本基线契约：**
1. **全站默认主基线**：`vllm-ascend@c09d3e20`（`v0.30.0` 正式版）+ 配套 `vllm@ced6857a`；教学标准标尺采用 `Qwen3-8B`（Dense GQA）与 `Qwen3-30B-A3B`（MoE），不把未修复的 `v0.30.0rc2` 或停服模型混入主基线。
2. **显式例外 A（`RFork` 专题 10 篇）**：目标主基线为社区上游 `vllm-project/vllm-ascend` `main`（`8d6180e2`）；Wave 0–3 暂留 `wiki/seeds/rfork.yaml`（`rfork@3284850b`）保障全库 `wiki:audit` 全绿，待 Wave 4 单批原子重锚 169 处引用后退役旧 fork 钉点。
3. **显式例外 B（历史 GLM-5.3-Flash 绑定算例：第 7 章 4 篇 GLM 页 + 19 篇含冻结 `wiki-scene` 页中引自 `docs/mainline/01-03` 的绑定算例）**：继续保持原审定钉点 `vllm@0fc695fc + vllm-ascend@db701c1f`（双机 2×A2×8 TP8/DP2/EP16 W8A8，教程 `0576b647`、模型配置 `690b7052`，详情见 [glm-5-3-flash-two-node「部署前提」](../wiki/concepts/glm-5-3-flash-two-node.md#部署前提)）；**严禁将新版本支持范围、默认值或 Qwen3 数字混入冻结 3D 绑定算例，也不得将旧 GLM 算例套回 `v0.30.0` 主基线页**；并在 `glm-5-3-flash-two-node` 另设增量对照节对照 `vllm-ascend@c09d3e20:docs/source/tutorials/models/GLM5.3-Flash.md`。

## 写给谁，先讲什么

读者是初学者。每页须回答：这是什么；请求走到主线哪一站会遇到它、为什么需要；在对应基线部署下怎样运行、付出什么代价；如何对照源码。挂靠站点要链接到对应主线页的小节，页末通过 relations 说明下一步和相关站点。

先建立直觉，再沿请求逐步推演每卡形状、通信次数、字节数和显存。标准主基线部署数字（`Qwen3-8B` / `Qwen3-30B-A3B`）或例外 B 绑定算例数字在原理讲清后出现；通用示意图可以简化卡数，数值例子必须明确标为「示意」，公式和机制仍须正确，不得把示意数当成实测。不要反复铺陈部署前提，也不要把维护者的编排理由写进教学正文。

`docs/mainline/` 下三份主线底稿（[部署、入口与调度](mainline/01-deploy-entry-schedule.md)、[逐层前向](mainline/02-forward.md)、[采样与 decode](mainline/03-sample-decode.md)）仅作为**例外 B（第 7 章 4 篇 GLM 案例与 19 篇冻结 `wiki-scene` 历史绑定算例）的专用事实底稿归档**（钉住 `vllm@0fc695fc + vllm-ascend@db701c1f`）；标准 `v0.30.0` 主基线页面直接以 `vllm-ascend@c09d3e20`、`vllm@ced6857a` 源码、官方文档及 `src/sim/modelspec/` 单真源为准，不从 `docs/mainline/01-03` 搬运 GLM 数字。读者页的 sources 直接指向钉住 commit 的源码、官方文档或论文，不以底稿代替原始证据。

## 基础讲法：反八股自适应与从理解到演算

读者只懂基本 Python、向量和矩阵乘法，未必学过 Transformer、vLLM 或昇腾。用户的反馈表达初学者的困惑，写手应判断怎样讲最顺，**不立任何单篇固定模板（不把旧实验稿变成新八股，也不用新模板替代旧模板）**，不锁死旧稿句式、段落顺序或旧 2D 图，也不把一句反馈机械放大成整页规格。改写时**先提炼、后重写：不是每页或每段都推倒重来，原稿或候选稿中已经写得清楚的好段落、好算例与好 2D 图必须明确保留；对交错混乱、主次颠倒或空洞的段落与 2D 图，则允许重新组织与重写正文、重新设计 2D 教学图**；同时必须完整保留已核实事实、一手来源、成立条件、冻结的 3D 场景（`wiki-scene`）及与其绑定的核心算例数字。

写作与改写遵循**四条认知底线与两条硬核保真铁律**（见[渐进改造方案 §5.2](plans/2026-11-14-progressive-restructure-and-fix-plan.md#52-六条终态核心契约end-state-contracts)）：

1. **底线一（主干先行，条件归仓）**：前半程用干净标准路径把核心机制讲透；多版本分叉、特殊模型分支、`assert` 早退统一收束至后半段「适用范围 / 边界与版本差异」或文末 `## 对照源码` 区，`summary` 与首屏免除全量免责括号轰炸。
2. **底线二（表达工具随题材自由选配，废除单篇机械八股）**：按题材体裁选配最能帮读者建立直觉的表达工具，不强套同一种八股骨架：
   - **调度与控制流**：围绕核心不变量，可配 10–20 行提炼伪代码 + 步进时间轴算例；
   - **算子与数值计算**：先讲清为什么需要该运算与误差/代价出在哪里，再给最小可手算玩具算例（取出哪些数、怎样相乘相加、结果放哪里），配 KaTeX 数学公式（行内 `$...$` 或块级 `$$...$$`，多字母算子/函数名使用 `\text{clamp}`、`\text{round}` 等正体，负号使用标准 ASCII `-` 替代 Unicode `−`）与对比表；
   - **系统拓扑与多卡协同**：用 2D 比例分格图展示张量分片、发送/接收与归约前后状态（注：全部 3D 图/场景与 `wiki-scene` 在本轮渐进改造期间严格冻结，保留既有 3D 围栏及与其绑定的算例数字，但承接算例的正文讲解顺序、白话叙述与 2D 教学图可按理解需要重写重画）；
   - **配置参数与排障诊断**：直接给判据表、现象→最小首取证据→区分实验与下一站机制页结构及取证命令。
3. **底线三（单页入口自洽 + 共用数字回链单一出处表）**：每页能独立进入，入门算例在页内 30 秒立住，可用 2–3 句白话交代背景数字；前置概念首次出现须就地用一句话解释，链接放在实际用到概念之处。**凡引用跨页共用推导值，仍须回链下方「单一出处表」，严禁各页私自重推漂移。**
4. **底线四 + 保真铁律（自然语言条件留主干，机器标记与四版本矩阵入文末折叠核验区）**：
   - **保真铁律一**：**教学主干必须在结论就地用自然语言说清示意设定、静态推导前提或未实测边界（严禁在归档机器标记时把适用条件一起抽走后移），对照源码之上零证据角标**——`[C#]/[S#]/[D]/[I]/[A]/[!]` 机器方括号标记统一归入页末 `## 对照源码` 核验区（参数页 `type: param` 可在 `## 事实表` 保留紧凑标记，但严禁在首句用 `**v0.30.0 对照：**` 或 `**v0.30.0rc2 对照：**` 劫持开篇）；
   - **保真铁律二**：**`v0.23.0 (2c59ff10)` / `v0.26.0rc (2ed6cbba)` / `v0.30.0 (c09d3e20)` / `main (8d6180e2)` 四版本核验矩阵**与核心源码锚点**必须保留在同一 `.md` 文末 `## 对照源码` 核验节内**（保证 `wiki:find`、`wiki:mcp`、`retrieve.ts` 完整可读，绝不允许删空 `sources` 或版本差异），由前端阅读器渲染为默认折叠区，并由右栏 `WikiPanel` 离线证据面板支持源码、`raw:` 快照与精确图 `pin` 离线对照。

图按教学需要配置，**废除脱离题材的强制充数挂图**。张量用一个整体加格线；计算图要能看见数如何变化。静态通信图使用**静态分格**展示「发前各自有什么 → 谁把哪块发给谁 → 发后各自有什么」，样板是 [All-Reduce 分格图](../wiki/diagrams/collective-communication-all-reduce.yaml)。交互 3D 统一遵守 [教学 3D 标准](3d-teaching-standard.md)（当前轮次 3D 冻结不改）。

讲不清时先看参考资料的实际图像，学习它如何组织概念与例子，再用本站图语言重画，不照抄。通信原语及 TP/DP/EP 的参考包括 [通信原语](http://www.xzclass.com/?p=3366)、[AMD MoE 指南](https://rocm.blogs.amd.com/software-tools-optimization/vllm-moe-guide/README.html) 与[并行参考](https://zhuanlan.zhihu.com/p/2003423046342554380)；只有文字抓取不算看过图，本地已存截图也可使用。图元不足时新增能力，先核对未提交改动，不改变既有图元行为；改后运行 `pnpm wiki:diagrams --check`。

逐节让初学者用自己的话复述：核心概念错误、前置概念先用后讲、需要演算却没有演示，都按 P1 处理。参考已达标的量化缩放、KDA 二维状态、RMSNorm/LayerNorm 对照、稀疏注意力重归一化与 DP 请求分配例子。深度和事实保留要求见下节「顺序不等于删减」。

## 深入页参考递进骨架：先直觉、后数字

> **顺序不等于删减。** 「先直觉、后数字」只规定讲的顺序。该讲清楚的机制、推导、数字和边界情况，一样都不能少：知识库也是问答的知识底子，页面讲得不全，问答就答不全。瘦身只删重复和水分，不降深度。（用户，09-28）

并行、特性、机制深入页推荐按以下递进脉络组织（具体小节标题、讲解顺序与表达工具随题材自适应，不作机械模板锁死，也不用一套新模板替代旧模板）：

1. **第一屏：解决什么问题、这是什么。** H2 用贴合该页核心矛盾的问题或命题命名；开篇直接从具体痛点或问题切入，定义本页概念并交代解决什么问题，必要的前置词先就地解释。需要建立空间/结构直觉的机制页配一张通用直觉图（只画原理、只标卡数，不标字节、不画具体部署形状；箭头必须让人看出东西如何流动；首图位置按理解需要安排，不搞硬凑前两节挂图）。
2. **第二屏：怎么运作、为什么能接上、代价与条件在哪。** 用属于该机制的具体小算例、提炼伪代码或重绘的 2D 图把机制运作步骤与因果讲透，让读者读完前两屏不仅能用白话复述机制，还能换一组数字自行推导；需要数值时用已标明的示意数，具体部署数字留给后文。讲明哪一步后通信、每层几次、在哪里等待；用一段话或紧凑小表区分相邻概念。
3. **落到标准部署或绑定算例（适用时）。** 标准 `v0.30.0` 主基线页面采用 `Qwen3-8B` / `Qwen3-30B-A3B` 与 `src/sim/modelspec/` 单真源算例；19 篇冻结 `wiki-scene` 页与第 7 章 4 篇 GLM 页按例外 B 维持原 GLM R1 / 场景 M 单标尺走读（不混塞第二套 Qwen3 数字）。小节 `calc` 数量与表/`calc` 间隔以推演清晰为准（建议每节先给结论、表与 `calc` 间用正文交代因果，不靠拆空洞小标题凑密度）。整批账单独放在后面的 H2，首次使用时交代设定并链接，不混进单 token 走读。
4. **适用范围、特殊层与变体边界。** KDA、稀疏 MLA、词表、共享专家或多版本分叉只讲与一般主干有什么不同及成立条件，细节链接各自页面。
5. **常见误解 → 对照源码。** 教学正文对参数名、变量名、函数名、类名、退出码/状态码按语义正常使用反引号代码样式，普通技术名词保持正体、避免无意义代码底色（**已废除旧版“正文行内代码每千字不超过 13 个”的机械配额**）。源码行号锚点、commit 对照与完整四版本差异矩阵集中在文末默认折叠的 `## 对照源码`。
6. **机器证据角标与待核放页末。** 对照源码之上零证据角标（教学主干用自然语言就地写清条件），所有 `[C#]/[S#]/[D]/[I]/[A]/[!]` 机器角标与「待核：缺什么」归入页末 `## 对照源码`；迁移标记以降低阅读干扰，绝不删除已核实的事实与限制条件。

**TP 直觉图示例：** 按数学上的「输入维 × 输出维」画成对矩阵：先 column parallel（沿输出维按列切），各卡从同一输入算出数值完整的几列，本地完成逐元素激活；再 row parallel（沿输入维按行切），接住本卡这几列，得到形状完整、数值尚未加齐的部分和；最后一次 All-Reduce（各卡按位置相加并取得结果）。图中竖条、横条、长边和维度标注必须一致。紧接图解释反例：非线性激活不能对部分和分别算完再相加，先行切就得在激活前先归约；两次都列切则需在中间 All-Gather 拼回输入。先列后行才省去中间通信，不能只画行切，也不能宣称反过来在数学上完全无法实现。存储转置的区别移到源码区。

**EP 直觉图示例：** 画出源卡与多张持有完整专家的卡，给专家编号，区分选中与未选中的专家；用箭头串起「一个 token → router 选 k 个专家 → dispatch 发到持有卡 → 各卡计算 → combine 回源卡按权重相加」。源卡自己也持有专家；均分示意中每卡格数一致。图只表达分工，k 的含义在图旁解释；实际卡数和选择数在后文部署段交代。routed experts 指整个可供 router 选择的专家集合，不是某个 token 本次选中的子集；shared expert 是所有 token 都经过的共享专家，切分方式按对应部署说明回链。

## 页面格式与信息层级

- 开篇一句话说清概念；不另设「一句话」H2。首次定义要解释作用，仅展开缩写或给中文译名不算解释。参数页与来源页不强制写 `**v0.30.0 对照：**` / `**v0.30.0rc2 对照：**` 开篇段；参数页的紧凑对照信息留在 `## 事实表`。
- 数值推导用 calc 围栏，每块写 title；语法只以 [算式格式](wiki-calc-syntax.md) 为准，不另复制一套规则。符号公式、伪代码、形状与流程不要硬改成数值算式。
- **位置与密度指标作为诊断提示而非一刀切硬门禁（任务 `543` 已落盘并通过独立复审）：** 首图位置（`diagram-first`）、小节 `calc` 密度（`calc-density`）、表格与 `calc` 邻接（`stacked-blocks`）作为可读性提示供写手与审阅者参考，不再作为写管线或批准的一刀切拦截项。排版服务于前两屏理解与真实演算推演：既不靠拆空洞小标题绕过提示，也不为迎合位置规则在算例前硬塞空洞图；密集账单可汇总、后置或链接唯一出处。
- **按信息与教学需要配图与重画 2D 图，不设凑数配额：** 只有空间切分、多步状态流转、多分支条件分流、跨进程/跨卡拓扑等靠文字容易混淆的地方才配 2D 图；旧 2D 图若只画空洞方框或未能把核心机制讲清，允许按教学需要重新设计重画。概念、边界或参数页若靠清晰文字、对比表与源码对照即可讲清，不硬塞凑数流程图。
- **2D 图与 3D 场景规则：** 2D 静态图画布宽度 ≤900px，在既有桌面阅读列（`--wiki-measure: 1200px`）内按 `1:1` 舒适展示，超宽时由 `.wiki-diagram-scroll` 横向滚动兜底，不靠把字号缩到失真或强压到旧 `760px` 窄栏。静态图使用 `wiki-diagram` 围栏，支持两条已验收通道：① **`layout: figure` 规格图**（手写 `wiki/diagrams/<id>.yaml` 经 `pnpm wiki:diagrams` 确定性生成 `<id>.svg`，支持 `links[].bend` 单参数法向弧线［与 `curve` / 非空 `via` 互斥］，以及仅在 `texts[].font`、`items[].font`、`sketches[].shapes[kind="text"].font` 上支持的 `font: "sans" | "mono"` 等宽代码字体，已移除三类机械文字/代码名提醒，保留越界/碰撞几何硬检查与 `sketches` 提示，`897` 已验收）；② **手写原生 `.svg` + 同名伴生 `wiki/diagrams/<id>.yaml`（`mode: "native-svg"`）**（伴生 YAML 声明 `id`、`caption`、`size: [width, height]`［两维正数且 `width <= 900`，不限制高度，如 `[600, 1200]` 合法］与 `pins`，同名 `<id>.svg` 经严格 XML 1.0 解析、内部 `#id` 引用完整性与 `diagram-sanitize.ts` 正向属性值语法白名单校验，CLI 保留原始 `.svg` 字节不作派生覆盖重绘，底座 `910` 已验收；`Drop` 三路整合第 2 轮 `922`/`928` 修复复验中，静态白名单注册交互式 React 2D 仍属包 4 待完成项）。正式阅读页（`WikiDiagram.tsx`）与 `ReviewPane` 浏览器预览共享 `diagram-sanitize.ts` 正向白名单清洗；图 `pins` 源码符号由 AC11 `diagram-symbol` 对固定 `commit` blob 核验，已移除要求图 `pins` 文件在所属页 `sources` 重复登记的 `diagram-identifier` 规则，右栏 `WikiPanel` 离线证据面板（`868`/`886` 已验收）按精确 `pin` 与 `raw:` 快照提供离线源码/原文对照（无本地快照时诚实提供外链）。**全部现有 3D 动画与 `wiki-scene` 冻结不动**（保留绑定算例数字，正文与 2D 图可重写重画），不新开 3D 重做；后续触碰教学 3D 时遵守 [教学 3D 标准](3d-teaching-standard.md)。不得用脚本批量生成或改写正文与图的内容。

## 术语规则

vLLM、Ascend 以及论文里有固定名字的机制、组件、特性使用英文原名，例如 KV cache、block table、prefix caching、chunked prefill、graph mode、EngineCore、MoE、All-Reduce、MC2、HCCL；源码标识符保持原样。请求、权重、张量、矩阵、向量、显存、带宽、吞吐、时延、维度、副本、节点等通用技术词用中文；「昇腾」「超节点」保留中文，包名、类名中的 Ascend 不改写。

首次出现就用一两句中文解释它是什么、做什么，图中的词也一样；不另造中文机制名。统一拼写查 [TERMS.md](../wiki/TERMS.md)。同形近形名称要区分，例如 AllGather 通信路径与 All-Gather 集合通信操作；R1、场景 M 等示例标签也须先说明再使用。

## 写手常见错误

1. **把每台机器／每个 DP 组说成完整模型副本。** 在 GLM-5.3-Flash 双机部署算例（或一般 MoE EP 部署）中，EP16 把 288 个专家分在 16 卡，每台是 DP 执行组，两台合起来才构成完整模型。
2. **术语先用后解释。** 首次出现就地解释；不要让首屏别名、参数和未解释的图标签压过概念。
3. **两页重推同一个量，结果对不上。** 按单一出处表只保留一份推导，其余给结论和链接。
4. **先算账后讲概念。** 第一张图之前堆 calc、部署数字和形状表，读者仍不知道概念是什么；直觉图也不能画成部署图。动机必须用属于该机制的数字，不能用 EP 专家容量证明 TP 的必要性。
5. **TP 只画按行切，或图文切分方向相反。** 必须讲列切、激活、行切如何成对配合，并解释反过来为何不能省掉激活前的通信；不能靠「非等比例」图注掩盖方向错误。
6. **把 routed experts 定义成「被挑选的专家」。** 它指可供选择的整个集合；本次选中的是子集，另须区分共享专家。核心概念或定义讲错一律 P1，不能因后文用法正确而降为 P2。
7. **为简洁删事实，或把猜测写成事实。** 重排需保留已核实数字、条件、反例、链接和误解条目；纠错要给原始证据。静态推导、源码证据和硬件实测分清，未核项不能因换写手消失。
8. **只有数字没有解释，或反复更换算例。** 形状标明每一维代表什么；场景切换交代设定；表与 calc 之间用正文解释因果，不用一句空泛引语隔开。

- **重写丢信息与旧事实三出口守恒**（09-28 P5 实测：GPT 写的前 7 页里有 4 页丢了旧版的关键结论，都记为 P1）。深改前必须先把旧版的结论、机制、数字、边界情况与已核实源码/排障线索逐条列成清单；写完逐条核对旧事实的三类合法去向（三出口守恒，见 [渐进改造方案 §5.2](plans/2026-11-14-progressive-restructure-and-fix-plan.md#52-六条终态核心契约end-state-contracts)）：
  1. **保留或等价改写（`editorial`）：** 新版正文、表格或折叠核验区中仍保留该事实及版本/硬件限定条件，或以语义等价的自然语言/表格重写；
  2. **跨页迁移（`editorial` 同批承接）：** 挪到拆分子页或单一出处页时，必须满足四项条件：**① 同批候选 `Review.writes` 包含目标承接页写入；② 目标页具备真实承接锚点与实际承接事实正文；③ 目标页通过 `base` 校验；④ 原页留有指向该锚点的链接，并经独立语义复核**（绝不能只凭原页填一个链接就算旧事实已保留）；
  3. **带证据显式纠错（复用 `supersede.claims`）：** 旧版结论或默认行为与一手源码/实测冲突，必须走 `revisions.ts` 的 `supersede.claims`（`claims[].old` 唯一匹配旧正文、`claims[].replacement` 存在于新正文且不同于旧文、`claims[].sources[]` 列出符合 `isSourceRef` 的合法来源并列入新页 `sources`［其中源码证据须固定 `commit/路径/行号`；官方文档、归档实测材料等一手证据按现有合法 `source` 类型提供，不要求非源码来源伪造源码行号］）。
  **严禁三类伪判据：** ① 严禁拿 `sources` 来源数量不减、仅看数字集合或总字数未下降代替 `editorial` 事实保真判断（保留 `supersede` 中 `claims[].old` 唯一匹配旧文与 `claims[].replacement` 存在于新文的确定性校验）；② 严禁以“某句无独占来源”为由免检删句；③ 严禁要求“必须有新上游 commit 才准纠错”（同一固定 commit 下的准确源码行号与一手资料同样可作为纠正历史误读的合法 `claims[].sources[]` 依据）。必须在整合回执、审阅记录与独立语义复核中逐条闭环。

## 审查与修订流程

流程是 **前置参考提炼（烁烁） → 重写（墨墨） → 双路独立审查（烁烁对照旧稿审讲法 + 砚砚核事实/源码/参考） → 修订**。
1. **前置参考提炼（烁烁）：** 重写任何文档前，先由烁烁通读正式旧稿、已有候选稿、实际 2D 图与一手参考材料，产出单页提炼稿（`docs/reviews/2026-11-15-wiki-restructure/rewrite-briefs/`），明确提炼：① 读者核心问题与讲解主线；② **旧稿/候选稿中已经写得清楚、必须保留的好段落、好算例与好 2D 图（不搞盲目推倒重来）**；③ 概念交错、顺序混乱或需要重写/重画的部分；④ 旧版事实与成立条件去向。
2. **短批次重写（墨墨）：** 墨墨依据前置提炼稿与一手证据，保留原有好段落与好图，重组或重写混乱段落与需重画的 2D 图，确保已核实事实、来源、成立条件、冻结 3D `wiki-scene` 与绑定算例数字完整无损，并按短回合交付（严禁单回合超长运行）。
3. **双路独立审查（烁烁 + 砚砚）：** 每页重写完成后，必须同时经过**烁烁（教学递进与旧稿对比审阅）**与**砚砚（源码、参考文档与事实性独立校验）**双审，不复用写手自查或前置提炼代替重写后的独立审阅。存在 P1 必须修订后复审，直到 P1 关闭；只有 P2、P3 时由写手全部改完并自查即可，不因此省略重写后的双路独立审查。

审查清单：

- **与旧稿逐节对比 + 初学者体验测试（烁烁教学审阅硬规格）：** 审阅者**必须将重写稿与之前的文档（正式旧稿及此前候选稿）对照审阅**，逐项给出结论：① 哪里比旧稿讲得更清楚；② **有没有讲得不清楚或比旧稿改差/退步的地方**；③ **旧稿中原本写得好的段落和好 2D 图是否保留或真正改好**；④ 只读前两屏能否用自己的白话复述该机制解决什么问题、怎么运作、为什么能接上、代价与条件在哪，并把例子换一组数字后仍能独立推导。凡有讲得不清楚、比旧稿退步、误删好图好段、或换数字推不出，一律记 P1，**严禁拿自动检查全绿、字数、免责词比例、标题保留率或主观打分替代与旧稿的实际对比**。同时检查正文是否被机器角标或句句跨四版对照打断阅读。
- **源码与参考文档事实性校验（砚砚事实审阅硬规格）：** 独立对照钉住 commit 的实际源码（`vllm` / `vllm-ascend`）、官方参考文档与原论文，逐条核实定义、切分维度、计算顺序、通信、数值算式、默认行为与反例，图文一起核，**防止乱编、防止不符合代码、防止不符合参考文档**；任何核心概念错误或无依据编造均为 P1。
- **数字与版本边界：** 与主线底稿及唯一出处一致，单位、统计范围、分支和版本条件完整；正文按需用自然语言交代触发条件，文末 `## 对照源码` 完整列出四版差异与可点击源码引用。发现不一致先核原始证据，再统一来源。
