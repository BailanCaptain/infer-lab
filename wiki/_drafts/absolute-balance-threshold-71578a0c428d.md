## 一句话

`absolute_balance_threshold` 是 STAIR 判断是否继续评估专家摆放方案的一道绝对门槛：**非零负载窗口已有有效锚点时，当前均衡度小于或等于这个阈值，就通过这道门控。**

这里的专家是执行前馈计算的模块；专家摆放方案决定这些模块放在哪些设备上。门控回答的是“是否值得继续评估候选方案”，实际是否搬运还要经过后续筛选。

本页依据本地材料中的配置与规划器摘录，覆盖其中标明的两个提交快照。材料没有提供它们与在册发布分支的映射，也没有完整运行时调用链，因此本页不据此登记已核对版本或给出启动配置命令。

## 事实表

| 项 | 值 | 意味着什么 |
| --- | --- | --- |
| 类型与静态默认值 | 材料中 `4d1412d1` 配置摘录标注为 `float`，默认 `0.90` | 这是配置定义记录，不能单独证明启动后的最终有效值 |
| 数值范围 | 有限数，且 `0 < 值 ≤ 1` | `0`、负数、大于 `1` 的数、NaN 和无穷值不合法 |
| 布尔输入 | 显式拒绝 `True` 和 `False` | 不能用布尔值代替数值阈值 |
| 均衡度 | `balance = 1 / mean_ratio` | 平均峰均比越大，均衡度越低；峰均比比较最忙设备与设备平均负载 |
| 绝对条件 | `current_balance ≤ absolute_balance_threshold` | 包含等号；在已有有效锚点的分支中，达到门槛就允许继续评估 |
| 与相对条件的关系 | 两项条件以 OR 连接 | 绝对条件或相对条件满足一个即可，不要求同时满足 |
| 全零窗口 | 直接返回 `None` | 不进入后续阈值比较，也先于锚点合法性校验返回 |
| 尚无锚点 | 非零窗口中，锚点为 `None` 或 NaN 时直接返回当前不均衡评估结果 | 此时不靠绝对阈值决定是否通过 |
| 有效锚点 | 有限且不小于 `1` 的已提交预测峰均比 | 其他非空、非 NaN 的非法锚点会报错 |
| 候选筛选 | 预测平均峰均比或 p95 峰均比任一变差，就丢弃该候选 | 通过门控不等于候选会被接受，更不等于已经搬运 |

## 为什么存在

专家负载不均衡时，某些设备承担的工作比其他设备多。判断是否需要重新评估摆法，需要一个能描述当前负载差距的量。材料中的 STAIR 使用峰均比：把各设备中的最大负载除以设备平均负载，再用其均值的倒数表示均衡度。

因此，均衡度较低表示负载差距较大。绝对阈值直接判断当前均衡度是否低到了设定水平；[相对阈值](../params/relative-balance-threshold-bcbc40e7dc87.md)则把当前均衡度与一个已经提交的比较基准相联系。

这个比较基准称为锚点。材料第 221–222 行说明，锚点保存的是**实际提交摆放方案之后记录的预测平均峰均比**。它不是任意一个刚搜索出来、尚未提交的候选结果。

### 一组示意数怎样通过门控？

设当前窗口有非零负载，保存的锚点为 `1.25`，绝对阈值取材料所示静态默认值 `0.90`。下面只演示门控中的倒数与比较，不重建窗口统计过程。[A]

假设当前统计得到的平均峰均比也是 `1.25`，则：

- 当前均衡度为 `1 ÷ 1.25 = 0.80`。
- 锚点对应的均衡度也为 `1 ÷ 1.25 = 0.80`。
- 当前均衡度与锚点均衡度之比为 `0.80 ÷ 0.80 = 1`。[D]

若相对阈值也设为 `0.90`，相对条件不满足，因为 `1 > 0.90`；绝对条件却满足，因为 `0.80 ≤ 0.90`。两项条件以 OR 连接，所以门控返回当前不均衡评估结果，允许后续评估继续。[A]

这个例子说明：**即使当前负载没有比锚点更差，只要它本身已经不够均衡，绝对条件仍可通过。**

等号同样有效。例如当前平均峰均比为 `10/9` 时，均衡度为 `0.90`，恰好满足默认绝对门槛。[D]

### 没有锚点与没有负载时怎样处理？

材料中的判断顺序是：

1. 全零负载窗口直接返回 `None`。
2. 非零窗口若尚无锚点，即锚点为 `None` 或 NaN，直接返回当前不均衡评估结果。
3. 其余锚点必须有限且不小于 `1`，否则报错。
4. 有效锚点才进入绝对条件与相对条件的 OR 判断。

所以，“均衡度不高于阈值才通过”只适用于已有有效锚点的分支。首次尚无锚点时，非零窗口走的是另一条分支；全零窗口则直接跳过。

## 开了的代价

这不是一个独立的布尔开关，而是数值门槛。在其他条件不变、已有有效锚点的情况下，调高它会扩大满足绝对条件的均衡度范围；调低它会缩小这个范围。相对条件仍可能单独使门控通过，所以降低绝对阈值不能保证减少所有后续评估。[D]

材料还显示，进入候选评估后，如果某个候选的预测平均峰均比或 p95 峰均比比当前更差，该候选会被跳过。因此，阈值调高并不意味着一定发生专家搬运；它先改变的是允许继续评估的条件。材料没有提供完整执行链和性能数据，无法据此量化规划耗时、搬运量或吞吐变化。

### 输入错误会怎样？

范围检查失败时，错误字符串为：

```text
stair_config.absolute_balance_threshold must be between zero and one
```

布尔值触发的错误为：

```text
STAIR numeric fields must not be booleans
```

因此，不能写 `0` 来关闭这道门。很小的正数只会使绝对条件更难满足；无锚点分支和相对条件仍按各自规则运行。[D]

非法锚点的错误为：

```text
last_committed_mean_ratio must be NaN or a finite ratio no smaller than one
```

该错误属于规划器状态校验，与用户填写阈值越界是两种不同的问题。全零窗口先返回，不会走到这项锚点校验。

### 这些结论覆盖哪些版本？

材料标出了 `4d1412d1` 与 `7d825229` 两个提交快照。前者包含静态默认值和候选退化筛选摘录；材料也提供了两个快照中的阈值校验，以及后者关于已提交锚点的接口说明。

现有材料不足以逐项确认 v0.23 维护分支、v0.26 分支、v0.30.0rc2 分支与 main 开发主线的支持范围、默认策略和运行时行为。本页也不把摘录中的字段存在，扩展为所有环境都会消费该字段。

后续需要补核的内容包括：发布分支与快照的映射、配置入口、策略选择条件、调用门控的时机，以及候选方案实际提交和搬运的执行逻辑。`0.90` 的选取依据与适用负载也需要额外材料；本次摘录没有给出标定过程。
