## 一句话

`cross_node_transfer_limit` 是 STAIR 专家摆放规划中的跨节点搬运次数上限：对一层的一次计划，每个节点的传出次数与传入次数分别计数、分别受限。这里的节点指参与专家搬运的机器；专家是 MoE 中执行前馈计算的模块，搬运专家涉及改变其存放位置。

本页依据本地材料中的配置、规划和校验摘录整理；材料没有建立各提交与在册发布分支的对应关系，因此这里只说明摘录能支持的行为，不登记已核对版本。

## 事实表

| 项 | 值 | 意味着什么 |
| --- | --- | --- |
| 限制范围 | 一层的一次计划，每个节点分别计算传出和传入次数 | 不是整个运行过程的累计额度，也不是发送与接收合计共享一份额度 |
| 合法取值 | 非布尔整数，且不小于 -1 | 摘录中的策略入口拒绝布尔值、非整数和小于 -1 的值；0 合法 |
| 设为 0 | 禁止跨节点专家搬运 | 只关闭跨节点方向，不表示禁止所有节点内搬运 |
| 设为 -1 | 取消这道跨节点次数限制 | 不能据此认定其他搬运限制也被取消 |
| 声明默认值 | 材料中的不同提交分别为 1 或 -1 | 不能把一个快照的默认值推广为所有版本的默认值 |
| 自动 Gloo 回退 | 摘录所述回退只把用户未设置的传输限制收紧为 1 | 显式设置保留，包括用于禁止跨节点搬运的 0 |
| 节点归属 | 每个 rank 对应一个非负节点编号；编号相同表示同一节点 | rank 是参与分布式执行的成员编号，是否跨节点取决于节点编号，而非 rank 是否不同 |
| 计划校验 | 非 -1 时，源节点传出或目标节点传入次数超过上限即报错 | 发送方向符合上限，并不足以证明整份计划合法 |

表中的定义、默认值、校验与回退行为分别见材料第 1—9、97—109、232—248 行。材料是本地归档摘录，本页未将其中的源码文本升格为独立核验的源码证据。

## 为什么存在

专家摆放规划要在改善计算负载与搬运专家之间作选择。跨节点搬运需要机器之间传输数据；这个参数给规划器增加一道次数约束，使一次层计划不能任意集中大量跨节点搬运。它限制的是次数，不能直接换算成传输字节数或耗时：这还需要每次搬运的数据量、传输路径和执行方式。

假设有节点 A 和节点 B，将上限设为 1。计划包含一次 A → B 和一次 B → A 的专家搬运。[A]

A 的传出次数是 1、传入次数也是 1；B 同样如此。两次搬运满足这道限制，因为两个方向分别计数。若再增加一次 A → B，A 的传出和 B 的传入都会变成 2，超过上限。这一例子只检查跨节点次数约束，计划仍须满足其他合法性条件。[D]

对于有 N 个节点、非负上限为 L 的计划，每次跨节点搬运恰好计入一个源节点的传出次数，所以总次数不超过 N × L。接收方向也必须逐节点检查；仅满足总次数上界，不能保证某个目标节点没有超额。这是次数上界，不是计划一定会执行的次数。[D]

规划器也不是无条件选择搬运最少的候选。材料第 57—61 行描述的层计划选择规则是：候选的平均与 p95 不均衡指标都不能恶化，然后优先选择预测平均比值最低的候选。只有平均比值落在内部绝对容差内、被视为并列时，才依次比较跨节点搬运、节点内远程搬运以及后续编号。

材料第 72—76 行还描述了最终搬运来源分配中的排序：先最小化跨节点搬运次数，再按目标槽位顺序比较源 rank 编号。层计划的候选比较与最终来源分配是两个不同位置的规则，不能合并成“整个规划始终只追求跨节点次数最少”。

## 开了的代价

这个参数通过限制可接受计划的范围发挥作用。较小的有限值可能排除需要更多跨节点搬运的摆放；较大的值或 -1 则允许规划器考虑更多这样的计划。它们是否改善负载、增加多少传输时间，材料没有提供实测对照，不能据此给出性能收益或开销数值。[I]

设为 0 适合表达明确的约束：本次专家调整不允许跨机器搬运。设为 -1 则只取消本参数对应的次数门槛；其他约束仍需分别满足，例如材料中同时参与检查的 [rank_transfer_limit](../params/rank-transfer-limit-99529b37d91d.md)。两者的取值规则不同：摘录中的策略入口允许本参数为 0，却拒绝 rank 搬运上限为 0。

**声明默认值需要与实际生效值分开。** 材料第 1—3 行展示的配置声明为 1，第 103—109 行展示的两个提交声明为 -1；材料另有默认值为 -1 的提交摘录。这些快照不足以确定变更顺序、首次引入时间或对应发布版本。[!]

材料第 241—248 行说明，一种自动 Gloo 回退会把用户未设置的 STAIR 传输限制收紧为 1。Gloo 在这里是回退使用的传输路径；摘录注释给出的理由是经 CPU 暂存的传输难以承受集中迁移。该处理保留用户显式设置的值，包括 0。材料没有完整展示触发条件，因此不能把这条规则扩展到所有使用 Gloo 的场景。

非法输入与非法计划也要区分。材料第 97—101 行的策略入口对非法类型、非法上下限等统一抛出：

```text
STAIR transfer limits and backtrack_limit must be valid integers
```

材料第 232—236 行展示的计划校验则在某节点传出或传入超额时抛出：

```text
STAIR plan exceeds a per-node cross-node transfer limit
```

前者说明输入参数未通过该入口的检查，后者说明搬运计划违反了次数约束；不能将它们当成同一种问题。

版本核对仍有缺口：本次材料无法分别确认 v0.23 维护分支、v0.26 分支、v0.30.0rc2 分支及 main 开发主线的完整配置入口、默认值和运行时行为。已有页面上下文中的版本结论不作为本次新证据，需在后续整合时对照各分支固定源码核实。
