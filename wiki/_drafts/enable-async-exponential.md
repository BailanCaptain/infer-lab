## 一句话

`enable_async_exponential` 控制是否提前生成采样所需的指数分布随机数，让这部分工作有机会与后续执行重叠；采样真正使用这些随机数时，仍要等待它们准备完成。

采样是根据模型给出的候选 token 概率选出输出 token 的过程。这里的“指数”指随机数的分布，不是对模型分数做指数运算的开关。以下行为来自材料标识为 `2c59ff10` 的摘录；材料没有给出该提交对应的在册发布分支，因此暂不归入任何已核对版本。

## 为什么存在

这项配置尝试把随机采样所需的一部分准备工作提前做。若等到采样要使用随机数时才开始生成，生成过程就处在采样的直接等待路径上；提前提交后，这段工作有机会与其他执行重叠。具体能重叠哪些操作、重叠多少，以及是否缩短请求耗时，摘录没有给出完整执行时序或测量结果，尚不能确定。

在给出的调用片段中，模型执行侧检查开关是否生效，随后调用 `do_async_exponential`，传入需要采样的行数、词表大小和随机数生成器集合。生成器是控制随机数序列的对象；摘录按行索引为部分行使用各自的生成器。

预生成方法进入 `global_stream()` 指定的 NPU 执行流。执行流是提交设备操作的队列；这里先让该流等待当前流，再创建随机数张量 q。q 的每一行对应一个待采样位置，每一列对应一个词表候选，因此预生成规模同时受行数和词表大小影响。

若生成器集合没有覆盖全部行，代码先对整个 q 生成指数分布随机数；随后，对集合中指定的行，再使用对应生成器生成随机数。由此可见，部分行指定生成器时，整体生成与逐行生成会同时出现在这条准备路径中。

到了采样阶段，异步分支先同步事件，再把概率张量逐元素除以 q，沿最后一维选出最大值所在的位置。完整流程是“提前生成 → 等待完成 → 使用随机数选取”，提前提交并未消除使用前的依赖。

材料中的注释还提到 AI-CPU exponential 或默认 exponential 实现，但没有展示选择条件，不能据此指定现场会使用哪一种实现。

## 开了的代价

**预生成需要额外的随机数张量。** 摘录中 q 的元素数是采样行数与词表大小的乘积，数据类型为 float32。其精确生命周期、是否复用以及对峰值显存的影响，仍需完整实现才能核实。

**采样可能仍需等待。** 异步分支在使用 q 前显式同步事件。如果随机数尚未生成完，采样会在此等待；材料没有证明这段等待一定能被其他计算覆盖，也没有提供吞吐或时延收益。

**与批不变性模式存在明确约束。** 批不变性关注同一输入在同批其他请求改变时能否保持结果一致。摘录中的配置逻辑在 VLLM_BATCH_INVARIANT 开启时关闭异步指数路径，注释给出的理由是该路径会让 AscendSampler 与 vLLM Sampler 不同，从而使批不变性模式失效。材料第 108–111 行的测试注释也说明，这种关闭可以静默发生；测试为此单独创建了关闭批不变性模式的 LLM 实例。测试片段本身不证明测试已经通过。

需要批不变性时，应按这一约束理解开关行为。以性能为目的启用时，则需先确认现场版本仍有此功能，再测量实际负载的收益；当前材料不足以给出推荐配置或收益数字。

**版本范围仍有缺口。** 对 v0.23 维护分支、v0.26 分支、v0.30.0rc2 分支和 main 开发主线，现有摘录均不足以逐项确认功能是否存在、默认值及行为是否一致，因此本页未登记 verified。材料中的未来弃用计划，也不能用来确定删除版本。

另两份提交摘录展示：发现未知配置项且检测到 vllm_omni 时，会告警并过滤未知项。但摘录没有给出完整字段集合，无法确认此开关在这些提交中是否属于未知项，也无法据此断言传入它一定报错或一定被忽略。
