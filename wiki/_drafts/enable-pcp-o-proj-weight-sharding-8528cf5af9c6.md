## 一句话

在材料所述的 SFA-PCP 路径中，`enable_pcp_o_proj_weight_sharding` 控制是否在加载时进一步切分 attention 输出投影的权重，并在运行时切换局部权重与聚合后的权重视图。

attention 输出投影通常记作 o_proj：它把 attention 计算得到的向量，再通过一次矩阵乘映射到后续计算需要的表示。PCP 是 prefill context parallel，即在处理提示词时沿上下文位置分配工作的一种并行路径；组内每个参与成员有自己的编号，称为 rank。相关分工见[上下文并行](../concepts/context-parallel.md)。

这里切分的是权重参数的物理形状。材料以 `baa023ad` 快照说明机制：原先每个 TP 成员持有的权重片，还会沿输入维度进一步分到 PCP 组成员上。TP 即 tensor parallel，把一次张量计算分给多个设备完成；进一步切分权重后，原有前向 TP 分工仍保留。

本页仅依据归档材料中的文档与代码摘录整理，未直接复核上游源码，也没有设备运行结果。

## 事实表

| 项 | 值 | 意味着什么 |
| --- | --- | --- |
| 参数类型 | 材料中的声明为 `bool` | 用布尔值控制该分片机制；材料不足以判断其他输入类型的校验行为 |
| 机制讲解范围 | `baa023ad` 的 SFA-PCP 路径 | 下文的加载与前向行为限定于这份快照 |
| 设置时机 | 服务启动时 | 它会改变加载时的参数形状，不能按请求临时切换 |

| 输入宽度约束 | TP 局部输入宽度须能被分片域成员数整除 | 无法均分时抛出 `RuntimeError` |

## 为什么存在

### 保存的权重怎样变小？

假设一次输出投影原本已经按 TP 切过。对某个 TP 成员而言，它仍持有一片矩阵，输入向量与这片矩阵相乘，产生该成员负责的部分结果。这个开关在这片矩阵内部继续沿输入维度切分，让 PCP 组成员分别保存其中一段。

材料中的加载方法在模型加载权重之前调整参数尺寸，再由替换后的加载器选取连续的 checkpoint 切片。checkpoint 是保存模型权重的文件；这里直接选择目标局部片，不先把完整的 TP 局部 checkpoint 权重装入该参数后再切一次。加载器保留原有前向 TP 元数据，因此加载时增加的分片层次不会取代前向 TP 分工。

这一做法减少了目标参数的常驻权重范围，但不能单凭这段加载逻辑判断整模型加载峰值：参数构造、其他权重和临时缓冲的分配还需要另外检查与测量。

### 不拼完整权重，怎样算出同一个结果？

下面只用一个示意矩阵说明局部分片与结果相加的关系，设一个 TP 成员内部的输入宽度为 4，输出宽度为 2，PCP 组有两个成员。[A]

输入向量为：

```text
x = [1, 2, 3, 4]
```

按数学上的“输入维 × 输出维”写权重：

```text
W = [[1, 0],
     [0, 1],
     [1, 1],
     [2, 0]]
```

完整投影沿输入维相乘并求和，得到：

```text
xW = [1×1 + 2×0 + 3×1 + 4×2,
      1×0 + 2×1 + 3×1 + 4×0]
   = [12, 5]
```

现在沿输入维把矩阵切成两片。成员 0 保存前两行，用输入的前两个数计算；成员 1 保存后两行，用输入的后两个数计算：

```text
成员 0：[1, 2] × [[1, 0], [0, 1]] = [1, 2]
成员 1：[3, 4] × [[1, 1], [2, 0]] = [11, 3]
```

两个结果的形状都已经是输出宽度 2，但各自只包含一部分乘积之和。按位置相加得到 `[12, 5]`，与完整投影相同。[D]

材料第 95—98 行对 decode 的说明正是这一结构：decode token 在 PCP 成员间复制，每个成员只投影自己的输入切片，再通过 PCP All-Reduce 重建原有的 TP 局部结果。All-Reduce 是一种集合通信操作，这里让组内成员按位置求和，并让每个成员取得合并后的结果。启用 TP 时，后面仍要执行正常的行并行 TP 归约。

这个示例说明代数关系，不代表实际量化计算的误差或设备上的逐位一致性测试。

### 为什么还需要聚合后的权重视图？

局部权重适合上述“各算一部分，再合并结果”的路径；实现也保留了先聚合权重、再执行投影的路径。

材料第 73—78 行的判断条件是：权重切换已经启用，并且 attention 状态既不是 `DecodeOnly`，也不是 `SpecDecoding`，才调用完整 o_proj 权重聚合。因此，按阶段解释时必须保留状态条件，尤其不能把投机解码状态归入“必定聚合权重”的情况。

材料第 247 行还说明，DSA-CP 不受此开关控制，其既定策略是 prefill 聚合完整 o_proj 权重、decode 使用局部权重。这个配置项控制的是 SFA-PCP 的可选行为，不能当作所有上下文并行路径通用的输出投影开关。

## 开了的代价

### 节省常驻权重，换来哪些通信？

进一步分片后，各成员保存的目标权重范围变小，但计算时仍须形成完整结果。材料展示了两种补全方式：

- 满足聚合条件的前向先收集各成员的权重片，形成完整的 TP 局部权重视图。这会产生权重通信，也需要容纳聚合后的权重。
- 材料说明的 decode 路径使用局部权重计算，再通过 PCP All-Reduce 合并部分结果；启用 TP 时，正常的 TP 归约仍保留。

所以收益不能只看常驻权重减少多少，还要比较权重聚合、结果归约及临时内存的代价。材料没有显存、时延或吞吐实测，不能据此给出净节省量或推荐阈值。

### 哪些条件会直接报错？

材料列出的两项检查都会抛出 `RuntimeError`：

1. TP 局部输入宽度无法被分片域成员数整除，错误消息以 `Cannot split the TP-local input width across the requested parallel domain` 开头，并带出输入宽度和成员数。
2. 实际线性方法不属于 `WeightSwitchMixin`，或未声明支持权重切换，错误消息以 `Weight switching requires a weight-switch capable linear method` 开头。

这些检查意味着，配置值能够写入，不等于实际投影层与所选计算方法就能运行。需要核对具体模型的输入宽度和实际线性方法。

### 当前材料还不能回答什么？

以下事项仍待补充证据：

- **发布版本边界：** 材料不足以分别确认 v0.23 维护分支、v0.26 分支及 main 开发主线的完整行为；这些快照也没有足够依据映射到在册版本，因此本草稿不填写 `verified`。
- **运行默认值：** 已知静态声明存在差异，但缺少各快照的配置处理与实际启动结果。
- **组合兼容性：** 缺少完整模型、量化方法和其他上下文并行路径的逐项核验。
- **GLM 双机适用性：** 材料没有证明固定 GLM-5.3-Flash 双机部署能够启用此项，不能把主线部署数字用作本开关的收益依据。
- **工程收益：** 需要实测加载峰值、稳定运行时显存，以及不同请求负载下的通信和时延，才能判断是否值得启用。

本草稿的机制依据集中在归档材料第 13—18、73—78、95—98、158—179、215—218 和 247 行；静态默认值对照位于第 322—328 行。上述位置用于定位摘录，不替代对原始源码及版本映射的后续核验。
