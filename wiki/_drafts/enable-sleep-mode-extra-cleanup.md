## 一句话

这个开关让 [Sleep Mode](../concepts/sleep-mode.md) 在暂停推理时进一步清理通信资源和图工作区，把更多 NPU 显存让给训练；恢复推理时，则需要承担重建这些资源的时间。

HCCL 是昇腾集合通信库，负责组织设备间的数据交换；这里清理的是它的通信组资源。ACL Graph 是昇腾上捕获并回放一组计算操作的机制，图工作区是其执行需要的资源。额外清理针对这些资源，并不代替原有的权重与缓存休眠处理。

本稿仅根据给定的本地摘录整理，没有直接核读上游文件或进行设备实测。材料能支持固定源码快照之间的比较，尚不足以认证整个发布分支。

## 事实表

| 项 | 值 | 意味着什么 |
| --- | --- | --- |
| 旧配置入口 | 顶层 `enable_sleep_mode_extra_cleanup` | 所给旧配置片段直接从 additional_config 读取它 |
| 嵌套配置入口 | `rl_config.sleep_mode_extra_cleanup` | 所给迁移后文档明确移除了旧顶层键 |
| 缺省行为 | 所列配置片段均为关闭 | 未显式启用时，不进入这条额外清理路径 |
| 嵌套入口的执行条件 | enabled 与 sleep_mode_extra_cleanup 同时为真 | 只开清理子键，管理器不会执行额外清理 |
| ACL Graph 清理条件 | 管理器检查 use_aclgraph | 开启额外清理不代表一定执行图清理 |
| 图重新捕获条件 | tags 为 None，或包含 kv_cache | 只唤醒 weights 的阶段不会重新捕获图 |
| 带生命周期锚点的 HCCL 清理 | 锚点建立成功，且 MoE 拆卸准备成功 | 开关已启用，也可能跳过本轮 HCCL 清理 |
| 单 rank 的锚点路径 | 返回 False | 在该实现中跳过本轮 HCCL 清理 |

这里的 rank 是分布式执行成员的编号；单 rank 表示该执行范围内只有一个成员。tags 是唤醒调用指定的资源标签，用来区分恢复权重还是恢复 KV cache。KV cache 保存后续推理所需的历史状态。

配置读取与缺省值见材料第 4、549、645—646 行；嵌套入口的双重条件见第 144—147、677—683 行。图清理与重新捕获条件见第 39—41、63—69 行。生命周期锚点及跳过条件见第 736—740、756—758、812—818 行。

## 为什么存在

训练与推理共用设备时，推理暂停之后，通信组和图工作区仍可能占用训练需要的显存。额外清理把这些资源也纳入休眠处理：休眠时释放，唤醒时恢复。它解决的是暂停期间的资源让出问题，而不是请求运行期间的计算加速问题。

材料中的 Worker 片段显示，额外清理管理器先执行，随后才调用显存分配器的 sleep。即使额外清理条件不成立，分配器仍会执行原有的休眠处理。因此，“额外清理关闭”和“没有执行休眠”是两种不同状态。

### 配置条件怎样决定实际行为？

对采用嵌套配置入口的片段，可以逐项判断：

| enabled | sleep_mode_extra_cleanup | 是否调用额外清理管理器 |
| --- | --- | --- |
| false | false | 否 |
| false | true | 否 |
| true | false | 否 |
| true | true | 是 |

两个条件都成立，只表示进入管理器。随后是否清理 ACL Graph，还要看是否使用对应图路径；是否实际拆卸 HCCL 资源，还取决于该快照的运行条件与保护逻辑。

### 休眠与唤醒怎样改变资源状态？

材料中较早的管理器片段先按图模式条件清理 ACL Graph，再调用 HCCL 清理。所示 HCCL 路径要求分布式能力可用且已经初始化；满足条件后，等待尚未完成的流水线发送，清空发送记录，同步 NPU，再调用销毁逻辑。等待与同步使前面的设备操作完成后再进入资源拆卸。

带生命周期锚点的实现增加了保护步骤。锚点是清理周期中保留的通信资源；如果无法建立锚点，或者 MoE 的 HCCL 拆卸准备失败，就跳过本轮 HCCL 清理。MoE 是用多个专家模块与路由机制组织计算的模型结构。单 rank 路径也会使锚点检查返回 False，从而跳过这轮 HCCL 清理。

唤醒还可能分阶段进行。材料中的 level 2 注释说明，先恢复权重，供外部加载新权重；恢复 KV cache 后才重新捕获图。对应代码在 tags 非空且不含 kv_cache 时直接返回，避免在只恢复权重的阶段捕获图。带锚点的实现也把锚点保留到 KV cache 恢复、图重新捕获完成之后再释放。

这些是不同快照中的实现片段，不能把较早的拆卸顺序和较后的保护逻辑拼成未经核对的统一调用链。

## 开了的代价

主要代价是唤醒更慢。休眠时释放的通信资源需要恢复；使用 ACL Graph 时，模型状态恢复后还需要重新捕获图。若训练更需要休眠期间的显存，可以考虑这一取舍；若频繁切换且更看重恢复推理的速度，材料中的文档建议保持关闭。

材料没有提供可复算的显存节省量或唤醒延迟增量。模型权重大小、KV cache 预算也不能直接当作这个开关的收益；量化收益需要在目标模型、通信布局和图模式下分别测量。

### 哪些模型风险需要保留？

材料所标 2ed6cbba 快照的发布说明记录：DeepSeek-V4 配合额外清理使用 Sleep Mode，可能在唤醒后无法恢复，并说明 Sleep Mode 主要面向训练场景。该风险应随此快照保留，不能据此认定所有模型都会失败，也不能认定后续快照已经修复。
