GLM-5.3-Flash 是本知识库贯穿讲解的模型。认识它，需要同时看两件事：输入在一层里经过哪些计算，以及这些计算为下一轮保留什么历史状态。

token 是分词器输出的离散符号，通常以整数编号表示；模型计算时使用与这些编号对应的向量。向量经过一层又一层变换，形成后续计算所需的中间表示，称为隐藏表示。本页关注一层内部的分工，以及材料中能确认的实现条件。

本次材料包含模型相关源码摘录与部署教程，但没有提供完整模型配置，也没有完整展示模型名称到实现类的注册关系。因此，下文区分“摘录直接展示的实现行为”与“仍需配置或注册入口确认的模型事实”，不据此补出整模型层数、专家数或参数量。

## 一层里的注意力和前馈计算怎样分工？

attention 利用查询与键计算匹配权重，再按权重汇合值向量，使当前位置能够使用历史信息。不同注意力机制会改变历史如何表示、怎样更新，以及本轮访问哪些位置。

MLP 是对每个位置独立施加的前馈变换，常包含矩阵乘法与非线性计算。MoE 则用多个专家和路由机制组织这部分计算；在稀疏 MoE 中，每个输入位置只选择部分专家。这里的“专家”是执行前馈变换的模块。

材料中的层构造代码分别决定注意力类型和前馈类型：

- 注意力分支调用层类型判定函数，在 KDA 与 MLA 之间选择。
- 前馈分支优先读取配置中的逐层类型列表；没有非空列表时，再依据稠密层与稀疏层的分界配置选择。
- 进入 MoE 分支，还要求模型启用 MoE、专家数已设置，并且当前前馈类型为 sparse。

这两次选择回答不同问题：注意力决定怎样利用历史，前馈计算决定怎样进一步变换当前位置的表示。不能仅凭某层使用稠密前馈计算，就推断它采用哪一种注意力。

逐层前馈类型列表还有一个具体边界：当层索引超出列表长度时，所示实现沿用列表最后一项。核对模型结构时，应检查实际配置列表及其长度，不能只看列表开头几项。

完整的层分布仍需模型配置确认。材料只展示了注意力类型判定函数的调用，没有展示该函数如何为每个层索引作出选择。

## KDA 与 MLA 为什么需要分别理解？

KDA 的全名是 Kimi Delta Attention，是采用按通道遗忘的 delta 更新注意力机制：它通过矩阵状态汇总历史，并按当前输入更新状态。理解这一机制，需要接续矩阵状态、误差修正与遗忘门的基础，详见 [KDA](../concepts/linear-attention.md)。

MLA 的全名是 Multi-head Latent Attention，通过压缩潜在表示及相应投影组织多头注意力。压缩潜在表示是一种较紧凑的中间表示；压缩表示的维度，与本轮读取多少历史位置，是两个不同问题，详见 [MLA](../concepts/mla.md)。

材料中的 KDA 初始化代码要求提供线性注意力配置，并要求注意力头数能够被 tensor parallel 大小整除。tensor parallel（TP）是把一次张量计算分片到多个设备，再通过相应通信组合结果的执行方式。这里的整除条件意味着，配置的注意力头必须能按当前 TP 规模分配；不能把任意 TP 大小都视为可用选择。

MLA 摘录展示的是带索引池的路径。索引器负责产生后续注意力要访问的位置索引；KPool 则把历史位置组织成池，供索引过程使用。这条路径同时要求查询低秩投影配置、缓存配置和索引选择配置存在。

低秩投影是通过较小的中间维度组织投影计算。摘录前面虽然出现了没有查询低秩配置时的投影分支，但后面的完整 Indexer KPool MLA 构造仍会检查并拒绝缺少该配置的情况。判断一条路径是否支持某种配置，要读完这条路径的约束，不能停在局部条件分支。

## 索引池为什么还要保留未完成的尾部？

索引池把若干位置组织成一组。当前输入可能只填满了部分组：已经完成的历史池可以参与历史选择，最新的不足一组的位置则仍属于未完成池。

所示索引输出把两部分拼接起来：

1. 历史池选择结果展开得到的位置索引。
2. 当前未完成池中的尾部位置索引。

因此，最终输出不只有历史池的选择结果；最新的尾部位置还有单独的处理路径。

用一组示意数走一遍。假设每池容纳 4 个位置，位置从 0 开始编号，当前处理到位置 9。位置 0–3 构成一池，4–7 构成另一池，8 和 9 属于尚未填满的当前池。历史选择结果与尾部位置 8、9 拼接后，形成后续计算使用的位置索引。示意设定及其推导见页末来源说明。

摘录还展示了输出布局中的两个细节：尾部槽位不足时用 −1 填充，拼接结果转换为 32 位整数。这里的 −1 是无效槽位标记，不代表一个真实历史位置。

这一例子只演示尾部边界。材料没有给出该示例的历史池评分和选择结果，因此不能继续推演哪些历史池一定被选中。

## 索引缓存为什么不能统一按一种精度计算？

数值精度描述一个数如何编码存储。BF16 是一种 16 位浮点格式，FP32 是一种 32 位浮点格式；计算链可以在不同阶段使用不同格式。

材料明确把压缩完成的 Indexer K 缓存设为 BF16，并注明不再为这一缓存分配量化缩放系数缓存。这个结论只针对所示索引缓存，不能扩展为整模型的全部历史状态。

另一段实现注释说明，在其讨论的 A3、A5 路径中，生成 K 与 gate 的计算链主要使用 FP32。gate 是调节后续更新的门控量。输入先转换为 FP32，再供两个投影使用；压缩完成的池进入索引缓存时，才舍入为 BF16。

这条链还有局部例外：RoPE 部分使用 BF16。RoPE 是通过旋转向量编码位置信息的方法。注释说明，该算子对 FP32 输入产生的旋转差异不只是舍入级别，因此旋转部分维持 BF16；不参与该旋转的部分保留 FP32。

这会影响显存核算。压缩完成的索引池、计算中的中间张量与尚未完成的尾状态，应分别核对形状、元素类型和生命周期，不能只看到一个 BF16 缓存声明，就给整个索引机制套用相同的字节数。

## 在 GLM 双机主线上，这些机制怎样接起来？

本知识库的固定主线使用两台 A2 服务器，每台 8 个设备，采用 W8A8 权重与激活量化。W8A8 表示权重与激活使用相应的 8 位量化计算方案；它不意味着所有历史状态、索引缓存和临时张量也都是 8 位。

硬件与分组的完整说明见[双机部署页](../concepts/glm-5-3-flash-two-node.md)，模型与部署的固定依据见[来源基线](../sources/glm-5-3-flash-baseline.md)。请求何时进入逐层计算、何时采样并开始下一轮，沿[单请求主线](../concepts/one-request.md)接续阅读。本页不重算这些页面负责维护的整机显存和通信账。

本次材料中的后续教程明确列出：GLM-5.3-Flash 的 W8A8 权重在 A2 上需要两台服务器，每台配有 8 个 64 GB 设备。该教程还分别列出 A3 和 950DT 的其他部署条件。这些是教程给出的资源要求，不能当作本次已完成的硬件运行结果。

后续教程还介绍了实验性的稀疏注意力上下文并行。上下文并行是沿输入位置或历史状态分配工作的机制；教程中的具体做法是在 TP 组内分片稀疏注意力的查询位置，同时保持主要历史缓存、索引池和尾部缓存复制。KDA 继续沿用原有 TP 路径。

这里减少的是各设备承担的查询工作，并没有同时把上述缓存分片。教程要求 prefill context parallel 和 decode context parallel 的大小都保持为 1；实验入口不能直接解释成这两类通用上下文并行已经可用。

## 阅读实现时，哪些范围需要分开判断？

**主干连接与 MTP 连接需要分别检查。** residual 是把子层输入通过直接路径与子层输出相加的连接方式。mHC 则约束多路残差连接的混合与写回。材料中的前向代码在“未启用 mHC”或“当前是 MTP 层”时进入普通残差处理分支。MTP 是多 token 预测结构，推理时可用配套模块生成供目标模型验证的候选 token。仅凭主模型启用了 mHC，不能推断 MTP 层也走同一路径。

**候选生成中的索引复用有条件。** 所示 proposer 是组织候选 token 生成的组件。首步之后，只有启用索引共享、取得草稿模型对象，并且该对象提供相应接口时，它才设置跳过后续 top-k。top-k 是选取得分最高的若干项；这里跳过的是特定路径中的选择工作，不能概括为所有 MTP 都跳过索引器。

**模型实现存在与部署组合可用需要不同证据。** 模型文件能说明某段计算如何实现；配置校验说明哪些输入组合被接受；部署教程说明某套配方的预期条件。教程中的硬件要求与实验开关，也不能代替实机验证记录。

## 对照源码

### 怎么开

材料中的教程说明，GLM-5.3-Flash 在其所述 Ascend 版本范围内仅支持 Model Runner V1。Model Runner 是把本轮输入组织起来并执行模型的组件；教程中的 A3 脚本显式设置 `VLLM_USE_V2_MODEL_RUNNER=0`。

实验性稀疏注意力上下文并行通过以下附加配置启用：

```text
--additional-config '{"enable_dsa_cp": true}'
```

同一段教程要求 prefill context parallel 与 decode context parallel 大小都为 1。材料没有给出可在此完整复述的双机启动命令，因此这里只保留已提供的入口和条件，不拼装未经运行的命令。

### 会报什么错

所示 Indexer KPool MLA 构造会检查三项必要配置，缺失时分别抛出：

```text
GLM-5 Indexer KPool MLA requires q_lora_rank.
GLM-5 Indexer KPool MLA requires cache_config.
GLM-5 Indexer KPool MLA requires indexer configuration.
```

另一处 Ascend 索引器路径在启用 FP4 缓存选项时抛出：

```text
Ascend GLM-5 Indexer uses BF16 Q, not FP4.
```

这条错误只说明该索引器路径使用 BF16 查询并拒绝所示 FP4 选项，不代表整模型或所有后端的 FP4 支持范围。

KDA 初始化还包含配置存在性与头数整除断言：线性注意力配置不能为空，注意力头数必须能被 TP 大小整除。

### 开销和什么时候别开

实验性查询分片保持主要历史缓存、索引池和尾部缓存复制。因此，评估它时应分别检查查询计算分担和缓存显存占用，不能预期该入口自动按设备数降低这些缓存的单设备容量。

索引路径中的 FP32 中间计算、BF16 压缩缓存及尾部处理也应分别计量。材料不足以给出这条链的完整峰值显存、通信量或速度收益。

材料同样没有提供实验性上下文并行的性能比较，不能据此作普遍开启建议。需要结合具体硬件、输入长度、批次和执行版本验证收益。
