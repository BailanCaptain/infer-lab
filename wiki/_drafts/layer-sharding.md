Layer Sharding 把指定 Linear 模块的权重按层号轮流安排到通信组中的设备上常驻，其他设备需要计算时再通过广播取得权重。Linear 是用权重矩阵把输入向量映射为输出向量的计算模块；这里改变的是权重的存放与取得方式。

本页依据本地材料中的历史实现摘录解释机制。材料包含配置校验、文档和部分初始化代码，尚不足以完成四个社区版本的逐项验证。源码快照之间的差异与证据缺口集中列在页末。

## 按层分配权重，究竟分的是什么？

模型由多个计算层连接而成，各层可以包含名字相同、权重不同的 Linear 模块。例如，第 0 层和第 1 层都可能有一个名为 o_proj 的输出投影模块，但它们各自持有自己的权重矩阵。

材料中的 Layer Sharding 按层号决定这些权重的常驻位置。设通信组有 K 个成员，第 i 层对应权重的常驻成员是组内编号 i % K；% 表示取余数。通信组是共同参与通信的一组设备，组内编号只在这个组中有意义。

假设一个组有两台设备，选择了连续四层中的同一种 Linear 模块，则常驻分工如下：

| 层号 | 常驻成员的计算 | 常驻位置 |
| --- | --- | --- |
| 0 | 0 % 2 = 0 | 组内成员 0 |
| 1 | 1 % 2 = 1 | 组内成员 1 |
| 2 | 2 % 2 = 0 | 组内成员 0 |
| 3 | 3 % 2 = 1 | 组内成员 1 |

这个分工表描述权重的长期归属。执行某一层时，其他成员仍可能需要取得该层权重，并为它准备临时存储。材料中的文档说明，初始化阶段可使用共享占位张量，前向计算时通过异步广播取得真实权重。

广播由一个指定成员把同一份数据传给组内其他成员。异步广播允许通信发起后继续安排其他工作；真正使用权重之前，计算仍须满足数据已经可用的条件。

## 为什么少放一些权重，却可能算得更慢？

如果每个成员都长期保留各层相应权重，设备之间就会出现重复存储。Layer Sharding 让不同层的权重由不同成员常驻，以减少这部分重复。

代价是计算前必须取得权重。通信需要传输数据，也需要与计算协调；若数据尚未准备好，后续计算就要等待。异步传输提供了重叠通信与计算的机会，但能隐藏多少开销，取决于通信量、链路和可重叠的计算。

材料中的性能提示建议与 FlashComm2、DSA-CP 配合，并警告缺少这些配合时可能出现明显性能下降。这条提示没有给出可复用的实测速度，也没有证明任意配置下都能把广播时间完全隐藏。

因此，评价这个机制要同时看两个问题：减少了多少长期常驻权重，以及为取得权重增加了多少通信和等待。只比较常驻权重大小，无法判断端到端时延。

## 用两台设备，怎样走完一次权重取得与计算？

继续使用前面的两成员示意，考察第 1 层的一个 Linear 模块。为便于手算，设它的输入是一个包含两个数的行向量，权重是一个两行两列矩阵：

\[
x=[2,\ 1],\qquad
W_1=
\begin{bmatrix}
1 & 3\\
4 & 2
\end{bmatrix}
\]

按示意中的层号规则，第 1 层权重由组内成员 1 常驻。

成员 0 要执行这个 Linear 模块时，需要先取得 \(W_1\)。广播以成员 1 为来源，把矩阵中的数传给其他组成员。成员 0 得到可用权重后，才能计算：

\[
y=xW_1
=[2\times1+1\times4,\ 2\times3+1\times2]
=[6,\ 8]
\]

结果向量保存在执行这次计算的成员上，供后续计算使用。权重广播只负责提供权重，不会替成员 0 完成矩阵乘，也不负责汇合不同成员的输出。

这一例子把两件事分开了：层号取余决定从谁取得权重，矩阵乘决定取得权重后怎样得到输出。实际实现还要管理占位存储、临时缓冲区与通信完成时机；材料没有完整展开前向调度，不能从这个手算例子推定具体的缓冲区复用顺序。

## 初始化时，为什么还会广播和处理权重？

材料中的加载后处理代码也执行广播。它按照层号取余选择来源成员，把该层真实权重广播出来，再调用量化方法的加载后处理。量化方法在这里指负责相应低精度权重处理的实现。

这说明初始化过程也可能需要完整权重参与处理。随后，代码会根据是否为来源成员以及预取窗口等条件保留、关联或释放存储。摘录中的一个分支会释放非来源设备上的权重，最后还会释放共享占位张量。

所以，登记时使用轻量占位张量，不等于整个模型加载过程始终只占这些空间。加载期可能出现真实权重、处理所需存储和临时缓冲区；运行期也需要为即将使用的权重准备空间。材料不足以给出完整加载峰值或运行期峰值。

同一实现还要求一个权重系列至少包含一层，系列中的层号连续，并限制预取步数。这些约束属于具体存储与调度实现，不能从“按层号取余”这一条规则中直接推出来。

## 它与同层权重切分有什么区别？

Layer Sharding 按层决定某份权重由哪个成员常驻；同层权重切分则把同一个权重矩阵沿某个维度拆给多个成员。两者处理的存储对象和运行时配合方式不同。

材料中的另一个快照保留了 enable_pcp_o_proj_weight_sharding：文档描述它在加载时把 O-proj 权重分到 PCP 组中，并在运行时切换本地与汇集后的权重视图。PCP 是沿上下文位置分工的一种 prefill 执行路径。该快照的文档默认值为 False，并明确说这个开关不改变当时 DSA-CP 的策略。

因此，“移除 Layer Sharding”并不表示所有权重分片机制都被移除。名称中都出现 sharding，也不足以证明两个配置可以互换。另一机制的配置入口见 [enable_pcp_o_proj_weight_sharding](../params/enable-pcp-o-proj-weight-sharding-8528cf5af9c6.md)。

## GLM 双机案例能直接采用它吗？

本地材料包含 GLM5 教程的一项组合限制：启用 FlashComm1 时，layer_sharding 不能包含 o_proj。另一个摘录则规定，FlashComm2 与非空 Layer Sharding 联用时，列表必须严格等于仅含 o_proj 的单项列表。

这两条限制分别针对 FlashComm1 和 FlashComm2，不能合并为一个笼统的“FlashComm 限制”。同样，GLM5 教程中的说明不能直接证明 GLM-5.3-Flash 固定双机部署支持这一历史机制。

现有材料没有建立本机制与 GLM-5.3-Flash 固定部署源码之间的对应关系，也没有提供实机结果。因此，本页不为该双机案例给出启用命令、节省显存数或性能预测。要形成部署参考，还需要核对固定执行侧快照中的配置入口、模型接入和通信路径。

## 哪些状态需要分开判断？

**配置被接收、指定模块参与分片和运行性能达标，是三个不同结果。** 材料中的 MLA 初始化路径会在指定模块名不在传入模块集合中时发出警告，并跳过该模块。MLA 是用压缩潜在表示组织多头注意力的一种机制；这里提到它，是因为摘录展示了该注意力实现中的模块登记入口。

**来源成员的常驻权重与其他成员的临时权重需要分别计入。** 层号分工说明长期归属，不能据此认为其他成员在整个前向过程中都不占用真实权重空间。

**加载后处理中的广播与前向异步广播属于不同阶段。** 前者的代码片段证明初始化处理需要什么，后者在材料文档中说明运行时取得权重的方式。两者不能互相替代为完整调用链证据。

**计划弃用、已经移除和文档索引残留也应分别判断。** 发布说明表达计划时，不能写成当时已经删除；某个索引仍列出名字，也不足以证明运行入口和所有配置组合仍然有效。

## 对照源码

### 怎么开

材料中有按模块名填写列表的配置示例，也有代码把未配置值读取为 None；但同一批材料的参数表把类型写为 dict、默认值写为 {}。这些表述存在冲突，当前草稿不把其中任一种写成完整输入契约。[!]

在材料标注为 `2c59ff10` 的快照中，非空配置要求存在 KV 传输配置，且角色严格等于 `kv_producer`，即 PD 分离中的 P 端。PD 分离把提示词处理和持续生成分给不同执行组，角色背景见 [PD disaggregation](../concepts/pd-disaggregation.md)。这项角色条件针对非空配置，不应扩写成所有输入都会触发同一检查。

模块名还必须能被相应模型接入路径识别。材料中的 MLA 路径遇到不在传入模块集合中的名字时，会警告并跳过，不能仅凭配置文本判断实际分片范围。

### 会报什么错

材料展示了以下检查和提示：

| 触发条件 | 结果 |
| --- | --- |
| 非空配置缺少 KV 传输配置，或角色不等于 `kv_producer` | 抛出 `ValueError`，说明只能在 PD 分离的 P 端启用 |
| FlashComm2 联用的非空列表不严格等于 `["o_proj"]` | 抛出 `ValueError`，提示只支持 o_proj 单项配置 |
| 配置模块名不在 MLA 接入路径的传入模块集合中 | 警告并跳过该模块的分片 |
| 系列没有任何层 | 断言失败，消息为 `No layers in the series` |
| 系列层号不连续 | 断言失败，消息为 `layer_idx must be consecutive` |

预取步数的实际断言为：

\[
0\leq \text{prefetch\_step}\leq
\max(0,\text{num\_layers}-2)
\]

错误消息只写了区间 `[0, num_layers - 2]`，没有表达 max 的保护；解释允许范围时应以断言表达式为准。该范围和连续层号要求来自材料第 562–571 行。

### 开销和什么时候别开

需要按配置组合判断以下边界：

- **通信开销：** 材料提示缺少 FlashComm2、DSA-CP 等配合时可能明显降速，但未提供实测结果。
- **FlashComm1 组合：** 材料中的 GLM5 教程明确限制启用时不能把 o_proj 放入分片列表；这是该教程场景的限制。
- **RFork 组合：** 材料说明 RFork 权重传输不支持 Layer Sharding。同时指定 RFork 加载格式与 Layer Sharding 时，会绕过 RFork，改用默认模型加载器。
- **显存评估：** 占位张量和最终常驻分工不足以确定加载峰值，还需核对加载后处理、预取窗口与临时缓冲区。

没有这些运行期证据时，不能以“配置能启动”作为机制生效或性能可接受的判断标准。
