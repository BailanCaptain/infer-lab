LM head 接收模型计算得到的隐藏向量，为词表中的 token 计算分数。这些分数称为 logits：它们还不是概率，也还没有决定下一个输出 token。

本页解释输出投影、词表分片与分数汇集之间的关系，并对照材料中摘录的实现分支。材料包含多个固定提交的代码片段，但没有提供这些提交与四个在册社区分支的完整映射；因此，下面按实际可见的快照说明行为，不据此认定整页已经完成某个社区版本的核对。

## 隐藏向量怎样变成每个 token 的分数？

[隐藏向量](../concepts/layers-and-hidden.md)是模型为输入位置计算的中间表示。它的各个维度共同表示当前位置的信息，并不直接对应词表中的 token。LM head 完成最后一次映射：输入是隐藏表示，输出的每个位置对应一个词表编号。

若一次送入输出头的隐藏表示有 N 行，每行长度为 H，那么输入形状是 N×H。设词表有 V 个 token，输出便有 N×V 个分数。这里的 N 是本次参与输出投影的位置数；仅凭这两个形状，不能把它等同于请求数或提示词长度。

[矩阵乘](../concepts/matmul-and-weights.md)提供了理解这次映射的基础：一个输出分数由输入向量的各个分量与对应权重相乘，再求和得到。实际实现还可能通过量化方法执行投影，并处理偏置；这些实现选择不改变“把隐藏表示映射到词表分数”这一职责。

在材料展示的固定上游路径中，处理顺序是先应用输出头，再汇集分片得到的 logits，最后裁掉词表补齐的位置。补齐位置是为实现布局增加的额外槽位，不属于原始词表。

## 为什么要把词表分给多个通信成员？

词表分片把输出头的不同词表行交给不同成员持有。每个成员使用隐藏表示，计算自己负责的 token 分数；它得到的是输出矩阵的一部分列。

这里的 rank 是通信成员的编号，TP（tensor parallel）是把一次张量计算分给多个设备完成的方式。词表分片是这种分工的一种具体形式，基础概念见 [Tensor Parallel](../concepts/tensor-parallel.md)。

这种分工减少了单个成员需要持有的输出权重和本地计算范围，但引入了结果组织问题：后续步骤究竟需要完整词表分数，还是只需要某种筛选结果？不同答案会形成不同通信路径。

All-Gather 是收集各成员分片、让参与成员获得完整集合的操作，拼接本身不做加法。普通词表分片可以借此拼齐分数。复制输出头则让各成员各自持有完整输出权重；如果本地已经算出完整词表分数，再按词表分片方式汇集就没有必要。材料中的复制输出头分支正是对这种差异的处理。

## 用一组小数怎样看清本地打分和词表拼接？

以下是示意算例，设隐藏向量为 `[2, 1]`，词表只有四个 token。为突出矩阵乘与拼接，示例省略偏置和量化。[A]

四个 token 对应的输出权重行分别是：

```text
token 0： [1, 0]
token 1： [0, 3]
token 2： [1, 1]
token 3： [-1, 1]
```

假设 rank 0 持有前两行，rank 1 持有后两行，并且两者都获得这条隐藏向量。各成员本地完成以下计算：

```text
rank 0：
token 0 的分数 = 2×1 + 1×0 = 2
token 1 的分数 = 2×0 + 1×3 = 3
本地结果：[2, 3]

rank 1：
token 2 的分数 = 2×1 + 1×1 = 3
token 3 的分数 = 2×(-1) + 1×1 = -1
本地结果：[3, -1]
```

按词表编号拼接，完整 logits 是 `[2, 3, 3, -1]`。这里拼接的是不同 token 的分数；同一个 token 的点积已经在持有对应权重行的成员上算完，所以不需要把两个成员的结果逐元素相加。[D]

如果后续只执行贪心选择，也就是选择分数最高的 token，可以先在每个分片内选候选，再比较候选。此例中，rank 0 提交 token 1、分数 3，rank 1 提交 token 2、分数 3。若约定同分时选最低全局编号，结果是 token 1。[D]

材料中的一个 GLM5Next MTP 实现注释采用了这种分片候选比较思路。MTP 是用于提出多 token 预测候选的结构；这里展示的是其贪心草稿路径。注释将同分行为保持一致的条件明确限定为：词表分片连续，且按 rank 顺序排列。完整词表上的贪心选择与分片候选比较可以在这些条件下对应起来，但这段实现不能证明任意概率采样都能采用同样的归约方式。

## 输出头和 embedding 为什么不能仅凭形状判断是否共享？

[Embedding](../concepts/embedding.md)按输入 token 的编号读取向量；LM head 则把隐藏向量映射成各 token 的输出分数。两者的用途不同，即使权重形状能够对应，也仍需检查模型是否实际执行了权重绑定。

材料展示的绑定方法有两个分支。非 GGUF 分支把输出头的 weight 指向 embedding 的 weight，使两者引用同一份权重。GGUF 是这里单独处理的一种量化格式；对应分支直接返回 embedding 模块。

因此，绑定方法证明实现提供了共享能力。判断某个具体模型是否共享，还需要模型调用、配置和加载过程的证据。当前摘录没有完成 GLM-5.3-Flash 的这条证据链。

## 细粒度分片和 PCP 分片分别改变了什么？

普通词表分片以各成员计算自己的词表分数为基础。材料中的两类扩展进一步改变了权重放置或输入输出的分配方式，因此不能只用“最后拼一次分数”概括。

细粒度 LM-head TP 为输出头选择专门的通信分组。摘录展示的路径先沿第 0 维汇集隐藏表示，也就是先组织参与投影的输入行，再应用输出头。在未启用采样归约的分支中，随后执行 All-to-All。All-to-All 表示各成员按接收方分配数据，并收集其他成员发给自己的部分；它与把全部分片复制给每个成员的 All-Gather 有不同语义。仅凭当前片段，还不足以展开这一交换前后每个成员的完整张量布局。

PCP 是 prefill context parallel，即在处理提示词时沿上下文维度组织并行执行。材料中的 PCP 输出头权重分片需要同时满足模块匹配、分片开关启用和 PCP 大小大于 1。模块匹配使用名称前缀中的子串判断，但更早的“禁用 TP”分支可以直接选择复制模式，因此名字含有 head 并不保证发生分片。

这两类扩展有各自的条件与组合限制。PCP 输出头权重分片分支明确拒绝同时启用细粒度 LM-head TP；另一段配置校验则拒绝 batch-sharded sampling 与正值的细粒度 LM-head TP 配置同时启用。batch-sharded sampling 在该材料中指按 TP rank 分配采样输入的路径；其配置检查不能脱离这一条件，解释成所有输出头路径都互斥。

## GLM-5.3-Flash 的请求走到哪里会遇到输出头？

从模型计算进入输出选择时，隐藏表示需要转换成词表分数，随后才由 [Sampling](../concepts/sampling.md)决定输出 token。沿请求理解这两个职责，有助于区分“算出分数”和“选定结果”。

材料展示的 GLM5Next 构造代码只在流水线并行的最后一个 rank 创建输出头，其他 rank 放置缺失层占位模块。流水线并行是按模型计算顺序划分执行阶段的方式；在这一实现中，输出头属于末端阶段，而非所有阶段都各有一个可执行输出头。

固定部署依据中的执行侧快照包含这段构造逻辑，但当前材料不足以完整展开 GLM 双机每卡输出权重的形状、精度、显存占用及实际采样分支。这些数字需要直接核对模型配置、权重转换与加载链，不能用已有页面的对照文字补作本次证据。

## 哪些区别会影响对结果的理解？

**本地 logits 与完整词表 logits 的覆盖范围不同。** 一个词表分片的本地结果只覆盖该成员负责的编号；复制输出头的本地结果则可以覆盖完整词表。判断张量含义必须结合输出头布局。

**跳过汇集也可能跳过裁剪。** 材料中的提前返回分支直接返回输出头应用结果，没有继续执行后面的完整路径。调用者需要知道自己拿到的是哪一段词表、是否包含补齐位置。

**分数最高不等于已经完成所有采样处理。** 小算例演示的是贪心候选比较。概率采样的行为不能由这段贪心实现外推。

**代码分支可达与配置组合获准是两层问题。** 某个函数内出现了采样归约判断，不代表它与细粒度输出头分片一定允许同时启用；配置校验可能在更早阶段拒绝这一组合。

## 对照源码

### 怎么开

LM head 是模型构造的一部分。材料中的 GLM5Next 代码根据流水线 rank 决定创建输出头还是占位模块，不需要把它理解成一个单独启用的推理优化。

细粒度 LM-head TP 的判定函数检查 `lmhead_tensor_parallel_size > 0`。但进入具体通信路径还可能有额外条件：材料中的一个快照同时要求输出头的 TP 大小大于 1，以排除复制输出头。

PCP 权重分片则同时检查模块前缀、分片开关和 PCP 大小；`disable_tp` 优先返回复制布局。上述条件应当结合阅读，不能单凭一个开关判断实际布局。

### 会报什么错

材料明确展示了以下配置拒绝：

| 条件 | 结果 |
| --- | --- |
| 开启 `enable_reduce_sample`，同时将细粒度 LM-head TP 大小设为正值；适用于摘录中含该检查的快照 | 抛出 ValueError，要求关闭其中一项 |
| 已进入 PCP 输出头权重分片分支，同时启用细粒度 LM-head TP | 抛出 ValueError，说明两者不能组合 |
| 开启 `enable_batch_sharded_sampling`，同时将细粒度 LM-head TP 大小设为正值 | 抛出 ValueError，要求关闭其中一项 |

片段没有展示某项校验，不能据此断言对应快照允许该组合。

### 开销和什么时候别开

普通词表分片把本地投影与后续分数汇集分成两步；复制输出头已经持有完整词表分数时，材料中的实现会跳过这次汇集。

细粒度路径增加了隐藏表示的 All-Gather，并在所示条件下执行 logits 的 All-to-All。其收益需要与实际输入行数、权重布局和通信成本一起判断，当前材料没有提供硬件实测。

贪心草稿路径的候选比较旨在避免每轮形成并汇集完整词表分数。摘录提供的是实现注释，没有提供运行验证结果或性能测量，因此不能据此给出加速比例。
