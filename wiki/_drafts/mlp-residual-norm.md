MLP（前馈网络）对每个位置的隐藏向量施加变换；residual（残差连接）保留子层输入并参与后续合并，归一化则调整送入或送出子层的表示。这三件事共同组成一次更新，但不一定由同一个函数完成。

本页依据所给本地源码摘录，区分 MLP 内部计算、普通 residual 连接和 GLM 的 mHC 路径。请求中的 token 是按位置排列的离散符号，隐藏向量是模型为各位置维护的中间表示；这些表示沿模型各层继续更新。它们在完整请求中的位置见[一条请求](../concepts/one-request.md)，层间连接的背景见[层与隐藏表示](../concepts/layers-and-hidden.md)。

## MLP 算出的结果，为什么还不是整层的新表示？

材料中的 GLM 稠密 MLP 按以下顺序工作：输入先经过合并的 gate/up 投影，再经过 SiLU 门控激活，最后经过 down 投影，返回变换结果。投影是用权重进行矩阵乘，将输入映射到另一组表示；矩阵乘如何决定输出维度，见[矩阵乘与权重](../concepts/matmul-and-weights.md)。

gate 和 up 是门控计算的两路中间表示。合并投影让它们在同一步产生，随后由激活模块处理；down 投影把中间结果映射为后续需要的输出表示。所给摘录没有展开激活模块的内部实现，因此这里不把类名直接当作完整的数值计算说明。

MLP 的职责边界很清楚：展示的 forward 中没有归一化，也没有把原输入加回来。调用者负责安排这些操作。于是，“MLP 返回了什么”与“这一子层怎样更新隐藏表示”是两个需要分别回答的问题。

普通 residual 路径会保留一份输入，让 MLP 的变换结果与它相加。GLM 的 mHC 路径则由专门的入口和写回操作连接 MLP，不能统一写成一次普通相加。

## 为什么要保留输入，归一化又放在哪里？

普通 residual 连接提供一条直接保留输入的路径。经过这条路径，最终结果同时包含原表示和子层计算出的改变量。它需要保存参与相加的输入，并在子层计算后完成逐元素加法。

归一化的位置决定了哪一份表示经过调整。材料展示了两种实际存在的组织方式：

| 组织方式 | 计算顺序 | 直接影响 |
| --- | --- | --- |
| pre-norm，前置归一化 | 保存输入 → 归一化 → MLP → 加回保存的输入 | MLP 使用归一化后的表示，直接保留的路径使用原输入 |
| post-norm，后置归一化 | 保存输入 → MLP → 加回保存的输入 → 归一化 | 相加结果继续经过归一化 |

这里的 Norm 表示归一化操作；LayerNorm 和 RMSNorm 是具体的归一化方法。本材料展示了它们的调用位置，没有提供足以展开二者数学定义与数值对照的完整实现。

前置与后置改变的是计算顺序，不能只根据层中出现了归一化模块就判定采用哪一种。所给 GPT2Block 片段在 MLP 前调用归一化；OPT 的全连接分支则通过配置选择前置或后置。材料没有给出足以比较两者训练稳定性或推理性能的数据，因此这里不对优劣作判断。

## 用两个数，怎样看清 residual 的输入、输出与保存状态？

先只演示普通 residual 相加。设某个位置的输入为两个数，归一化和 MLP 的具体输出也作为教学设定给定；本例不推导它们内部怎样计算。[A]

```text
保存的输入 x             = [2, -1]
归一化后送入 MLP 的表示   = [1, -0.5]
MLP 返回的改变量          = [0.3, 0.4]
```

相加时，调用者取回保存的输入，按位置与 MLP 输出相加：

```text
第一个位置： 2 + 0.3  = 2.3
第二个位置：-1 + 0.4  = -0.6

更新后的隐藏向量 = [2.3, -0.6]
```

这个示意中，加回的是归一化前保存的输入。MLP 接收的归一化表示与 residual 路径保存的表示，承担不同职责。[A]

返回值还需要单独检查。材料中的普通 GLM 分支在 MLP 前保存 residual，计算后返回更新后的隐藏表示和这份 residual。因此，一个函数同时返回 hidden_states 与 residual，不代表它返回了两份相同的更新结果。沿源码阅读时，应追踪每次赋值发生在归一化之前、MLP 之前，还是相加之后。

## 带限幅的门控与普通门控有什么变化？

在固定 GLM 执行侧快照中，稠密 MLP 根据是否提供限幅值选择激活模块：未提供时使用普通 SiLU 门控模块，提供时使用带 clamp 的模块。clamp 指把数值限制在指定边界内。

这项变化发生在合并投影之后、down 投影之前，继承了“投影 → 门控激活 → 输出投影”的整体结构。它没有把归一化或 residual 相加移入 MLP。

所给主题摘录没有展开 clamp 模块的内部计算，尚不能据此确认限制哪一路输入、上下界是否对称，以及门控相乘后的范围。最终 MLP 输出还要经过 down 投影，其数值边界也需要结合该投影分析。具体阈值与限幅效果应在补齐激活实现后展开。

材料还暴露了一个实现核对点：替换表中的键与实际类名存在不一致。仅看到替换表里有相近名称，不能据此确认带限幅模块已经切换到 Ascend 实现。具体名称及待核范围保留在页末。

## GLM 双机案例里，MLP 怎样接入一次逐层前向？

本节只使用固定执行侧快照中直接展示的连接关系。完整双机部署与请求路径分别由[模型来源基线](../sources/glm-5-3-flash-baseline.md)和[一条请求](../concepts/one-request.md)维护；本材料没有提供足以重算每卡形状、通信字节数与显存的证据。

在固定快照中，普通路径与 mHC 路径有明确分支。mHC 是约束多路 residual 混合与写回的一种连接机制，其完整状态结构需结合[层与隐藏表示](../concepts/layers-and-hidden.md)理解。

**普通路径与 MTP 例外。** MTP 是用于多 token 预测、可参与投机草拟的模型结构。所给代码在未启用 mHC 或当前为 MTP 层时，先完成注意力结果与 residual 的相加，再保存这时的隐藏表示，经过归一化与 MLP，最后加回保存的表示。

**mHC 且非 MTP 的路径。** 代码先调用入口操作准备 MLP 的输入及后续合并所需状态，然后归一化、执行 MLP，最后调用写回操作。这里没有展示普通路径中的显式 residual 相加。

这两个分支说明，MLP 内部的三步变换可以相同，外围的状态组织却不同。材料没有给出 mHC 入口与写回操作的完整实现，因此本页不据此推导混合系数、流数或完整数学等价关系。

层末的最终归一化也要按实际调用理解。所给模型片段在最后一个流水线执行成员上，对隐藏表示单参数调用最终归一化；其他成员返回中间张量。流水线执行成员是按模型计算顺序承担某段计算的进程角色，背景见[流水线并行](../concepts/pipeline-parallel.md)。

## 哪些说法需要附上实现条件？

**“MLP 自己完成归一化和 residual 更新。”** 所给 GLM 稠密 MLP 只展示投影、激活和输出投影；归一化与连接由外部层代码安排。

**“所有模型都先归一化再执行 MLP。”** 所给 OPT 分支可以在相加之后归一化，必须检查配置与调用顺序。

**“只要归一化模块支持融合加法，这次调用就融合了 residual。”** 材料中的 AscendRMSNorm 仅在传入非空 residual 时进入融合加法归一化分支；单参数调用不能直接套用该分支的行为。

**“GLM 的每个分支都可以写成输入加上 MLP 输出。”** 固定快照的 mHC 非 MTP 路径通过入口与写回操作连接 MLP，应按该分支追踪状态。

**“MLP 类型列表为空时，各快照都会使用同一规则。”** 所给快照展示了不同的回退方式，差异见下方源码区。

## 对照源码

### 怎么开

MLP、归一化和 residual 连接由模型层构造与调用安排，不是三个可以脱离模型任意组合的独立开关。

固定执行侧快照的稠密 MLP 根据 `swiglu_limit` 是否为 None，选择普通或带限幅的激活模块。材料没有提供完整启动配置入口，不能据此给出可执行的部署命令。

MLP 类型选择还受模型配置约束。固定快照仅在模型启用 MoE、专家数非空且当前层类型为 sparse 时选择 MoE。MoE 是由路由机制组织多个专家前馈模块的结构，具体计算见[MoE](../concepts/moe.md)。

### 会报什么错

后续两个快照中的 `Glm5NextMLP` 明确检查激活类型；非 silu 时抛出：

```text
Unsupported activation: <hidden_act>. Only silu is supported for now.
```

固定执行侧快照所给构造片段没有这项检查，而激活选择仍是 SiLU 门控。缺少检查不能证明其他激活可用。

### 开销和什么时候别开

材料足以定位投影、激活、归一化、相加与 mHC 调用，尚不足以量化它们的耗时、临时显存或融合收益。这里没有实机运行结果。

后续快照的 MLP 注释区分了两种布局：序列并行时，输入输出按 TP 组分片、权重复制；标准 TP 则描述为末尾执行 All-Reduce。序列并行把部分逐位置计算分给不同执行成员，TP 则将张量计算分片；All-Reduce 将成员的对应结果归约，并使各成员得到归约结果。

该构造器同时暴露结果归约控制项，因此不能只凭注释断言每次调用都会发生 All-Reduce。完整代价还需核对调用者和输出投影实现，相关基础见[Tensor Parallel](../concepts/tensor-parallel.md)与[序列并行](../concepts/sequence-parallel.md)。
