## 一句话

`placement_search_backtrack_limit` 是 STAIR 约束放置搜索的回溯预算：为单个候选安排位置时，首次源可行选择不扣预算，此后每接受一次替代可行选择才扣一次；设为 0 禁用这些替代选择，仍保留初始选择和其他候选的尝试。

这里的“放置”是为候选方案确定分配位置；“源可行”表示当前选择通过了搜索中的来源可行性检查。它是搜索过程中的检查结果，不等于整个候选已经完成合法放置。材料将该过程称为 constrained LPT，但没有给出完整算法，以下只解释摘录能够确认的预算行为。

本页依据提供的本地源码摘录整理，尚未独立核对上游完整文件；提交快照也尚未映射到在册社区分支，因此不登记已核对版本。

## 为什么存在

放置搜索需要找到同时满足每个 rank 和跨节点迁移限制的分配方案。rank 是参与分布式执行的成员编号；在这里，迁移限制会约束候选方案能否被接受。材料中的函数说明把合法放置与这些限制联系起来，并为搜索设置有限的回溯预算。

回溯是在已有选择无法继续时，撤销部分选择，再尝试其他分支。本参数限制的是其中接受替代可行选择的次数，而不是把所有检查都算作一次回溯。这个区别决定了如何理解预算耗尽。

例如，设预算为 1，当前决策已经接受过一个源可行选择。后来需要改选时：

- 新尝试未通过来源可行性检查：撤销这次放置并继续，在所示分支中不增加计数。
- 新尝试通过检查，并被接受为替代选择：已用预算从 0 增加到 1。
- 后续又需要接受替代可行选择，而预算已经用完：撤销新尝试并返回 `None`。

这是依据所示计数分支构造的示意，不是实际运行记录。[A]

预算为 0 时，首次源可行选择仍然免费。如果这条初始路径就能完成合法放置，预算本身不会阻止它；需要接受替代可行选择时，才会受到零预算限制。因此，“不允许反转可行分支”和“不进行任何搜索”是两种不同的行为。

单个候选返回 `None` 后，外层候选循环会执行 `continue`，继续检查其他候选。这个返回值表达的是本次有界搜索的结果，不能扩大解释为所有候选都失败，也不能扩大解释为不存在合法解。

## 开了的代价

设置为正数后，搜索可以在初始可行选择之外接受替代选择。预算约束这些选择被接受的次数；材料没有给出总检查次数或耗时上限，所以不能把“预算为 32”理解成“最多执行 32 次检查”。

材料未提供实际运行案例、性能数据或完整性证明。提高预算对找到合法放置的概率、搜索耗时和资源占用有多大影响，仍需补充完整实现与运行记录；也没有依据保证设为 64 就一定能找到合法解。本页据此不推荐固定调优值。

配置路径与直接函数调用还需分开看。所示配置字段要求值处于 0 至 64，并在转换前拒绝布尔值；越界时的错误文本为：

```text
stair_config.placement_search_backtrack_limit must be between 0 and 64
```

布尔值触发的错误文本为：

```text
STAIR numeric fields must not be booleans
```

另一份快照中的 `lpt_placement` 入口将 `backtrack_limit` 与迁移限制一起校验，要求它是非布尔整数且非负，所示代码没有检查上限 64。其错误文本为：

```text
STAIR transfer limits and backtrack_limit must be valid integers
```

这些检查发生在不同入口，不能用函数入口摘录推翻配置字段的上限，也不能把字段上限当成函数入口已经执行的检查。

版本方面，材料涉及若干提交快照，但没有提供与 v0.23 维护分支、v0.26 分支、v0.30.0rc2 分支及 main 开发主线的可靠映射。四个分支的存在范围、默认值与运行时行为均待逐项核对；当前摘录不足以判断首次支持版本或分支间差异。
