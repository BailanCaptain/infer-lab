Quantization 的加载涉及两个相互衔接的决定：模型使用什么量化方法，以及模型中的具体层由什么实现执行。当前材料展示了这两个决定的部分代码，还不足以完整讲解数值怎样量化、整数矩阵乘怎样计算，以及结果怎样恢复到后续计算需要的表示。

本页先说明加载时能够确认的识别规则、冲突处理和失败条件。这里的权重指模型计算使用的参数；模型配置是描述模型的元数据，读取配置与检查权重文件内容是不同的操作。

## 为什么量化方法与 dtype 要分别判断？

上游模型配置中的 quantization 字段表示用于量化权重的方法。dtype 则在相应条件下用于决定权重的数据类型。两者的关系有明确的判断顺序，不能只凭某一个设置推断最终的权重加载方式。

材料中的字段说明规定：没有指定量化方法时，先检查模型配置文件中的 quantization_config；这一项也为空时，才假定权重未量化，并使用 dtype 决定权重的数据类型。

因此，“没有显式指定量化方法”还不是判断结束的位置。程序仍可能从模型配置中获得量化信息。

## 显式设置与模型配置不一致时，会发生什么？

需要区分上游的配置解析与 Ascend 的自动检测。材料展示的两处逻辑采用不同的冲突处理方式。

| 判断位置 | 没有已有量化方法时 | 已有方法与识别结果不同时 |
| --- | --- | --- |
| 上游模型配置解析 | 使用解析出的量化方法 | 在方法专用的覆盖检测之后，若最终方法仍不一致，抛出 ValueError |
| Ascend 自动检测 | 检测到方法后，按说明自动应用 | 尊重已有设置，并发出 warning |

上游的“覆盖检测”指量化方法专用的识别逻辑可能先调整识别结果。冲突检查使用的是经过这些逻辑处理后的方法，不能把任意原始字段差异都直接等同于报错。

Ascend 自动检测的说明则规定：显式设置应被保留，检测到不同方法时发出警告。这条规则只描述该自动检测环节，不能扩大为整个加载过程的统一规则。

## JSON 检测能够确认到哪一步？

材料中的检测函数明确说明：它只检查 JSON 文件，不检查 safetensors 或 bin 权重文件的内容。

这使检测结果具有清楚的边界：它反映配置文件中的量化标记，不能单独证明权重内容与标记相符。判断加载是否可用，还要继续看具体层的实现选择。

未找到量化签名时，检测函数返回 None。部分摘录还展示了对 JSON 解析错误和文件操作异常的忽略处理。因此，返回 None 表示这次检测没有得到方法，不能据此证明权重实际未量化。

材料中的 FP8 检测条件也存在差异：一个快照要求配置方法匹配 FP8，且设备类型为 A5；另两个快照只检查方法是否匹配 FP8。这是自动检测分支的差异，不能直接用来判定所有设备上的 FP8 执行支持范围。

## 为什么识别出方法之后，具体层仍可能失败？

模型级的方法名与层级的执行方案是两个判断对象。

材料展示的层级选择逻辑，用“量化类型”和“层类型”的组合查询已注册方案。找到方案类后，创建相应实例；找不到时，记录错误并抛出 NotImplementedError。

例如，模型级识别已经得到一种量化方法，程序随后仍需为某个具体层查询对应方案。这个组合没有注册实现时，加载会在这里失败，不能从前面的识别成功推导出所有层都可执行。

错误提示建议使用支持的量化格式，或加载模型原始的浮点权重。展示的分支本身执行的是抛错，没有展示自动改走浮点加载的过程。

## 这些材料能说明 GLM 双机实际用了什么方案吗？

当前摘录涉及固定主线所用的上游控制流快照，也涉及多个 Ascend 实现快照，但没有提供 GLM-5.3-Flash 部署权重包的逐层量化描述内容。

因此，本稿不能确定固定双机部署中每层采用什么量化方案，也不能补出逐层输入输出类型、量化参数形状、通信数据类型或显存账单。要把加载机制接到实际部署，需要核对权重包中的描述文件与对应加载实现，并检查具体层最终选择的方案。

本次材料也没有提供可支撑数值教学的量化公式或手算实例。数值映射、舍入、截断、静态与动态量化的演算，以及精度和速度比较，仍需补充材料后编写。

## 排查时，哪些判断需要分别确认？

排查加载问题时，应分别确认下面几个问题：

1. 上游解析最终认定的量化方法是什么，是否与显式设置发生冲突？
2. Ascend 自动检测读到了什么 JSON 标记，是否保留了已有设置？
3. 每种具体层能否找到对应的量化方案？
4. 配置标记是否与实际权重内容一致？

其中前三项对应当前材料展示的配置解析、检测与方案查询。第四项需要权重内容或额外校验依据，不能由只读 JSON 的检测结果代替。

## 对照源码

### 怎么开

材料涉及显式量化选项 `--quantization`，也展示了未指定方法时从模型配置读取量化信息的规则。它没有给出完整的部署命令、权重包准备步骤或全部初始化调用链，本稿据此不提供可直接执行的 GLM 双机启动命令。

Ascend 自动检测说明提到了应用检测结果及重建量化配置；但展示的函数只设置模型配置中的 quantization 字段，未展示重建过程。完整的量化配置何时建立，仍需沿调用方核对。

### 会报什么错

上游模型配置解析中，经过方法专用的覆盖检测后，显式方法与解析结果仍不一致，会抛出 ValueError。错误信息指出模型配置中的方法与 quantization 参数中的方法不匹配。

层级方案查询失败时，会抛出 NotImplementedError，错误信息包含不支持的 quant_type 与 layer_type 组合，并建议使用支持的格式或原始浮点权重。

Ascend 自动检测中已有设置与检测值不一致时，按材料说明发出 warning 并保留已有设置。这与上游的 ValueError 属于不同位置的处理。

### 开销和什么时候别开

自动检测只读 JSON，函数说明称其为轻量检查；材料没有给出耗时测量。

是否使用某种量化方案，还需要确认权重格式与具体层的实现是否匹配。当前材料没有覆盖精度验收、运行速度、辅助参数占用和工作区开销，不能据此推荐某种方案用于固定部署。
