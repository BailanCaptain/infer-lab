## 一句话

`replica_search_beam_size` 限制 STAIR 副本数搜索每阶段保留的不同候选数量。副本数候选描述的是“每个专家各有几份”，不是“这些副本分别放在哪个设备上”。束宽（beam size）就是每轮筛选后允许继续参与搜索的候选数上限。

材料中的默认值为 64，合法范围为 1–128。最终候选还会强制保留当前副本数，因此设为 1 时，唯一留下的是当前份数方案；这会限制副本数调整，但不能据此断言后续物理摆放不变。[D]

本页只依据提供的本地源码摘录整理。摘录覆盖配置校验、候选筛选和部分策略初始化代码，没有设备实测，也不足以完成四个在册社区版本的逐项核对。

## 事实表

| 项 | 值 | 意味着什么 |
| --- | --- | --- |
| 声明类型与默认值 | `int`，64 | 未另行设置时，摘录中的配置声明采用束宽 64；不等于每次一定产生 64 个有效方案 |
| 合法范围 | 1–128 | 0 不合法，不能用 0 关闭搜索 |
| 布尔值 | 校验器拒绝 | `true`、`false` 不能当作整数配置 |
| 阶段筛选 | 按阶段份数向量去重，排序后取前若干项 | 重复状态不占多个保留位置 |
| 阶段排序依据 | 专家风险除以候选份数所得数值的最大值，越小越靠前 | 筛选考虑的是候选份数下的每副本风险，不是完成物理摆放后的设备负载 |
| 同分处理 | 依次比较补全后的份数向量、阶段份数向量 | 数值相同时仍有确定的筛选顺序 |
| 当前份数保留 | 最终截断后，必要时用当前份数替换最后一项 | 束宽为 n 时，改变份数的候选至多有 n − 1 个 |
| 束宽为 1 | 最终只保留当前份数 | 副本数不调整；摆放位置是否变化仍取决于后续处理 |
| 有效方案数量 | 可以少于束宽 | 去重、补全失败和后续摆放失败都会减少可用方案 |

配置声明与校验见材料第 3、12–13、98–103、119–154 行；阶段筛选见第 17–34、160–174 行；当前份数保留见第 178–196 行。表中“至多 n − 1 个”和束宽为 1 的结果，是对保留逻辑的直接推导。[D]

## 为什么存在

副本数搜索会产生多个方案，之后还要尝试把这些副本放到设备上。束宽把“继续保留多少个方案”变成一个明确上限：每阶段先去掉重复状态，再按分数排序，只让靠前的候选继续参与搜索。

材料中的阶段筛选先用补全后的份数向量计算分数：对每个专家，用它的风险值除以副本份数，再取其中最大值。这个分数衡量候选里压力最大的那一份副本；分数越小，排序越靠前。摘录没有给出专家风险值的完整计算过程，因此这里不能把“风险”直接等同于请求数、运行时间或设备利用率。

下面用一组**示意数**说明筛选。假设三个专家的风险分别为 8、4、2，有两个候选：

- 方案甲的份数为 `(2, 1, 1)`，每副本风险为 `(4, 4, 2)`，最大值为 4。
- 方案乙的份数为 `(1, 2, 1)`，每副本风险为 `(8, 2, 2)`，最大值为 8。

这些风险和份数是教学设定。[A] 按摘录中的阶段排序规则，甲排在乙前面，因为 4 小于 8。[D] 这一步只比较份数方案；设备能否容纳这些副本、迁移限制是否允许，以及最终负载如何，还需要后续摆放处理。

早期摘录还展示了两次相关截断。目标份数生成后，会过滤无效结果、按份数去重并截断；从当前份数逐步向目标调整后，又会排序并截断，同时确保当前份数仍在结果中。材料第 78–94 行随后逐个调用摆放过程，并跳过摆放失败的候选。因此，束宽同时影响搜索中的保留数量，以及可能进入摆放尝试的候选数量。

当前份数的保留规则尤其影响小束宽。假设当前份数为 `(1, 2, 1)`，另一个候选为 `(2, 1, 1)`。[A] 若截断只留下后者，而束宽为 1，保留逻辑就会把它替换成当前份数；若当前份数本来就在唯一位置上，结果同样只有当前份数。[D] 要让最终候选集合有位置容纳改变份数的方案，束宽至少需要为 2，但这不保证一定能产生有效的改变方案。[D]

搜索阶段怎样组织，可结合 [replica_search_num_stages](../params/replica-search-num-stages-e4b10925ff97.md) 阅读；配置入口见 [stair_config](../params/stair-config-cca9e594a052.md)。

## 开了的代价

束宽越大，允许继续参与搜索的候选越多，也允许更多不同份数方案进入后续比较。这给搜索保留了更多选择，同时扩大了排序、候选处理和摆放尝试的可能工作量。具体运行时间还取决于实际生成多少个不同候选、候选能否补全，以及摆放是否成功，不能直接按束宽倍数换算耗时。[I]

束宽较小时，排序靠后的候选更早被舍弃。阶段分数没有直接描述完整设备摆放结果，因此可以推断：过早截断可能舍弃后续摆放更合适的方案；提供的材料没有给出这种情况的实测或完整算例。[I]

束宽为 1 的边界不同于一般的“少留几个候选”：最终保留规则使它只留下当前副本份数。后续摆放过程仍接收当前布局及迁移限制等输入，不能仅凭份数没有改变，就认定专家所在设备也不会改变。

材料第 198–214 行展示了 MRV2 的 EPLB 初始化路径：取得 STAIR 配置后，将其传给策略创建函数。它能支持“配置进入了策略创建入口”这一结论，但摘录没有展示策略创建函数内部、束宽读取位置及完整服务调用链，不能由此单独证明所有启用组合都已可运行。

**版本边界。** 材料标识的早期扫描快照和后续 `7d825229` 快照均声明默认值 64；两份摘录中的阶段筛选都按份数去重、排序并按束宽截断。后续快照也保留了范围校验、布尔值拒绝以及最终强制保留当前份数的逻辑。材料没有提供这些提交与四个在册社区分支的完整映射，也没有提供旧分支上的配置入口和替代实现，故本页不据此登记 `verified`，也不判断某个分支是否不存在该参数。

**待核事项。** 仍需补充四个在册版本的配置与运行时核对、策略创建后的参数传递链，以及相同负载下不同束宽的耗时和摆放效果对照。材料也未包含 GLM 双机基线的配置与冗余容量证据，不能据此给出该部署下的启用结论或收益数字。
