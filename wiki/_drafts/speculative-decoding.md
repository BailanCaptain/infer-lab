Speculative decoding 先提出若干候选 token，再由目标模型验证，利用通过验证的连续前缀推进生成。目标模型是负责最终验证和输出的模型；草稿是提前提出的候选，尚未成为确定输出。

本页关注三个问题：验证怎样决定留下哪些候选，候选涉及的缓存与状态为什么需要额外处理，以及 GLM 固定实现有哪些执行限制。内容依据本地材料中的源码摘录整理，尚未据完整源码逐项复核，也没有设备运行结果。

## 候选怎样变成确定输出？

[token](../concepts/token.md) 是分词器用整数编号表示的离散符号，一个 token 不必对应一个汉字或单词。[Decode](../concepts/prefill.md) 则是在已有历史上继续生成输出的阶段。

推测解码把候选提出与最终确认分开。草稿阶段提出接下来的候选序列；验证阶段判断候选能否留下。材料中的拒绝采样循环只保留第一次拒绝之前的连续候选，不会跳过一个被拒绝的位置，继续保留后面的候选。

这是因为后面的候选建立在前面的候选历史上。当前缀被改写，后续候选对应的条件也随之改变，不能把它们当成已经在新历史下得到确认的结果。

在材料展示的普通贪心验证分支中，每个位置输出目标模型的最高分 token；候选与它不同时，该位置被拒绝。若所有候选均通过验证，循环还会追加一个 bonus token，即候选之后额外得到的输出 token。

## 为什么多做草稿计算仍可能节省时间？

普通 decode 通常沿生成序列逐位置推进。推测解码尝试让一次验证留下多个位置，从而减少推进同样长度所需的验证轮数。

减少轮数需要付出额外工作：草稿本身要计算，目标模型要处理候选验证，执行过程还要准备相应的输入空间与状态。只有省下的工作超过这些新增开销，总时间才会缩短。

候选容易被接受时，一轮验证可能留下较长前缀；候选频繁被拒绝时，已经花费的草稿计算只能换来较少进展。材料没有提供接受率、单轮耗时或不同并发量下的测试，因此本页不能给出加速倍数，也不能据此推荐候选数量。

## 用三个候选怎样手算一次贪心验证？

下面使用示意 token 编号，不对应真实文本或模型输出。

请求 A 已有一段确定历史，草稿提出三个候选：

| 候选位置 | 草稿 token | 目标模型在对应位置的最高分 token |
| --- | --- | --- |
| 第 1 个 | 7 | 7 |
| 第 2 个 | 4 | 9 |
| 第 3 个 | 8 | 不再用于本轮输出 |

验证过程如下：

1. 第 1 个候选是 7，目标模型也选择 7，因此留下 7。
2. 第 2 个候选是 4，目标模型选择 9，因此拒绝 4，输出 9，并停止沿候选继续确认。
3. 第 3 个候选 8 不进入本轮确定输出。它原先接在候选 4 后面，而确定前缀已经改为接在 9 后面。

本轮确定输出是 `[7, 9]`：其中 7 是接受的候选，9 是拒绝位置由目标模型确定的 token。这个例子说明，“提出三个候选”与“留下三个候选”是不同的量。

若三个候选都通过贪心验证，材料中的循环会在接受它们之后追加 bonus token。具体请求最终输出多少，还需要结合结束条件与完整执行路径核对。

## 随机采样为什么还需要候选概率？

贪心采样直接选择分数最高的 token；随机采样则根据概率分布抽取 token。二者的验证条件不同。

材料中的普通随机拒绝采样分支会比较目标模型与草稿对当前候选给出的概率。设目标概率为 \(p\)，草稿概率为 \(q\)，抽取的均匀随机数为 \(u\)，代码在下列条件成立时接受候选：

\[
q>0 \quad\text{且}\quad \frac{p}{q}\ge u
\]

例如，示意条件为 \(p=0.2\)、\(q=0.4\)，则比值为 \(0.5\)：当本次随机数为 \(0.3\) 时接受，为 \(0.8\) 时拒绝。这是对材料中判断式的代入演示。

草稿概率为零时，代码明确拒绝，避免除法产生无效数值。被拒绝后，随机采样分支使用恢复采样得到的 token；它与贪心分支直接选择目标最高分 token 的做法不同。

在提供草稿概率的恢复采样分支中，各 token 的权重取目标概率减去草稿概率的非负部分：

\[
w(x)=\max\bigl(p(x)-q(x),0\bigr)
\]

材料还展示了不提供草稿概率的另一条分支：接受判断中将草稿概率设为 1，恢复采样则读取目标概率并屏蔽草稿 token。因而，上面的差值公式只适用于提供草稿概率的对应分支。

完整的分布保持证明需要核对候选生成、接受判断与恢复采样之间的配合。本页摘录不足以完成这一证明。

## 候选已经计算过，为什么还不能都当成有效缓存？

[KV cache](../concepts/kv-cache.md) 保存后续计算需要的历史表示，避免重复处理已完成的位置。推测解码引入了一个额外区别：某个位置已经参与计算，不代表它已经成为确定历史。

材料中的缓存管理注释明确说明，当新 token 同时包含已验证与未验证候选时，只缓存已验证部分，并以请求当前确认的 token 数为上限。这里的“只缓存已验证部分”不表示未验证候选无需计算空间。

因此，需要分别理解：

- **执行所需空间**：为候选计算准备的临时位置或额外状态槽位。
- **已确认的可缓存前缀**：经过验证、可以作为后续确定历史的部分。

不同方法需要的预留位置也不同。材料中的 DFlash 使用填充式解码，需要为最后采样的 token 和每个候选分别提供查询，因此其 lookahead 槽位数是候选数加一；同段中的 EAGLE 与使用草稿模型的分支则设为候选数。Lookahead 在这里指执行前为后续位置预留的空间，不能统一理解为所有方法都额外加一。

## GLM 固定实现增加了哪些执行条件？

本页涉及的 GLM 执行侧摘录钉住 vllm-ascend 的固定提交，验证与缓存相关摘录钉住配套 vLLM 提交。它们不等同于已经核验三个社区分支的全部行为；模型与部署边界见[GLM-5.3-Flash 来源基线](../sources/glm-5-3-flash-baseline.md)。

### 草稿与目标模型怎样选择执行模式？

Graph mode 会捕获满足条件的设备操作序列，之后通过回放减少逐次提交开销；eager mode 则沿执行过程逐步提交算子。

固定实现对检测到的 GLM 系列强制草稿模型使用 eager mode，同时保持目标模型的 graph mode 设置不变。这里分别控制的是草稿与目标两条执行路径，不能把草稿的限制扩大为整个推测解码过程都必须使用 eager mode。

### KDA 为什么需要额外状态槽位？

[KDA](../concepts/linear-attention.md) 使用递推状态汇总历史，固定实现还涉及短卷积状态。材料中的适配注释说明：vLLM 0.23 的通用 KDA helper 虽然接收候选数量，却没有据此增加短卷积状态长度，而推测解码需要这些额外槽位。

这说明候选带来的资源变化不限于普通注意力的历史缓存，还可能影响其他随序列推进的状态。具体状态形状、额外显存，以及拒绝后选择哪一份递推状态，现有摘录不足以完整展开。

## 哪些数量和限制需要分别理解？

**候选数量不是接受数量。** 候选可能在中途被拒绝；全部接受时还可能追加 bonus token。配置的候选数、接受的候选数与最终输出数应分别统计。

**验证轮数减少不等于总耗时减少。** 总耗时还包含草稿计算、验证新增工作和状态管理，收益需要实测。

**算子的 16 token 限制不是候选数可以直接设为 16。** 材料中的实现先把候选数量加到已有 decode 阈值上，再检查总阈值不超过 16。基础阈值同样占用额度。

**MTP 的配置项不能照搬其他草稿方法。** MTP 是 Multi-Token Prediction，即多 token 预测结构或目标，推理时可使用配套模块提出草稿。材料中的 main 快照明确指出，MTP 复用目标模型的层，因此会忽略草稿滑动窗口；限制这些层的注意力窗口也会影响目标模型。

## 对照源码

### 怎么开

材料出现了 `--speculative-config`、`num_speculative_tokens`、`enforce_eager` 和 `draft_window_size` 等配置名，但没有提供足以复现部署的完整命令、模型文件与运行环境。本草稿不据此拼接启动命令。

固定 GLM 实现会强制草稿使用 eager mode，等价于给草稿配置添加 `"enforce_eager": true`；目标模型的 graph 设置保持原值。该结论来自本地材料第 373—377 行所保存的实现注释。

### 会报什么错

固定执行侧的 `sfa_v1.py` 在配置推测解码时，将候选数加到 decode 阈值上，再执行：

```python
assert self.decode_threshold <= 16
```

材料将此限制关联到 `npu_fused_infer_attention_score` 的 TND layout。TND 是该算子使用的张量布局标记；摘录没有展开各维的完整接口定义。这里能确认的是总阈值约束，不能据此直接给出所有配置下统一的候选数上限。

main 的指定快照对 MTP 配置草稿滑动窗口时给出警告，并忽略该窗口：

```text
[sliding-window] draft method is MTP, which is not compatible with draft_window_size; the window is ignored.
```

### 开销和什么时候别开

现有材料支持检查以下新增成本：草稿计算、目标验证、候选预留空间，以及 KDA 短卷积状态的额外槽位。固定 GLM 实现还要求草稿使用 eager mode。

材料没有性能测试，无法判断哪种候选数最合适，也无法确定什么并发量下收益消失。工程评估应对照相同模型、输入与生成条件下的开启和关闭结果；本页没有完成这项验证。
