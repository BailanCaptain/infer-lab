Streaming output 是在请求尚未结束时，逐步交出已经可以返回的结果。模型先产生 token 编号，输出处理再把编号转换成文字、决定本次交出多少内容，聊天接口最后把结果封装成响应消息。

[token](../concepts/token.md) 是分词器使用的离散符号，通常用整数编号表示；一个 token 不必对应一个汉字或单词。因此，“模型又生成了一个 token”“又有文字可以展示”“客户端又收到一条消息”是三个不同的事件。

本页接续[一条请求](../concepts/one-request.md)中生成 token 之后的阶段，解释这些事件怎样联系起来。材料提供了输出处理和聊天流生成器的片段，能够说明程序何时创建或交出响应；网络代理、传输缓冲与客户端渲染不在这些片段中。

## 为什么生成了 token，页面还可能没有新文字？

**反分词**是把 token 编号转换回文字。增量反分词在已有解码状态上继续处理新编号，不要求每次都从头转换整个回答。

输出文字的边界还会受到停止字符串影响。停止字符串是请求指定的一段文字：生成结果遇到它时，应当结束；请求也可以要求把这段文字从返回结果中排除。

如果停止字符串分几次才生成完整，已经发送的文字无法再从客户端撤回。因此，在配置了停止字符串、并要求排除它时，材料中的实现暂存尾部字符，暂存长度为“最长停止字符串的字符数减一”。没有这种排除要求时，该缓冲长度为零。

这里存在两种等待：

- 反分词处理 token 编号，形成文字。
- 停止字符串缓冲决定已有文字中哪些可以安全交出。

这也解释了为什么 token 计数增加时，本次可返回的文字仍可能为空。

## 怎样手算一次停止字符串缓冲？

设一个**示意请求**的停止字符串为 `END`，要求返回结果不包含它。假设本次反分词已经得到 `abcEN`，尚未发送任何文字。最长停止字符串有三个字符，因此尾部保留两个字符。

这时可以交出 `abc`，把 `EN` 留在缓冲中。下次得到 `D` 后，尾部组成完整的停止字符串 `END`；排除停止字符串时，返回文字截在它的起点，最终正文仍为 `abc`。

另一种结果是下次得到 `X`。此时尾部成为 `ENX`，没有组成 `END`。在继续保留末尾两个字符的规则下，前面的 `E` 可以交出，新的尾部为 `NX`。

这个例子区分了两份状态：**已经解码出的文字**与**已经发送的文字**。前者可以暂时领先于后者。请求结束时，取文本逻辑不再沿用普通的尾部保留长度；DELTA 模式仍只取尚未发送的部分。停止判断决定的截断范围则继续影响最终文字。

## 为什么一个响应片段可能包含多个 token？

材料展示了三种影响输出分组的机制。

**输出模式决定是否需要中间结果。** DELTA 表示增量输出，每次取相对于此前尚未交出的部分；FINAL_ONLY 表示只需要最终结果。聊天请求启用流式响应时选择 DELTA，否则选择 FINAL_ONLY。后者在请求尚未结束时不创建中间 RequestOutput。RequestOutput 是引擎向调用方交付请求结果的对象，还不是网络消息本身。

**输出间隔决定何时创建结果。** 材料中的服务端间隔按新增 token 数计量，默认值和最小值均为一。间隔大于一时，首次输出、结束输出或新增 token 数达到间隔，均可通过输出门控。它不是每隔固定毫秒发送，也不是机械地每隔若干次引擎迭代发送。

**消费者速度决定结果是否继续合并。** RequestOutputCollector 是交付请求结果的收集器。生产者快于消费者时，DELTA 结果可以合并；因此，即使前面已经创建了多个结果对象，消费者也可能一次取得合并后的内容。

用一个**示意序列**观察输出间隔：间隔设为三，请求首次已有一个输出 token，首次例外允许交出它。此后又增加两个 token，尚未达到三；再增加一个，便可交出这三个新增 token。若请求随后只增加一个 token 就结束，结束例外允许交出剩余结果。

这些规则只确定程序何时产生结果。实际接收到的分组还会受到消费者合并以及后续响应处理影响。

## 聊天流里除了正文，还有哪些消息？

聊天接口把引擎结果封装成响应。SSE（server-sent events，服务器推送事件）是这里使用的流式消息形式；材料展示的生成器以 `data:` 消息交出载荷。

一条流中可以出现不同用途的消息：

| 消息用途 | 材料展示的内容 | 调用方怎样理解 |
| --- | --- | --- |
| 初始化 | role、空 content、尚无结束原因 | 建立角色信息，此时可以没有生成文字 |
| 内容增量 | 正文或工具调用等增量字段 | 按字段含义更新对应结果 |
| 结束信息 | finish_reason，可能伴随最后的增量 | 先处理本条内容，再处理结束状态 |
| 最终用量 | 启用 include_usage 时，choices 为空并携带 usage | 这是统计消息，不是新的正文 |
| 流终止标记 | `[DONE]` | 表示所示生成器交出终止标记，仍需结合错误与结束信息判断结果 |

choice 是一份候选回答。材料中的最终 completion_tokens 对所有 choice 的 token 数求和，不能把它直接当成某一份回答的长度。

空文字也有不同来源。初始化消息可以带空 content；解析器未产生内容增量时，如果已经结束，或调用方要求返回 token ID，代码仍可能构建空的 DeltaMessage。另一方面，材料还展示了一条专门跳过初始空结果的判断：本次没有文字、没有 token ID，而且该 choice 此前的 token 数为零。它不能推广为“所有空文字消息都会被过滤”。

## 多个 token 一起返回时，停止判断怎样处理？

模型执行可以一次交回多个 token。[Speculative decoding](../concepts/speculative-decoding.md) 先产生候选、再由目标模型验证，是需要关注这种情况的路径之一。

材料中的调度器逐个追加新 token，每追加一个就检查停止条件；命中后，裁掉本批尚未追加的后续 token，再构造 EngineCoreOutput。EngineCoreOutput 是后端向输出处理交付的执行结果。这个顺序说明：执行结果中的候选 token，并不一定全部进入最终请求输出。

停止字符串还涉及文字匹配规则。材料末尾的另一个上游快照说明：同一段新增文字匹配多个停止字符串时，选择**在文字中最早完成**的那个；完成位置相同，再按请求中停止字符串列表的顺序选择。

例如，示意新增文字为 `abcd`，停止列表依次为 `bcd`、`ab`。`ab` 在第二个字符处完成，`bcd` 在第四个字符处完成，因此按最早完成规则选择 `ab`。是否把停止字符串放进结果，进一步决定截在匹配串的末尾还是起点。

这条规则只由材料末尾的特定快照支持，不能直接作为所有版本的共同结论。

## GLM 双机中的工具调用，为什么要特别处理最后一块？

在 GLM-5.3-Flash 双机主线中，本页关注生成结果离开执行侧之后的输出处理。现有材料没有提供可复算的双机输出时延、通信字节数或 CPU 开销测量。

材料中的昇腾补丁说明了一种 GLM 工具调用收尾情况：最后一段工具参数可能重复工具调用元数据，也可能与 `tool_calls` 结束原因放在同一个 SSE 消息中。工具参数是交给被调用函数的输入内容，客户端需要把它们累积完整。

补丁对满足条件的消息拆成两条：

1. 参数消息保留内容，清空结束原因与停止原因。
2. 结束消息保留结束信息，清空增量内容。
3. 按参数消息在前、结束消息在后的顺序返回。

拆分有明确边界：消息必须恰有一个 choice，结束原因为 `tool_calls`，且至少一个工具调用包含非空参数。非 `data:` 消息、`[DONE]`、无法解析成 JSON 的载荷以及不满足判定的消息，都原样返回。

因此，客户端需要先消费最后一条消息中的内容，再处理它的结束状态。某些消息会由补丁拆开，但补丁没有把所有结束消息统一改成无内容消息。

## 怎样判断请求结束，怎样理解停顿？

**生成结束、响应收尾和客户端交付分别发生在不同位置。**

后端的结束原因表示生成状态已经结束。聊天生成器还可能交出末尾内容、用量信息或错误消息，随后才交出流终止标记。材料中的异常分支把生成异常或其他异常转成流内消息，其后仍交出 `[DONE]`。因此，客户端需要同时检查错误消息和结束原因。

客户端断开时，材料展示的 generate 异常处理会在收到取消异常或生成器退出异常、且请求队列已建立时，调用中止请求逻辑。网络断开怎样触发这条路径，以及资源何时全部归还，需要接续[请求收尾](../concepts/request-teardown.md)核对。

一次可见停顿也不等同于一次设备计算停顿。它可能出现在输出间隔门控、尾部字符缓冲、结果合并或后续交付阶段。要定位原因，需要分别观察生成 token 的进度、创建输出的时刻和客户端收到消息的时刻；本材料没有这些阶段的端到端实测。

## 对照源码

### 怎么开

聊天请求的流式开关决定输出模式：启用时选择 DELTA，关闭时选择 FINAL_ONLY。服务端 `--stream-interval` 控制按多少新增 token 攒成输出；材料中的定义默认和最小值均为一，单位是 token 数，而不是时间。依据见材料第 680–684、697–699 行。

材料末尾另有请求级 `stream_interval` 定义：可以提高引擎级间隔，低于引擎设置时向上限制到引擎值。该定义来自另一个固定快照，不能据此认定主线运行环境已具备此接口。

### 会报什么错

材料第 997–1004 行展示：生成器捕获 GenerationError 和其他 Exception，交出流内错误响应，然后交出 `[DONE]`。调用方应保留流内错误状态，不能仅凭终止标记记录成功。

材料第 122–127 行展示取消与生成器退出时的请求中止处理，但没有给出可供完整列举的网络错误信息或资源释放时限。

### 开销和什么时候别开

增大输出间隔会减少输出分组频率。材料注释说明，这可以降低主机侧开销，并可能改善吞吐；吞吐提升不是这份材料中的实测结果。较大的间隔也会让中间文字更集中地出现，使用者应按交互连续性与主机开销的需求取舍。

停止字符串缓冲解决的是尾部文字可否交出的问题，输出间隔解决的是按多少新增 token 创建结果的问题；两者不能互相替代。

快速增量反分词的材料条件包括 tokenizers 版本不低于 0.22.0；摘录说明的实现选择还要求快速分词器。现有直接引文仅完整展示了依赖版本判断，完整选择分支仍需在整合时补核。
