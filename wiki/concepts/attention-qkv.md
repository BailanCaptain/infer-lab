## 「它」指的是谁

看这句话：「小猫吃饱了，它睡着了。」你一眼就知道「它」是小猫。可模型是怎么知道的？

到这一步，句子已经切成了一个个 [token](token.md)，每个 token 各有一串 2048 个数字（[隐藏向量](layers-and-hidden.md)）。模型每一层里的大部分计算——比如后半段那组专家——都是**每个 token 各算各的**：「它」这串数字怎么改，只看「它」自己，不看旁边是谁。

这样算下去，「它」永远不会知道前面有只小猫。光凭「它」这一个字本身，谁也猜不出它指代什么。

所以每一层里专门有一段，让每个 token **回头看前面的 token**，把跟自己相关的信息取过来，揉进自己那串数字里。这一段叫**注意力**。这一页就讲它具体怎么「看」。

## Q、K、V：每个 token 算出三份数字，一份去问、一份被问、一份交出去

注意力开工的第一步，是让每个 token 用自己的隐藏向量各算出三份新的数字。怎么算？就是[乘一张权重表](matmul-and-weights.md)：每层有三张不同的权重表，隐藏向量分别乘这三张，得到三份结果，名字分别叫 Q、K、V。

三份数字分工不同：

- **Q**（query，提问）：拿去问别人的。「它」的 Q 大意是「我在找前面一个能被我指代的东西」。
- **K**（key，标签）：挂在自己身上、等着被别人问的。「小猫」的 K 大意是「我是个名词，是个能被指代的活物」。
- **V**（value，内容）：真正要交出去的东西。别人决定听你的，拿走的是你的 V，不是你的 K。

打个比方：一屋子人开会，每人胸前别着一张名牌（K），脑子里装着自己知道的事（V）。你心里揣着一个问题（Q），拿它挨个去对别人的名牌，名牌越对得上，你就越认真听那个人讲——听进去的是他讲的内容（V），不是他的名牌。

为什么 K 和 V 要分成两份？因为「凭什么被选中」和「被选中后交出什么」是两回事。名牌写得好不代表要把名牌交出去；把两件事拆开，模型可以分别学好。

这三份数字在每一层都要重新算一遍：每层有自己的三张权重表，同一个 token 在第 4 层和第 8 层算出来的 Q、K、V 各不相同。

## 注意力分数和 softmax：先定该看谁多少，再按比例收内容

有了 Q、K、V，「看」分三步走。拿「它」举例：

**第一步，打分。** 「它」拿自己的 Q，和前面每个 token 的 K 各算出一个数，叫**注意力分数**，表示「该看它多少」。怎么算：Q 和 K 都是一串同样长的数字，对应位置两两相乘，再全部加起来，得到一个数。两串数字越「对得上」，这个数越大。实际还会再除以一个固定的数（下面会讲到，这个模型里是 16），免得分数太大。

**第二步，换算成比例。** 一排注意力分数有正有负、大小不一，不能直接拿来当比例用。**softmax** 就是把这一排数换算成「每个都是正数、加起来正好等于 1」的比例：先把每个分数变成正数（分数越大变得越大，差距被拉开），再各自除以总和。换算完，分数最高的那个通常占掉大头。

**第三步，按比例收内容。** 用这组比例，把前面各家的 V 加权加起来：占 0.7 的就拿它 V 的七成，占 0.05 的只拿一点点。加出来的这一份，就是「它」从前面收到的内容。

图里的比例是编出来示意的，但形状是真的：「它」把 0.7 的注意力给了「小猫」，于是收进来的内容大半来自「小猫」的 V——「它」这串数字里从此就带上了「小猫」的信息。

注意「它」自己也在被看的名单里：一个 token 看的是**自己和前面所有 token**，不是只看别人。

收回来的这份内容，最后还要再乘一张权重表变回 2048 个数字，作为这一层注意力段算出的「修改量」，加回「它」原来那串隐藏向量上（加回去而不是换掉，是[层与隐藏向量](layers-and-hidden.md)那一页讲过的规矩）。

## 因果掩码：每个 token 只看得见自己和前面

图右边那道虚线后面的「睡着」，「它」是看不见的。

原因在于模型生成回答是**从左到右一个一个吐**的：吐「它」的时候，后面的「睡着」还不存在，根本没得看。模型训练时也是照这个规矩学的——每个位置只准看自己和前面，学的是「根据前文猜下一个」。

那如果后面的 token 其实已经在手里呢？比如你问的那 37 个 token，第一步是一起送进去算的，第 5 个 token 算注意力时，第 6 到第 37 个就摆在旁边。这时也得挡住：模型学的时候从来没偷看过后文，现在让它看，算出来的就不是它学会的那种东西了。

挡住后面的这道闸，叫**因果掩码**。做法很直接：在第二步换算比例之前，把「后面的 token」那几格的注意力分数全部改成负无穷。softmax 之后它们的比例就是 0，一点 V 都不会收进来。

生成回答时（每步只送进 1 个新 token），新 token 本来就排在最后，后面没东西可挡，这道闸自然就不起作用了；它真正干活是在第一步一次送进一整段的时候。

## 注意力头：同一层里并排做 16 份

上面讲的是「一份」注意力。实际每层里是**好几份并排做**，一份叫一个**注意力头**。

每个头有自己的一套 Q、K、V，各算各的注意力分数、各收各的内容。为什么要分好几份？因为一个 token 想从前面找的东西不止一种：一个头可能专门找「我指代的是谁」，另一个可能盯着「紧挨在我前面的词」。一个头只能算出一组比例，分成多个头，就能同时按几种不同的标准去看。哪个头看什么，是训练出来的分工，不是人规定的。

落到这个模型：全注意力层有 **16 个 Q 头**，每个头的 Q 是一串 **256** 个数字——这个「一个头里那串数字有多长」叫**头维度**。前面说打分时要除以的那个固定数 16，就是 256 的平方根。

但 K 和 V 的头没有 16 个，只有 **2 个**：16 个 Q 头分成两组，每 8 个共用同一份 K、V。8 个 Q 头拿着各自不同的问题，去对同一组名牌、听同一组内容，算出 8 组不同的比例。

K、V 的头为什么可以比 Q 少、这样省下的是什么，是 [GQA](gqa.md) 那一页的主题，这里只要记住：**Q 头 16 个，KV 头 2 个，每个头的数字都是 256 长。**

16 个头各自收回来的内容（每份 256 个数字）拼在一起，就是上一节最后那一步「再乘一张权重表变回 2048 个数字」的原料。

## 落到例子上：每步只有 1 个新 token，却要看前面全部

回到[贯穿例子](one-request.md)：问题 37 个 token，回答 200 个 token。

第一步，37 个 token 一起送进去，每个都照上面的办法看自己和前面：第 1 个只看自己，第 37 个看全部 37 个。

之后生成回答的每一步只送进 1 个新 token，但这个新 token 要看的是**前面全部**：回答写到最后一步时，送进去的那个 token 连同它自己，要看 236 个 token。

问题来了：看前面那 235 个，要用它们的 K 和 V。这些 K、V 如果每一步都重新算，就得把前面所有 token 在这一层之前的全部计算重做一遍——一步比一步亏得多。

所以换个做法：每个 token 的 K 和 V 算出来一次就**存下来**，后面每一步新来的 token 直接拿存好的去打分、收内容。只存 K 和 V，不存 Q——Q 只在自己那一步拿去问一次，问完就没用了；而 K 和 V 是后面每个新 token 都要来问、来收的。

这份存下来备查的 K、V，就是 [KV Cache](kv-cache.md)。它怎么存、占多少地方，在那一页。

## 40 层里只有 10 层这样「回头全看」

最后交代一句：上面讲的这种注意力，每个 token 都要把前面所有 token 挨个打一遍分，前面越长越费事。这个模型的 40 层里，只有 **10 层**是这种「回头全看」的注意力（叫全注意力）；另外 30 层用的是另一种省事的办法，不逐个回看前面的 token，只维护一份固定大小的「状态」，那一种叫[线性注意力](linear-attention.md)。

所以上面说的 16 个 Q 头、2 个 KV 头、存 K 和 V，都只发生在那 10 层里。
