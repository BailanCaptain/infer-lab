## hidden 是什么，一层又在做什么？

**hidden（隐藏向量）是模型给每个输入位置维护的一排连续数值，逐层汇总该位置从上下文获得的信息。** 在标准单残差流 Transformer 中，每一层读取本步各位置的 `hidden`，算出每个位置的改变量并加回原向量，再把结果交给下一层。

模型读一段文本时，先把它切成 [token](token.md)（文本切出的小片段；这里为了好读，一个词算一个），每个 token 占一个位置。[Embedding](embedding.md)（词嵌入）按每个 token 的编号查表，给每个位置发一排数作为 `hidden` 的起点。一条 `hidden` 含多少个数叫 `hidden_size`（隐藏维度，真实模型通常为几千维，下图画 4 维示意）；一次处理 $T$ 个位置就拼成 `[T, hidden_size]` 的矩阵。

拿这句话来说：「小明把书借给小红，因为她……」。刚查完表时，「她」这个位置的 hidden 只代表「她」这个词本身，放进哪句话里都一样。往上每过一层，它就多带上一点上下文：先是注意到前面有个「小红」，接着是「她」指的就是小红、而小红刚从小明那里借到了书。到最后一层，这个位置的 hidden 已经攒够了信息，可以拿来猜下一个词。这是打比方，hidden 里的几千个数并不能一个个读出「谁是谁」；但「每层都在上一层交出的结果上接着改」这一点，就是模型实际的算法：


图里每一层都分两段，每段叫一个子层：

- **attention 段**让每个位置去看上下文里的其他位置，按相关程度把它们的信息取过来。主流自回归生成模型（如 `Qwen3-8B`）只用 Transformer 解码器（decoder）一侧，每个位置只看自己和前面的位置，所以这种层也叫 Decoder 层。attention 是层里唯一让位置之间交换信息的一步，具体算法见 [attention](attention-qkv.md)。
- **MLP 段**对每个位置各自做一次变换。MLP（前馈网络）是一个「升宽 → 过一个非线性函数 → 降回原宽」的小网络，位置之间不交换信息，加工的是 attention 刚取来的内容，见[前馈网络](mlp-residual-norm.md#前馈网络怎样变换一个位置的特征)。

两段算出的都不是一条新的 hidden，而是「要改多少」，算完加回原来的 hidden，下一节讲为什么这样设计。层与层交界处 hidden 的宽度始终不变，所以任何一层的输出都能直接交给下一层；层内部的投影可以临时换宽度，出来时再回到 hidden size。最后一层之后，用最后一个位置的 hidden 给词表里每个候选词打一个分，下一个 token 就从这些分数里选出来；分数怎么算见后文[很多层叠起来](#很多层叠起来hidden-怎样从头走到尾)一节末尾。

## 为什么要叠很多层，又为什么是「加回」？

**单层只能做一次跨位置取信息与逐位置加工，多跳指代依赖多层串联传递；每段只算改变量并加回原向量，则为输入留出直达末层的恒等通路，使深层网络能够稳定训练。** 注意按维相加仍可能改写或抵消旧分量，并不保证早期信息原封不动。

**一层为什么不够。** 同一层里，所有位置读到的都是上一层交出的 hidden。回到上面的图：第 1 层里「小红」读了「借给」，它交出的 hidden 才带上「是小红借到了书」；可同一层里「她」要是去读「小红」，读到的还是查表得来的那条，只有「小红」这个词。要等到第 2 层，「她」再读「小红」，拿到的才是已经合进「借到了书」的那条。每多一层，信息就能多转一手，一个位置能用上的推理也多一步。这仍是简化的比方，真实模型里每层学到什么由训练决定；但「同一层里大家读的都是上一层的结果」是算法本身的规定。另一方面，每一层的本事是固定的：attention 按比重取一次信息，MLP 是一个大小固定的小网络；要表达更复杂的规律，就把更多层接起来，让后一层在前一层的结果上继续加工。

**代价。** 每层有自己的一套权重，层数越多，权重越多；每个 token 要做的计算也跟着层数成倍增加。而且对同一批位置来说，第 n 层必须等第 n − 1 层算完才能开始，层与层之间只能一层一层串着算。

**为什么是加回，不是换掉。** 如果每一层都交出一条全新的 hidden，前面各层攒下的信息就得靠每一层重新抄一遍才留得住，哪一层没抄好就丢了。改成「算改变量再加回」以后，一层没什么要补的，改变量接近 0，hidden 就原样通过；要补的，也只是在原有内容上添一笔。这条让输入绕过子层、直接送到出口去相加的旁路叫 **residual（残差连接）**。它也让很深的网络训得动：ResNet（一种图像识别网络）的作者发现，没有这条旁路时一味加深网络，连训练误差都会变高；有了它，几十上百层也能训下去。训练上的原因见[残差连接](mlp-residual-norm.md#残差连接保留一条输入路径)。

## 一层怎么算？跟着一条 hidden 走一遍

**一层的两段做的是同一套动作：把 hidden 复制一份走支路，先做 RMSNorm、再送进 attention 或 MLP，算出改变量；原来的 hidden 沿旁路直接到出口，和改变量按维逐个相加。先做 attention 段，再做 MLP 段。**

RMSNorm（均方根归一化）是支路入口的那一步：把向量里每个数除以这排数的均方根（先平方、再求平均、再开方），再逐个乘一组学到的系数，调整送进子层的尺度。实际分母还带数值稳定项 ε；它和另一种归一化 LayerNorm 的区别、那组系数怎么起作用，见 [RMSNorm](mlp-residual-norm.md#rmsnorm-怎样调整向量尺度)。下面为便于手算，把系数设为 1、ε 设为 0。

下面跟着「她」这个位置走完第 1 层。为了能手算，`hidden` 只取 4 个数：`x = [2, 1, 2, 0]`，就是本页第一张图里「她」在 `embedding` 那一行标出的 4 个数（数值为示意，算法与标准单残差流 Transformer 如 `Qwen3-8B` 完全一致；多路残差 `mHC` 变体见后文[复杂异构实战对照](#复杂异构实战对照glm-双机-45-层异构与-mhc-四流残差)）。

```wiki-diagram
file: layers-one-layer
```

**① 支路先做 RMSNorm。** x 的均方根是 √((2² + 1² + 2² + 0²) ÷ 4) = √2.25 = 1.5，每个数除以 1.5，得到 [1.33, 0.67, 1.33, 0]。旁路上的 x 不做这一步，原样等在出口。这种只在支路入口做归一化的排法叫 pre-norm。

**② attention 算出改变量。** 归一化后的这一条和其他位置一起送进 attention：按相关程度从各位置取来信息，再乘一个输出投影矩阵变回 4 个数，得到改变量 Δ₁ = [1.2, 0.6, −0.4, 0.8]。这几个数是示意，attention 内部怎么算见 [attention](attention-qkv.md)。

**③ 加回。** x 和 Δ₁ 按维逐个相加：第 1 维 2 + 1.2 = 3.2，第 3 维 2 + (−0.4) = 1.6，四维合起来是 x′ = [3.2, 1.6, 1.6, 0.8]。加的是旁路上没有归一化的 x，不是 [1.33, 0.67, 1.33, 0] 那一条。逐个相加要求两边一样长，所以 attention 的输出最后一定回到 hidden 的宽度。

**④ MLP 段再来一遍。** $x'$ 做 RMSNorm，均方根正好是 2，得到 $[1.6, 0.8, 0.8, 0.4]$；送进 MLP，得到改变量 $\Delta_2 = [-0.4, 0.3, 0.5, -0.2]$（示意）；加回 $x'$，得到 $x'' = [2.8, 1.9, 2.1, 0.6]$。这就是这一层交给下一层的 hidden，仍是 4 个数：

| 单层内步骤（Pre-Norm 示意数） | 算式 | 结果 |
| --- | --- | --- |
| $x$ 的均方根 | $\sqrt{(2^2 + 1^2 + 2^2 + 0^2) \div 4} = \sqrt{2.25}$ | $1.5$（支路缩放，旁路不变） |
| attention 段残差加回 $x'$ | $[2,\; 1,\; 2,\; 0] + [1.2,\; 0.6,\; -0.4,\; 0.8]$ | $[3.2,\; 1.6,\; 1.6,\; 0.8]$ |
| $x'$ 的均方根 | $\sqrt{(3.2^2 + 1.6^2 + 1.6^2 + 0.8^2) \div 4} = \sqrt{4}$ | $2$（支路缩放，旁路不变） |
| MLP 段残差加回 $x''$ | $[3.2,\; 1.6,\; 1.6,\; 0.8] + [-0.4,\; 0.3,\; 0.5,\; -0.2]$ | $[2.8,\; 1.9,\; 2.1,\; 0.6]$ |

一次处理 T 个位置时，hidden 是 [T, 4] 的矩阵，每行一个位置。RMSNorm、MLP 和加回都是一行一行各算各的，只有 attention 这一步让一行去读别的行；同一层的权重被这 T 个位置共用。改变量也可以很小：Δ 全是 0 时，这一段就让 hidden 原样通过。

## 很多层叠起来，hidden 怎样从头走到尾？

**embedding 交出第一条 hidden；之后每一层都把上一层的输出当输入，做一遍上一节的两段；最后一层交出的 hidden 经过最终归一化和输出投影，变成词表里每个词的分数。一路上 hidden 只是在同一条线上被一笔一笔地往上加，这条线叫 residual 流（残差流）。**

每一层的骨架相同，但各有自己的一套权重；同一层的权重被本步所有位置和请求共用。标准 Pre-Norm 模型（如 `Qwen3-8B` 等 Dense 架构）全程沿这一条单残差流从第 0 层堆叠到末层。上一节的位置走完第 1 层变成 $[2.8, 1.9, 2.1, 0.6]$，第 2 层就从这里起步，重复「RMSNorm → attention → 加回」「RMSNorm → MLP → 加回」直至末层。把加法摊开看，每一层交出的 hidden 都等于起点加上此前所有子层的改变量：

$$h_{\text{final}} = x_0 + \Delta_1 + \Delta_2 + \Delta_3 + \dots + \Delta_{2L}$$

| 堆叠位置（接上节示意数） | 展开累加式 | 结果 |
| --- | --- | --- |
| 第 1 层交出 | $[2,\; 1,\; 2,\; 0] + [1.2,\; 0.6,\; -0.4,\; 0.8] + [-0.4,\; 0.3,\; 0.5,\; -0.2]$ | $[2.8,\; 1.9,\; 2.1,\; 0.6]$ |
| 末层交出（共 $L$ 层） | 起点 $x_0$ 累加沿途全部 $2L$ 个子层改变量 | 送入最终 RMSNorm 与 `lm_head` |

所以 residual 流就是一条从 embedding 通到最后一层的主线：每个子层都从它上面读一份（先做 RMSNorm），再把改变量加回它上面。前面写进去的内容，后面每一层都读得到；后面每一层也都只能往这同一条线上加。

最后一层之后，hidden 先做最终 RMSNorm，再乘输出投影（`lm_head`，一个把 hidden size 维映射到词表大小的权重矩阵），得到每个候选词的分数，交给采样选出下一个 token。

hidden 是前向过程里逐层传递的中间表示，不是长期保存全部历史的 KV cache。它用完后可以释放或覆盖；在开启投机解码（如 MTP 草拟）的场景下，主模型输出 hidden 还会继续交给草拟模块使用。供下一轮 attention 读取的历史另存于 [KV cache](kv-cache.md)；三者的区别见后文[本轮 hidden、历史状态和权重各管什么](#本轮-hidden历史状态和权重各管什么)。

## 标准主干走读：Qwen3-8B 的 36 层同构单流残差

在 `v0.30.0` 标准主基线下，**Qwen3-8B** 是最典型的同构单流 Transformer：36 层（编号 `0–35`）结构完全一致，全程只维护**一条 `[T, 4096]` 残差高速公路**，不存在跨层异构切换，也不做多流混合。

```wiki-diagram
file: layers-stack-qwen3
```

沿图从左到右走完一次前向（本步共 $T$ 个 token、BF16 精度）：

1. **词表查表建立起点。** `embed_tokens`（形状 `[151936, 4096]`）为 $T$ 个输入 token 查出初始单流 `hidden`，形状 `[T, 4096]`。
2. **36 层同构串联。** 第 `0–35` 层结构 100% 相同，固定执行「2 次 Pre-RMSNorm（`eps = 1e-6`）+ 2 次残差相加」：先走 `input_layernorm` → GQA（`32Q : 8KV`，头宽 128，带逐头 QK-Norm 与全维 RoPE）→ 残差相加；再走 `post_attention_layernorm` → SwiGLU（`4096 → 12288 → 4096`）→ 残差相加。每层各有独立权重，但在层交界处形状恒为 `[T, 4096]`。
3. **末层收口与采样。** 出第 35 层后经最终 `model.norm`（RMSNorm）归一，再精选需预测的位置行送入独立非绑定的 `lm_head [4096, 151936]`（`tie_word_embeddings = false`），产出词表分数交给采样。

| Qwen3-8B 逐层栈关键指标（BF16，单步 $T$ 个 token） | 数值 | 说明 |
| --- | --- | --- |
| 层数与异构切换 | `36` 层，0 次层型切换 | 第 `0–35` 层全部为同构 GQA + SwiGLU |
| 层间残差流宽度 | 单条 `[T, 4096]` | 每 token 残差占 $4{,}096 \times 2\text{ B} = 8{,}192\text{ B}$（`8 KiB`） |
| 主干 RMSNorm 次数 | 合计 `73` 次（$36 \times 2 + 1$） | 36 层子层入口 `Pre-RMSNorm` 共 `72` 次 + 末层独立最终 `model.norm` `1` 次（不含每层 Attention 内部独立的 `q_norm` / `k_norm`） |
| 主干残差相加次数 | $36 \times 2 = 72$ 次 | 昇腾侧通常与下一处 RMSNorm 融合为 `npu_add_rms_norm` |

**边界与例外。** 在稀疏 MoE 同构模型中（如 `Qwen3-30B-A3B`，48 层、`hidden_size = 2048`），层间依然保持同一条单残差流 `[T, 2048]`，仅将每层的稠密 SwiGLU 替换为 128 选 8 的 MoE；只有当模型同时引入多种注意力层型交替与多流残差混合时，才会进入下面要拆解的复杂异构路径。

## 复杂异构实战对照：GLM 双机 45 层异构与 mHC 四流残差

本节为例外 B 历史绑定算例（`GLM-5.3-Flash` 双机 2×A2×8，TP8 / DP2 / EP16、W8A8）。与 `Qwen3-8B` 36 层同构单流不同，GLM-5.3-Flash 把层数扩到 45 层（34 层 KDA 与 11 层稀疏 MLA 交替、前 3 层稠密 MLP + 后 42 层 MoE），并在层间用 **mHC** 同时维护四条并行残差流。

### 一层接过什么、交出什么？GLM 为什么在层间传四条？

**前面讲的是常见做法：层与层之间只传一条 hidden。GLM-5.3-Flash 在层与层之间同时传四条这样的向量，叫四条残差流：一层接过四条、交出四条；每段子层先从四条里合出一条去计算，再把结果写回四条，旁路上的旧四条流之间还要按一个 4×4 矩阵互相混合。**

这套连接方式叫 **mHC**（Manifold-Constrained Hyper-Connections）。它的前身 Hyper-Connections（超连接）把上一节那一条 residual 流扩成 n 条并行的流，并规定流之间怎样混合、子层结果怎样写回；mHC 在此基础上给混合加了约束，下一节讲。GLM 取 n = 4。子层本身不变，送进去的仍是一条和普通 hidden 一样宽的向量，所以上面讲的 RMSNorm、attention、MLP 都照旧，变的只是子层外面「从哪读、往哪写」。下面仍用示意数，每条流也按 4 个数算，但图里只画四条流的第 1 维：


图里是一段子层（attention 段或 MLP 段）的一次进出。一层有两段，所以一层做两次：

1. **分出一路。** 入口先根据四条流当前的值算出一组系数，其中 4 个入口权重把四条流加权合成一条。第 1 维是 0.5 × 4 + 0.1 × 0 + 0.3 × 2 + 0.3 × 2 = 3.2，其余 3 维用同样 4 个权重各算一遍。合出的这一条，形状和普通模型的 hidden 一样。
2. **计算。** 这一条先做 RMSNorm，再送进 attention 或 MLP，输出仍是一条。图里它的第 1 维是 0.5（示意）。
3. **写回。** 子层输出按 4 个写回权重分别加到四条流上，每条流分到的份量不同：0.5 × [1.2, 0.4, 0.8, 1.6] = [0.6, 0.2, 0.4, 0.8]。
4. **汇合。** 旁路上的旧四条流不是原样通过，而是先经过一个 4×4 混合矩阵互相混合，再和写回的量按流相加，成为下一段的四条流。矩阵第 $g$ 行第 $h$ 列的数，表示旧流 $g$ 有多少份量进入新流 $h$，所以新流 $h$ 取的是第 $h$ 列（单条残差在这一步只做 $x + \Delta$；mHC 多出来的是入口合成、写回分配和旧流混合，下表按第 1 维示意数计算）：

| 新流编号 | 旧流加权混合算式 | 混合结果 | 加子层写回（$[0.6,\; 0.2,\; 0.4,\; 0.8]$） |
| --- | --- | --- | --- |
| 新流 1 | $4 \times 0.50 + 0 \times 0.13 + 2 \times 0.13 + 2 \times 0.24$ | $2.74$ | $2.74 + 0.6 =$ **$3.34$** |
| 新流 2 | $4 \times 0.15 + 0 \times 0.59 + 2 \times 0.12 + 2 \times 0.14$ | $1.12$ | $1.12 + 0.2 =$ **$1.32$** |
| 新流 3 | $4 \times 0.15 + 0 \times 0.12 + 2 \times 0.59 + 2 \times 0.14$ | $2.06$ | $2.06 + 0.4 =$ **$2.46$** |
| 新流 4 | $4 \times 0.20 + 0 \times 0.16 + 2 \times 0.16 + 2 \times 0.48$ | $2.08$ | $2.08 + 0.8 =$ **$2.88$** |

入口权重、写回权重和混合矩阵这三组系数，都是入口按四条流当前的值一次算出来的：一部分当入口权重，一部分送到写回那一步当写回权重，一部分送到旁路上当混合矩阵。它们是每个 token 按自己此刻的四条流单独算出来的，不是全模型共用的常数；学出来并固定下来的，是「怎样从四条流算出这些系数」的那组参数。入口算出的原始混合系数可以是任意数，Sinkhorn 迭代使每行、每列的和接近 1；图中用一个两位小数的双随机矩阵演示目标性质。下一节讲为什么要这样约束，以及有限轮迭代与精确等式的区别。

### 为什么要四条流，Sinkhorn 又管什么，代价在哪？

**多条流让每个子层能学着选择从哪几条读、往哪几条写；但 45 层 × 2 段 = 90 次混合是串起来的，旁路上的信息要连着被乘 90 次，混合矩阵只要稍微放大或缩小，连乘后就会失控。Sinkhorn 把每次混合限制成「加权平均」，换来稳定；代价是每段多一次小矩阵乘和 20 轮迭代，残差占的字节变成四倍。**

**为什么不只留一条。** 单条残差里，每层只能往同一条向量上叠加改动，也就是上面那串「起点 + Δ₁ + Δ₂ + …」的加法：早先写进去的信息和后来的改动混在一起，谁也拿不出来。Hyper-Connections 把残差加宽成 n 条：子层可以按 token 学着决定从哪几条读、写到哪几条，旧流之间也能交换内容，层与层之间怎样连由训练决定，不再只有一条直通。mHC 论文把这种做法概括为加宽残差流、让连接方式多样化，并报告了明显的效果提升。

**不加约束会怎样。** 最初的 Hyper-Connections 对 $n \times n$ 混合矩阵不加限制。第 0 层入口的内容要走到最后一层，途中经过的是全部 90 个混合矩阵的连乘：每个矩阵哪怕只把数放大一点点，连乘后也会爆炸；缩小一点点，连乘后就趋于 0。设四条流的第 1 维都是 1（暂不算子层输出，示意）：

| 单次列和倍数 | 连乘 90 次算式 | 末层幅值结果 |
| --- | --- | --- |
| 每次放大 $\times 1.1$ | $1.1^{90}$ | $\approx$ **$5{,}313$**（幅值爆炸） |
| 每次缩小 $\times 0.9$ | $0.9^{90}$ | $\approx$ **$0.000076$**（信号趋零） |
| 严格守恒 $\times 1$ | $1^{90}$ | **$1$**（保持稳定） |

单条残差原本有一个好性质，输入能原样直达出口（恒等映射），相当于每次都乘 1；加宽后这个性质丢了。mHC 论文指出，这正是它在大规模训练里不稳定、难以放大的原因。下图把标准 Pre-Norm 单残差高速路、GLM 四流 `mHC` 与 90 次串行连乘的幅值标尺放在一起对照：

**Sinkhorn 把混合矩阵变成双随机矩阵。** 双随机矩阵的每个数都不小于 0，每行、每列加起来都是 1。上一节图里的矩阵就是一个双随机矩阵，用它混合旧流有三个直接后果：

- 每列和为 1：每条新流都是四条旧流的加权平均，每一维的数都落在四条旧流这一维的最小值和最大值之间。新流 1 取第 1 列的 0.50、0.13、0.13、0.24，混出的 2.74 落在旧流的 0 和 4 之间。
- 每行和为 1：每条旧流的内容恰好分完，四条流加起来的总量混合前后不变。旧流 1 的 4 按第 1 行的 0.50、0.15、0.15、0.20 分给四条新流；四条合计混合前是 4 + 0 + 2 + 2 = 8，混合后 2.74 + 1.12 + 2.06 + 2.08 仍是 8。（严格说实际算出的矩阵行和只是接近 1，总量也就近似不变，原因见下文 20 轮那一段。）
- 两个双随机矩阵相乘仍是双随机矩阵：连乘后，每条输出仍是输入流的加权平均，各流的总和保持不变。这约束了混合系数的整体缩放，却不保证所有方向的信息保留。例如四条流某一维为 [1, −1, 1, −1]，每项都为 1/4 的双随机矩阵会把它们混成全零；不同流仍可抵消。单位矩阵也是双随机矩阵，“原样直通”是其中一个特例。

**Sinkhorn 迭代怎样做到。** 入口算出的 16 个原始混合系数排成 4×4，先按行做 softmax：每个数取 e 的这个数次方，再除以这一行的总和，得到全是正数、每行和为 1 的矩阵（softmax 的完整演算见 [attention](attention-qkv.md)）。这时列和还不是 1：下图第 ① 张里，新流 1 那一列加起来是 1.3，相当于每次放大 1.3 倍。接着一轮一轮地做：每一行除以这一行的和，每一列除以这一列的和。每做一次，一个方向的和变成 1，另一个方向被轻微打乱；来回几轮后两个方向都接近 1。

| 迭代步骤 | 算式 | 结果 |
| --- | --- | --- |
| 第 1 行原始系数取指数 | $[e^{1.79},\; e^0,\; e^0,\; e^{0.69}]$ | $\approx [5.99,\; 1,\; 1,\; 1.99]$（行和 $9.98$） |

| 第 1 列的和与列归一 | 列和 $0.6 + 0.2 + 0.2 + 0.3 = 1.3$；各元素 $\div 1.3$ | $\approx [0.462,\; 0.154,\; 0.154,\; 0.231]$ |
| 第 1 轮后第 1 行的和 | $0.462 + 0.125 + 0.125 + 0.182$ | $\approx 0.89$（下一轮继续按行、按列拉回 $1$） |

GLM 配置的是 20 轮，和 mHC 论文实验所用的轮数相同。轮数有限，而且参考实现还加入很小的数值稳定项，所以结果是近似的：每轮先按行、后按列归一，最后一步按列，行和与列和都应理解为接近 1，不能当成精确等式。

**入口和写回权重也有范围。** 入口权重经过 sigmoid（把任意数压到 0 到 1 之间的平滑函数），参考实现再加很小的稳定项；写回权重是 2 × sigmoid，范围相应为 0 到 2。图里的 0.5、0.1、0.3、0.3 和 1.2、0.4、0.8、1.6 都满足约束。系数非负只表示不由系数翻转符号；隐藏向量本身可正可负，合成与写回仍可能抵消。Sinkhorn 约束旧流之间的混合，子层输出随后加回，并不保证整个网络的数值或信息量恒定。三种连接方式对照如下：

| 连接方式 | 层间传几条 | 旧流怎样混合 | 子层输出怎样加回 |
|---|---|---|---|
| 单条残差 | 1 条 | 不混合，原样直通 | 直接相加 |
| Hyper-Connections | n 条 | n×n 矩阵，数值不受约束 | 按学到的权重写回 n 条 |
| mHC（GLM 用的） | n 条，GLM 取 4 | Sinkhorn 使每行、每列和接近 1 | 写回权重限制在 0 到 2 |

**为什么是 4 条。** 条数 n 同时决定收益和代价：残差要存 n 份，入口每次要算 (2 + n) × n 个系数，混合矩阵是 n × n。GLM 的配置写的是 4 条，mHC 论文的实验也取 n = 4；n = 4 时每段入口算 24 个系数（4 个入口权重、4 个写回权重、16 个混合系数）。所引 GLM 配置没有说明选 4 的实验依据，不能把 mHC 论文的选择自动当作 GLM 的选型理由。

**代价落在哪里。** 每段入口要把 n 条流拼成一条长向量，做一次不带可学习增益的 RMSNorm（只用来算系数，不改这 n 条流），再乘一个小矩阵得到 (2 + n) × n 个系数，然后跑 20 轮 Sinkhorn；出口再做一次写回加混合。残差要存的字节变成 n 倍。这些混合运算本身在卡内完成；若层与层跨[流水线并行（PP）](pipeline-parallel.md)阶段，四条流等中间状态仍要跨卡传递，不能把卡内混合等同于整条路径没有通信。拿示意数说：hidden 只有 4 个数、n = 4 时，长向量是 4 × 4 = 16 维，小矩阵是 16 × 24，残差从 4 个数变成 16 个数。GLM 真实尺寸下的开销放在后文[mHC 在 GLM 上多花了什么](#mhc-在-glm-上多花了什么)。

### GLM 双机下的 45 层异构走读

**GLM-5.3-Flash 的文本主干有 45 层，编号 0–44；hidden 宽 4096。一次前向里，hidden 从 embedding 出来是一条，进第 0 层时变成四条，45 层里每层做两次 mHC，第 44 层结束时求平均回到一条，再去算词表分数。**

固定部署是两台 Atlas 800 A2（每台 8 张卡，共 16 张），并行与精度取 `TP8 / DP2 / EP16`、`W8A8`（前提统一见[部署前提](glm-5-3-flash-two-node.md#部署前提)）：

- **TP8**（[张量并行](tensor-parallel.md)）：把同一层大矩阵切给单机 8 张卡合算。
- **DP2**（[数据并行](data-parallel.md)）：两台机器各成一组，各有独立调度和 KV cache，请求按负载分发。每组 8 卡也构成下文的 **TP 组**。
- **EP16**（[专家并行](expert-parallel.md)）：把 288 个路由专家摊到全部 16 张卡（每卡 18 个），同一请求的专家计算可跨组。
- **W8A8**（[量化](quantization.md)）：权重和激活主体用 INT8 加缩放系数，但并非处处量化（如 mHC 混合参数保持 FP32，逐部件口径见[部署页的每卡账](glm-5-3-flash-two-node.md#每张卡上放了什么)）。

一条请求先经过 **prefill** 处理提示词并建立各层历史（可一次完成或分块，见 [prefill](prefill.md)），再逐轮 **decode** 生成。固定部署还开启了**投机解码**（speculative decoding）：主干之外的 **MTP** 层草拟候选，下一轮由主干一起验证（见[投机解码](speculative-decoding.md)与[模型 MTP](glm-5-3-flash.md#mtp主干之外的第-45-层)）。下面沿示例请求 R1 走一遍：提示词 4 个 token 一步算完（$T = 4$，完整设定见[示例请求](one-request.md#示例请求-r1-与官方双机部署)）。

下面的逐卡形状与 All-Reduce 算例采用**普通 TP、[序列并行（SP）](sequence-parallel.md)关闭**的教学基线。它不是只看默认环境就能确定的实测配置：固定实现还可能因共享专家 DP 条件启用 SP，须检查最终配置；共同条件见[版本与来源基线](../sources/glm-5-3-flash-baseline.md#双机示例与教学视图)。版本节另列 SP 开启时按 token 切分的行为。

### 45 层怎样排

每层都是「attention 段 + MLP 段」，具体采用哪种子层由层号决定。这里出现三种子层：**KDA** 用固定大小矩阵状态汇总全部历史；**稀疏 MLA** 把历史压成低维潜向量后挑一部分去读；**MoE** 是一组专家 MLP，每个 token 只选其中几个。三者原理见 [KDA](glm-5-3-flash.md#kda把全部历史压进一个固定大小的矩阵)、[稀疏 MLA](glm-5-3-flash.md#稀疏-mla先把历史压短再挑着读) 和 [MoE](glm-5-3-flash.md#moe288-个专家里每次挑-8-个)，排法由来见[45 层怎样排](glm-5-3-flash.md#45-层怎样排)。

| 层号 | attention 段 | MLP 段 | 层数 |
|---|---|---|---|
| 0、1、2 | KDA | 稠密 MLP | 3 |
| 3、7、11、15、19、23、27、31、35、39、43 | 稀疏 MLA | MoE | 11 |
| 其余（4–6、8–10、…、40–42、44） | KDA | MoE | 31 |

按 attention 数：34 层 KDA、11 层稀疏 MLA，「KDA、KDA、KDA、稀疏 MLA」四层一组重复 11 次共 44 层，最后的第 44 层是 KDA。按 MLP 数：前 3 层稠密，后面 42 层全是 MoE。实现按层号分别建出每一层的模块，45 层各有一份权重，不是反复调用同一份；权重怎样在层内共用、层间不同，见上文[很多层叠起来](#很多层叠起来hidden-怎样从头走到尾)。

稠密 MLP 和每个专家内部是同一种前馈结构，只是宽度不同，见[前馈网络](mlp-residual-norm.md#前馈网络怎样变换一个位置的特征)。不管子层是哪一种，层与层之间的连接都一样：每段前后各一次 mHC。所以 mHC 的次数只看层数，一次前向固定是 45 × 2 = 90 次，与层型无关。一层两段首尾相接的样子见[模型总览的单层图](glm-5-3-flash.md#一层有两段计算四条-residual-流贯穿两段)。

这里的 90 次只统计 45 层主干，不包含额外执行 MTP 模块的计算。

1. **embedding。** 4 个编号查表得到 [4, 4096]。TP8 下每张卡只存词表的八分之一，各查一段再做一次 All-Reduce（组内各卡按位置相加并都拿到结果，见[集合通信](collective-communication.md#all-reduce)），8 张卡都得到完整的 [4, 4096]。查表细节见[Embedding 的 GLM 双机一节](embedding.md#放到-glm-双机8-张卡怎么查同一张表)。
2. **第 0 层入口复制成四条。** [4, 4096] 复制四份成 [4, 4, 4096]：4 个位置、4 条流、每条 4096。实现把后两维摊平，存成 [4, 16384]；两种写法是同一份数据，[T, 4, 4096] 是讲道理用的逻辑形状，不规定内存布局。刚复制时四条完全相同，差别是之后的混合和写回一点点造出来的。R1 这份四条残差占多少字节见[主线页的词嵌入一节](one-request.md#词嵌入与四路残差)。
3. **每层的 attention 段。** 入口混合把 [4, 16384] 合成 [4, 4096]，经 RMSNorm 送进 KDA 或稀疏 MLA。attention 的输出投影在 TP8 下按行切，末尾一次 All-Reduce 让 8 张卡都拿到完整的 [4, 4096]（切法见[TP 页](tensor-parallel.md#先过-attention各算自己的头再合回-hidden)）；拿齐以后才写回四条流，得到新的 [4, 16384]。
4. **每层的 MLP 段。** 同样先入口混合、再 RMSNorm，送进稠密 MLP 或 MoE；MoE 把 token 派到专家所在的卡、算完收回来，这些通信都在子层内部完成，写回时手里已是完整的 [4, 4096]。
5. **第 44 层结束时求平均。** 第 44 层 MLP 段写回之后，四条流沿「流」这一维直接求平均，回到 [4, 4096]。这是不带权重的平均，不是再学一次混合。
6. **最终 RMSNorm 和输出投影。** 就是上文[很多层叠起来](#很多层叠起来hidden-怎样从头走到尾)一节的最后一步，GLM 上的 lm_head 是一张「词表 × 4096」的权重；得到的分数交给采样那一步（[主线页](one-request.md#最终归一化与词表投影)）。不是每个位置都要算分数：R1 的 prefill 只取最后一个位置，前 3 个位置这一步的作用是把历史写进各层的状态。

这一路上有两种 RMSNorm，别混：mHC 入口那一次作用在拼起来的 16384 维长向量上，没有可学习的增益，只用来算混合系数，四条流本身不被它改动；子层前的 RMSNorm 作用在合成出来的 4096 维向量上，带每层自己学到的增益，结果才是子层的输入。代码里 mHC 入口在前，子层的 RMSNorm 在后。

四条流在 TP 组的 8 张卡上各有一份完整的，mHC 在每张卡上重复算一遍，结果相同，所以不需要通信。整次前向的集合通信次数和载荷见[主线页的通信账](one-request.md#一次前向的通信账)，里面没有一次属于 mHC。

### 哪几层的连接和别的层不一样？

**45 层里只有首尾两层多一步：第 0 层入口复制成四条，第 44 层出口求平均。主干之外的 MTP 层完全不走 mHC。其余层不管子层是什么，连接方式都相同。**

- **第 0 层。** 入口先把 embedding 交来的一条复制成四条，再做这一层的第一次入口混合。其他层接到的已经是四条。
- **第 44 层。** MLP 段写回之后多一步，四条流求平均回到一条，交给最终 RMSNorm。求平均不带可学习的权重；参考实现的注释特意写明，这一点和 DeepSeek-V4 用可学习权重汇合不同。
- **MTP 层（第 45 层）。** 它是模型附带的一层，用来给投机解码草拟候选，不属于 45 层主干。它只有一条普通残差：RMSNorm、子层、加回输入，没有 mHC 的混合参数。MTP 层的结构见[模型总览的 MTP 一节](glm-5-3-flash.md#mtp主干之外的第-45-层)。
- **KDA 层和稀疏 MLA 层、稠密层和 MoE 层。** mHC 只包在子层外面，看到的永远是进出子层的一条 4096 维向量。子层内部怎样切到 8 张卡、要不要跨卡通信，由子层自己决定，写回时手里已经是完整结果。

### mHC 在 GLM 上多花了什么

GLM 取 n = 4、hidden 宽 4096，把上文「代价落在哪里」的每一步换成真实尺寸：每段入口把四条流拼成 4 × 4096 = 16384 维的长向量，乘一个 16384 × 24 的小矩阵得到 24 个系数，再跑 20 轮 Sinkhorn。混合参数和四条流一样不按 TP 切，同一个 TP 组的 8 张卡各存一份、各算一遍：上文说过这样不需要通信，代价是下面这些开销每张卡都要付一遍。一次前向合计多做的事如下：

$$M_{\text{mHC,45L}} = 45 \times 2 \times 24 \times 16{,}384 \times 4\text{ B} = 45 \times 3.0\text{ MiB} = 135\text{ MiB}$$

| mHC 在 GLM 一次前向里多做的事（主混合矩阵为 FP32，每卡一份） | 算式 | 结果与备注 |
| --- | --- | --- |
| 入口混合次数（出口写回混合同为 90 次） | $45\text{ 层} \times 2\text{ 段}$ | **90 次** |
| Sinkhorn 总轮数 | $90\text{ 次} \times 20\text{ 轮}$ | **1,800 轮** |
| 每层主混合矩阵权重 | $2\text{ 套} \times 24 \times 16{,}384 \times 4\text{ B}$ | $3{,}145{,}728\text{ B} =$ **3.0 MiB** |
| 45 层主混合矩阵权重总计 | $45 \times 3.0\text{ MiB}$ | **135 MiB**（每套另有 24 个偏置和 3 个缩放，45 层共另加 9,720 B） |
| 每 token 的四条残差（按每数 2 B、SP 关闭计） | $4 \times 4{,}096 \times 2\text{ B}$ | **32,768 B**（单条残差为 8,192 B） |

### 本轮 hidden、历史状态和权重各管什么

各层 hidden（包括四条流）是本轮计算的中间表示。它们的用途和 attention 历史不同，生命周期也不能只用“一次前向”一概而论：

| 数据 | 放在哪 | 活多久 |
|---|---|---|
| 层内 hidden 与四条流 | 前向过程中的中间张量 | 用到后续层计算完成；底层缓冲可以复用 |
| 交给 MTP 的主模型输出 hidden | 草稿输入缓冲 | 主模型返回后仍供草拟使用，随后可被新输入覆盖 |
| 各层的 attention 历史 | KV cache：KDA 层存递推矩阵状态和短卷积状态，稀疏 MLA 层存潜向量、indexer 的池 K 和尾状态 | 跟着请求，一轮轮接着读写 |
| 模型权重 | 本部署常驻显存 | 加载后由请求共用；休眠、卸载或权重更新另有生命周期 |

KDA 和稀疏 MLA 留下的历史形式不同，不能把 hidden 和一种统一的 K/V 缓存混为一谈；两类历史各存什么见[KV cache 页](kv-cache.md#混合模型到底要保留哪几类状态)。prefill 和 decode 都完整走过 45 层，变的是本轮送进来的位置数和能读到的历史，不是层数。没有投机解码时，decode 每轮每条请求只送 1 个新位置（T = 1），但 attention 会读此前存下的历史，模型并不是只凭这一个位置做预测；固定部署开了 MTP 草拟，R1 的 decode 一步验证 1 + 3 = 4 个位置，所以也是 T = 4，见[主线页的第二圈](one-request.md#第二圈和第三圈decode-步一次验证-1--3-个-token)。多条请求同时在跑时，引擎把它们这一轮的位置拼成一批，T 是这一批的总位置数，见[并发请求](concurrent-requests.md)。

固定草拟入口会把主模型的 target_hidden_states 写进草稿缓冲，再作为模型输入传给 MTP；MTP 对它归一化并与新 token 的 embedding 拼接。因此“不是 KV cache”不等于“主模型返回后立即丢弃”。末层交出的是连续的向量，不是 token。模型层负责更新表示，输出投影负责给每个候选词打分，采样负责选出 token；这一轮之后什么时候开始下一轮由引擎决定，各组件的分工见[框架架构](vllm-v1-shape.md)。

## 常见误解

- **「每一层都把 hidden 整个重算一遍。」** 普通残差把子层输出加回原输入；改变量为 0 时原样通过。mHC 还混合旧流，所以子层输出为 0 时也不保证四条流各自不变。
- **「下一层拿到的是归一化以后的 hidden。」** 普通残差加回的是未归一化的原输入；mHC 加回的是旧流混合后的结果。子层入口的 RMSNorm 结果不直接充当下一层的残差。
- **「GLM 的 hidden 宽 16384。」** 子层的输入和输出都是 4096 维。16384 是四条流拼起来的宽度，只在子层之间的旁路上存在；embedding 的输出和末层求平均后的结果也都是 4096 维。
- **「四条流是四份模型，或者四个 attention 头。」** 四条流共用同一套子层和权重，每段只把合成出来的一条送进子层。它们的区别只来自入口权重、写回权重和混合矩阵，而这些系数是每个 token 单独算的。

- **「Sinkhorn 归一化的是 hidden。」** 它归一化的是 4×4 混合矩阵，hidden 的数值不受这个约束；子层输出照样按写回权重加上去。
- **「四条流从一开始就各不相同。」** 进第 0 层时四条是同一份的复制，差别由之后每段的混合与写回逐步产生。
- **「最后一层挑一条流当输出。」** 第 44 层结束时是四条求平均，不是取其中一条，也没有再学一组汇合权重。
- **「mHC 要按 TP 切，或者要跨卡通信。」** 混合参数每卡一份不切，四条流在 TP 组 8 张卡上各有一份完整的，各卡重复计算同样的结果，mHC 本身不产生集合通信。
- **「hidden 就是 KV cache。」** hidden 是计算中的表示，也可能继续供 MTP 草拟使用；它与各层 attention 保存的历史状态用途不同。KDA 和稀疏 MLA 的历史形式还不一样。
- **「decode 只送 1 个位置，模型只凭这个位置预测。」** 这个位置在每层的 attention 里会读取此前存下的历史；而且固定部署开了 MTP，R1 的 decode 一步送的是 1 + 3 = 4 个位置。
- **「45 层是同一层重复 45 次。」** 层的骨架相同，但每层有自己的权重（见[很多层叠起来](#很多层叠起来hidden-怎样从头走到尾)），attention 和 MLP 的类型也按层号不同。

## 对照源码

### 怎么开

mHC 不是运行参数，由模型配置决定：GLM 的配置写着 `mhc=true`、`hc_mult=4`、`hc_sinkhorn_iters=20`，层数 45、hidden 4096，层型由 `kda_layers` 和 `mlp_layer_types` 两张表给出。[S1] vllm-ascend 的配置类把 checkpoint 里的 `hc_mult`、`hc_sinkhorn_iters` 读进自己的 `mhc_num_residual_streams`、`mhc_sinkhorn_iterations`，两个名字同时保留。[C12]

Decoder 层构造时，只有 `self.mhc` 为真且不是 MTP 层，才建 `hc_attn_*`、`hc_ffn_*` 两套参数：每套一个 24 × 16384 的 FP32 矩阵、24 个偏置和 3 个缩放。[C4] checkpoint 里这些参数叫 `attn_hc.fn`、`ffn_hc.fn` 等，加载时按名字映射过去。[C13] 前向里 `self.mhc` 为假或是 MTP 层就走单条残差分支，否则走四条流分支。[C6]

### 会报什么错

- mHC 这段路径在 `glm5_next.py` 里没有自己的 `raise` 或 `assert`。它直接调用 vllm-ascend C++ 扩展里的两个融合算子 `npu_hc_pre_v2`、`npu_hc_post`；[C5] 扩展没有编进安装包时，第一次前向会在查找这两个算子时失败，具体报错文本本基线没有实测。
- 配置别名没有正确映射时，可能回退到默认值，并不保证启动时就报错。当前类显式映射专家数以及 mHC 的条数、轮数；应检查解析后的字段与 checkpoint 一致，不能因为默认值恰好是 4 和 20 就证明整个模型配置正确。

### 开销和什么时候别开

- 不能关。mHC 是模型结构的一部分，权重按四条流训练；把 `mhc` 改成假，代码会走单条残差分支，但算出来的已不是这个模型。
- 开销从哪来见上文「代价落在哪里」，GLM 的具体数字推导见[mHC 在 GLM 上多花了什么](#mhc-在-glm-上多花了什么)：主干一次前向 90 次入口混合、1,800 轮 Sinkhorn、90 次写回；普通 TP、SP 关闭时，主混合矩阵每卡 135 MiB，偏置与缩放另计，四条残差每 token 32,768 B。SP 会改变每卡处理的 token 份额，PP 会改变每卡负责的层数，不能把这份逐卡账推广到所有并行配置。[D] 作为容量量级比较，部署页约 20.58 GiB 是指定量化配方的主要语言权重子账，完整范围见[每卡权重账](glm-5-3-flash-two-node.md#每张卡上放了什么)。
- 论文报告 n = 4 时训练时间只多约 6.7%，那是训练侧加上算子融合、重计算等优化后的数；[S2] 推理时 mHC 在昇腾上的耗时本基线没有实测。

### 源码位置

阅读顺序：先看 `models/glm5_next.py` 的 `AscendGlm5NextDecoderLayer`：构造函数按层号选 attention 与 MLP，[C3] 并建 mHC 参数；`hc_pre`、`hc_post` 两个方法只是把张量交给融合算子；`forward` 里依次是第 0 层复制、attention 段、MLP 段、第 44 层求平均，复制用的是同文件开头的 `_expand_mhc_residual_streams`。[C7] 再看 `AscendGlm5NextModel.forward`：查表、逐层循环、最终 RMSNorm；[C8] 输出投影和 `compute_logits` 在同一文件末尾。[C9][C10] 残差分片辅助函数在 attention 输出与残差 token 数相同时原样返回，本页 SP 关闭的逐卡算例采用这条分支。[C14]

融合算子内部看不到 Python，入口权重的 sigmoid、写回权重的 2 × sigmoid、不带增益的 RMSNorm 和 Sinkhorn 迭代，本页按同一提交里的两份参考实现来讲：`ops/mhc.py` 的 `hc_split_sinkhorn_ref`，[C11] 以及适配补丁里 transformers 版的 `Glm5NextTextHyperConnection`；[C18] 写回公式「新流 h = 写回权重 h × 子层输出 + Σ 混合矩阵[g, h] × 旧流 g」取自补丁里的 Decoder 层。[C19] main 在入口混合函数的注释里也写明，融合算子对写回权重用的是 2 × sigmoid。

数值出处：45 层、4096、4 条、20 轮和层型表来自固定 revision 的模型配置；[S1] 90 次、1,800 轮、3.0 MiB、135 MiB、32,768 B 由形状与精度推导；[D] 双随机约束的作用、n = 4 与 20 轮的实验设定来自 mHC 论文，已联网核对摘要与正文。[S2]

实现边界：
- `npu_hc_pre_v2`、`npu_hc_post` 的 AscendC 实现与参考实现是否数值等价，只对过接口和参数顺序，没有跑过。
- 两份参考实现的 Sinkhorn 循环写法略有不同：`ops/mhc.py` 在 softmax 后做 20 轮「先行后列」；补丁版在 softmax 后先按列归一一次，再做 19 轮「先行后列」。softmax 后还加稳定项，归一分母也含稳定项，因此不能把省略的一次按行归一说成严格恒等操作。融合算子内部按哪一种写及两者数值差异，仍须核对实现与数值测试。
