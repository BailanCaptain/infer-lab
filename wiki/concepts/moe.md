## 从一个前馈网络到多个专家

Dense FFN 让所有 token 使用同一组前馈权重。**MoE（混合专家）**在前馈位置配置多个网络，并为每个 token 选择其中一部分执行。每个专家具有自己的权重，内部的门控投影见[前馈网络](mlp-residual-norm.md)。

扩大全部执行的 Dense FFN 会同时增加参数容量和每 token 的计算。稀疏 MoE 希望扩大总参数容量，同时只让部分专家参与当前 token；新增代价包括路由、负载不均，以及跨设备专家的通信。下文分别看选择与容量。[D]

GLM-5.3-Flash 的 45 层文本主干中，前三层使用 Dense FFN，其余 42 层使用 MoE。每个 MoE 层包含 288 个路由专家，每个 token 选择 8 个，另有 1 个共享专家。[S1]

## 路由结果包含编号和组合权重

路由器接收当前表示，为路由专家产生分数。一个 token 的路由结果至少包含两组对应数据：**选中的专家编号**用于决定计算哪些网络，**组合权重**用于将这些网络的输出聚合。

GLM 的固定配置使用 sigmoid 评分、选择校正偏置、选中权重归一化与路由缩放。选择排序所用的值，与最终乘在专家输出上的系数有不同用途。下面按所引原生参考路径展开；融合算子的选择由实现条件决定。[S1][C2][C4][C5][C6]

```wiki-diagram
file: moe-pick
```

令 `zⱼ` 为路由器给专家 `j` 的原始分数，`sⱼ = sigmoid(zⱼ)`。校正偏置 `bⱼ` 参与专家选择：在本模型单组配置下，从 `sⱼ + bⱼ` 中选择 8 个专家，集合记为 `S`。结果组合使用这些专家对应的原始 `sⱼ`，归一化后再乘路由缩放系数 2.5：[S1][C4][C5]

```text
αⱼ = 2.5 × sⱼ / Σ(k ∈ S) sₖ
路由分支输出 = Σ(j ∈ S) αⱼ Eⱼ(x)
```

`Eⱼ(x)` 表示专家 `j` 对当前表示的前馈输出。偏置影响集合 `S`，但不直接加入组合权重的分子。缩放后的权重之和为 2.5，因此不能把最终系数直接说成“和为 1 的选择概率”。上述公式说明路由关系，低精度与融合执行的数值细节仍以对应算子为准。

共享专家不进入这组 top-8 选择。固定 GLM 实现创建独立的共享 MLP，并交由 MoE 执行组件处理；其前馈内部也有 gate/up 分支，这种特征门控与专家选择是两种不同机制。[C2][C3]

## 不同 token 的选择怎样组成一轮批次

每个 token 根据自己在当前层的表示产生路由结果。同一个编号出现在不同上下文时，隐藏表示可以不同；同一序列在不同层也经过不同的路由器与专家权重。

假设两个 token 各选择 8 个专家，选择集合为：[A]

| 输入位置 | 选中的专家编号 |
|---|---|
| A | 0、1、2、3、4、5、6、7 |
| B | 4、5、6、7、8、9、10、11 |

这产生 16 个 token–专家配对，涉及 12 个不同专家。其中专家 4–7 各接收两个 token，其他列出的专家各接收一个。[D] 执行时可以按专家组织输入，再把结果关联回原 token 并聚合；单个 token 的 top-8 并不限制整个批次只能使用 8 个专家。

专家负载取决于所有输入位置的选择。负载不均可能使某些设备等待其他设备完成，具体的放置与均衡策略在[专家并行](expert-parallel.md)和 [EPLB](eplb.md)中展开。旧专题尚在迁移时，其数字和部署条件以各自声明的模型为准。

## 专家数量、激活范围与权重容量

GLM 单个专家的输入/输出宽度为 4096，中间宽度为 2048，包含 gate、up、down 三个无偏置逻辑投影。[S1][C3] 因此一个专家的这三片权重合计：

```text
3 × 4096 × 2048 = 25165824 个标量
```

一个 MoE 层的 288 个路由专家共约 72.48 亿个标量；若假设每个标量占 2 字节，单个专家为 48 MiB，整层路由专家为 13.5 GiB。[A][D] 这些数只计算所列三片权重，不含共享专家、路由器、注意力及其他模型部件，也不是量化部署的实测占用。

存储总量与一个 token 的激活范围需要分别统计：同一层保留所有专家参数，当前 token 只使用选中路径；其他 token 可以使用其他专家。改变专家数或 top-k 会改变模型计算，不能把删专家视为不影响行为的部署优化。

## MoE 结构与专家并行部署如何衔接

MoE 描述选择哪些专家计算；专家并行（EP）描述把这些专家放到哪些设备上。如果所选专家在另一设备，系统需要传递当前隐藏表示和路由关联信息，执行后再返回或合并结果。是否跨设备、跨服务器，取决于实际部署，而不是 MoE 名称本身。

本站的双机依据见[官方部署来源基线](../sources/glm-5-3-flash-baseline.md)。本页不将单 token 的计算分支画成固定的设备分配，也不从专家参数量单独推断所需设备数量。内存容量还要覆盖其他权重、请求状态和运行缓冲。

GLM 模型与路由细节依据固定 Ascend 专用快照；上游 v0.23.0 的引用说明共享与路由输出的合并接口。专用镜像内最终安装组合仍待核验，本页没有设备或性能实测。
