## 模型看到的不是你打的那句话

全库反复出现一句话：「问题 37 个 token，回答 200 个 token」（见[贯穿全站的例子](one-request.md)）。为什么不直接说「一句话的问题」「一段话的回答」？因为对模型来说，「一句话」这个东西不存在。你打的字它一个都没见过——它见到的是一串编号。

从你按下回车，到模型开始计算，中间有一步固定的转换：整段文字被切成一串 token，每个 token 换成一个编号，模型拿到的就是这串编号。「37 个」数的是切完之后的块数，不是字数，也不是词数。全库用 token 计数，是因为机器里真正被计数、被排队、被分配显存的，就是这个单位。

## 一段话先被切成一串字块，切法出厂就定死了

token 是模型处理文字的最小单位，可以理解成一个「字块」：可能是一个字，可能是半个词，可能是一个完整的词，英文里也可能是一段常见的字母组合。一段话进来，先被切成一串这样的字块。

负责切的东西叫**分词器**（tokenizer）：一套查表规则，规定了哪些组合算一块。它是模型出厂时定死的，跟着模型一起发布——同一个模型，同一段话，今天切和明年切结果完全一样；但换一个模型，切法就可能不同，同一段话切出来的 token 数也不同。所以说「多少个 token」时，其实隐含了「按哪个模型的切法数」。

## 按字切太碎，按词切表太大，字块是折中

为什么不干脆一个字一个 token，或者一个词一个 token？两头各有各的难处：

- **按字切**：切出来的串太长。同一段话的 token 数会翻好几倍，而模型的计算量和显存都跟着 token 数走，串越长越贵。
- **按词切**：词根本列不完。新词、错别字、人名、代码、别的语言……要么表大到装不下，要么一遇到表里没有的词就卡住。

字块是两头之间的折中：常见的组合合并成一块，剩下的拆碎了也总能用更小的块拼出来。于是常用词往往独占一块，生僻的组合被拆成几块，但**任何**输入都切得动，不会遇到「不认识」的情况。至于哪些组合被合并，是训练分词器时从大量文本里统计出来的，这里不展开。

## 每个字块换成一张大表里的一个编号

切完之后还有最后一步：查表。分词器带着一张很大的表，上面登记了它认识的所有字块，每块占一行，行号就是这块的编号，这张表叫**词表**，编号叫 **token id**。切出来的每个字块在表里查到自己那行，整段文字就变成了一串编号。

模型拿到的就是这串编号——不是字，不是词，甚至不是字块本身。反过来也一样：模型算完之后给出的也是编号，最后一步再拿着编号回词表里查出字块，拼回文字给你看。文字进去、文字出来，中间全程是编号在流动。

## 回到那个例子：37 个 token 进去，200 个 token 一个一个出来

[贯穿全站的例子](one-request.md)里，问题被切成 37 个 token。中文里一个 token 常常不到一个词——一个词可能被切成两三块——所以 37 个 token 对应的原文往往比 37 个词短，这也是「token 数」和「字数」对不上的原因。

回答 200 个 token 则是另一回事：模型每算一轮只吐出**一个** token 的编号，吐了 200 次才凑出整段回答。所以「回答 200 个 token」同时也是「模型把自己从头到尾跑了 200 遍」——这件事怎么展开、第一步为什么和后面 199 步不一样，都在[那一页](one-request.md)，这里只要记住：token 既是计数文字的单位，也是模型干活的节拍，一步一个。

## 两个常见误会

- **「token 就是字」**——不是。一个 token 可能是一个字、半个词、一个词。拿字数换算 token 数没有固定汇率，同一段话在不同模型下切出来的数量也不同。
- **「限制回答长度，限的是字数」**——不是。各种「最大长度」限的都是 token 数：模型一步吐一个 token，限的是它最多吐多少步。同样是「限 500」，答中文和答英文时实际能写多少字并不一样。
